- 动画蓝图是什么？
- 动画蓝图 Event Graph 和 Anim Graph 的区别
- State Machine 是什么？
- Blend Space 是什么？
- Animation Montage 是什么？
- Slot 是什么？

- 蒙太奇和动画蓝图如何配合？
- 攻击动画如何驱动伤害判定？

# 五、动画系统问题

## 1. 动画蓝图是什么？

动画蓝图，全称 **Animation Blueprint**，是 UE 中控制骨骼网格动画播放逻辑的蓝图。

它通常绑定在角色的 `Skeletal Mesh` 上，用来决定当前角色应该播放什么动画。

比如角色可能有这些动画：

```text
Idle       站立
Walk       行走
Run        奔跑
JumpStart  起跳
JumpLoop   空中循环
JumpEnd    落地
Attack     攻击
HitReact   受击
Death      死亡
```

动画蓝图的作用就是根据角色状态选择合适的动画。

例如：

```text
速度 = 0        → 播放 Idle
速度 > 0        → 播放 Walk / Run
是否在空中 = true → 播放 Jump
正在攻击       → 播放 Attack Montage
死亡           → 播放 Death
```

------

## 2. 动画蓝图一般由哪些部分组成？

动画蓝图主要包含几个重要部分：

```text
Animation Blueprint
 ├── Event Graph
 ├── Anim Graph
 ├── State Machine
 ├── Blend Space
 ├── Slot
 ├── Anim Notify
 └── Variables
```

------

# 3. Event Graph 和 Anim Graph 的区别

## 3.1 Event Graph 是什么？

`Event Graph` 主要负责**更新动画所需的变量**。

常见变量：

```text
Speed           当前速度
Direction       移动方向
bIsInAir        是否在空中
bIsAccelerating 是否正在加速
bIsDead         是否死亡
bIsAttacking    是否攻击
```

例如：

```text
Event Blueprint Update Animation
    → Try Get Pawn Owner
    → Get Velocity
    → Vector Length XY
    → 设置 Speed

    → Get Character Movement
    → Is Falling
    → 设置 bIsInAir
```

也就是说：

> Event Graph 负责从角色身上读取状态，然后保存成动画变量。

------

## 3.2 Anim Graph 是什么？

`Anim Graph` 负责**根据变量输出最终姿势**。

它会使用：

- State Machine
- Blend Space
- Montage Slot
- Layered Blend Per Bone
- Aim Offset
- IK 节点

最后输出到：

```text
Output Pose
```

例如：

```text
Speed = 0 → Idle
Speed > 0 → Walk / Run BlendSpace
bIsInAir = true → Jump
```

------

## 3.3 两者区别总结

| 对比     | Event Graph                      | Anim Graph                      |
| -------- | -------------------------------- | ------------------------------- |
| 作用     | 更新变量                         | 生成最终动画姿势                |
| 处理内容 | 逻辑数据                         | 动画姿势                        |
| 常见节点 | Try Get Pawn Owner、Get Velocity | State Machine、BlendSpace、Slot |
| 类似理解 | 收集状态                         | 根据状态播放动画                |

------

## 3.4 面试推荐回答

> 动画蓝图中的 Event Graph 主要负责更新动画变量，比如速度、是否在空中、是否攻击等；Anim Graph 负责根据这些变量生成最终动画姿势，比如通过状态机、Blend Space、Montage Slot 输出最终 Pose。简单说，Event Graph 负责数据，Anim Graph 负责动画结果。

------

# 4. State Machine 是什么？

## 4.1 基本概念

`State Machine` 是动画状态机，用来管理动画状态之间的切换。

常见状态：

```text
Idle/Run
JumpStart
JumpLoop
JumpEnd
Death
```

状态之间通过条件切换。

例如：

```text
Idle/Run → JumpStart
条件：bIsInAir == true

JumpLoop → JumpEnd
条件：bIsInAir == false

Any State → Death
条件：bIsDead == true
```

------

## 4.2 为什么需要状态机？

如果没有状态机，你需要自己写很多判断逻辑来决定播放哪个动画。

状态机可以把动画切换关系可视化：

```text
Locomotion → Jump → Land → Locomotion
```

适合管理角色的基础运动动画。

------

## 4.3 常见状态机结构

一个第三人称角色常见状态机：

```text
Locomotion
    ↓ bIsInAir
JumpStart
    ↓ 动画播放结束
JumpLoop
    ↓ !bIsInAir
JumpEnd
    ↓ 动画播放结束
Locomotion
```

其中 `Locomotion` 里面通常是一个 Blend Space。

------

## 4.4 状态切换条件

切换条件一般来自 Event Graph 更新的变量，例如：

```text
Speed > 0
bIsInAir == true
bIsDead == true
bIsAttacking == false
```

------

## 4.5 面试推荐回答

> State Machine 是动画状态机，用来管理不同动画状态之间的切换，比如站立、奔跑、跳跃、落地、死亡等。它通过变量作为切换条件，比如速度、是否在空中、是否死亡。状态机适合控制角色基础移动动画，让动画逻辑更清晰。

------

# 5. Blend Space 是什么？

## 5.1 基本概念

`Blend Space` 是动画混合空间，用来根据一个或两个参数在多段动画之间平滑混合。

最常见的是移动动画混合。

例如 1D Blend Space：

```text
Speed = 0     → Idle
Speed = 150   → Walk
Speed = 600   → Run
```

角色速度从 0 变化到 600 时，动画会从 Idle 平滑过渡到 Walk，再到 Run。

------

## 5.2 1D Blend Space

1D Blend Space 只有一个输入参数。

常见参数：

```text
Speed
```

例如：

```text
0     Idle
200   Walk
600   Run
```

适合：

- 站立 / 行走 / 奔跑
- 慢走 / 快跑
- 简单移动状态

------

## 5.3 2D Blend Space

2D Blend Space 有两个输入参数。

常见参数：

```text
Speed
Direction
```

例如：

```text
前进
后退
左移
右移
斜向移动
```

适合第三人称、俯视角、锁定视角等需要方向移动的角色。

------

## 5.4 Blend Space 和 State Machine 的关系

通常状态机中的一个状态会使用 Blend Space。

例如：

```text
State Machine
 └── Locomotion State
      └── BlendSpace：Idle / Walk / Run
```

也就是说：

- State Machine 管理大状态
- Blend Space 管理某个状态内部的动画混合

------

## 5.5 面试推荐回答

> Blend Space 是动画混合空间，用来根据参数在多个动画之间平滑混合。比如根据 Speed 在 Idle、Walk、Run 之间混合。1D Blend Space 通常用一个速度参数，2D Blend Space 可以用速度和方向，适合实现前后左右移动动画。它经常放在状态机的 Locomotion 状态中。

------

# 6. Animation Montage 是什么？

## 6.1 基本概念

`Animation Montage`，动画蒙太奇，是 UE 中用来播放**一次性、可控制、可打断、可分段**动画的资源。

常用于：

```text
攻击
翻滚
释放技能
换弹
受击
死亡
处决
交互动作
```

比如近战攻击，一般不会放在基础移动状态机里，而是用 Montage 播放。

------

## 6.2 Montage 适合什么场景？

适合：

- 动作有明确开始和结束
- 需要被代码或蓝图主动触发
- 需要动画通知
- 需要连招
- 需要分段跳转
- 需要打断
- 需要和 GameplayAbility 结合

例如：

```text
玩家按鼠标左键
    → 播放 Attack Montage
    → Notify Begin 开启攻击检测
    → Notify End 关闭攻击检测
    → Montage End 恢复状态
```

------

## 6.3 Montage 和普通动画序列的区别

| 对比             | Animation Sequence        | Animation Montage  |
| ---------------- | ------------------------- | ------------------ |
| 作用             | 单段基础动画资源          | 可控制的一次性动画 |
| 是否适合代码触发 | 可以，但不如 Montage 灵活 | 非常适合           |
| 是否支持 Section | 不支持                    | 支持               |
| 是否支持 Notify  | 支持                      | 支持               |
| 是否支持 Slot    | 一般不用                  | 依赖 Slot          |
| 常见用途         | Idle、Walk、Run           | 攻击、技能、换弹   |

------

## 6.4 Montage 的 Section 是什么？

`Section` 是 Montage 中的动画片段分区。

例如一个连招 Montage 可以分成：

```text
Attack_1
Attack_2
Attack_3
```

播放时可以根据输入跳转：

```text
Attack_1 → Attack_2 → Attack_3
```

常见用途：

- 连招
- 技能阶段
- 换弹分段
- 起手 / 循环 / 收尾

------

## 6.5 Montage 的优点

Montage 可以：

- 蓝图或 C++ 主动播放
- 控制播放速率
- 监听播放结束
- 使用 Anim Notify
- 使用 Section 做连招
- 使用 Slot 混合到动画蓝图
- 和 GAS AbilityTask 配合

------

## 6.6 面试推荐回答

> Animation Montage 是一种适合播放攻击、技能、翻滚、换弹、受击等一次性动作的动画资源。它可以由蓝图或 C++ 主动触发，支持 Section、Slot、Anim Notify、播放结束回调和打断。基础移动动画通常放在状态机里，而攻击、技能这类动作更适合用 Montage。

------

# 7. Slot 是什么？

## 7.1 基本概念

`Slot` 是 Montage 和动画蓝图之间的连接点。

Montage 并不是凭空覆盖角色动画，它需要在 Anim Graph 中通过 `Slot` 节点接入最终姿势。

例如：

```text
State Machine
    ↓
Slot "DefaultSlot"
    ↓
Output Pose
```

这样播放使用 `DefaultSlot` 的 Montage 时，Montage 才能影响最终动画输出。

------

## 7.2 如果没有 Slot 会怎样？

如果你播放 Montage，但动画蓝图中没有对应 Slot，常见结果是：

```text
Montage 播放调用成功
但角色看起来没有播放动画
```

因为 Montage 没有混入最终 Pose。

------

## 7.3 Slot 的作用

Slot 允许你控制 Montage 作用的位置和层级。

例如：

```text
DefaultSlot：全身攻击
UpperBodySlot：只影响上半身
FaceSlot：只影响面部
```

配合 `Layered Blend Per Bone` 可以实现：

```text
下半身继续跑步
上半身播放射击动画
```

------

## 7.4 示例：上半身攻击

Anim Graph 里可以这样组织：

```text
Locomotion State Machine
        ↓
Layered Blend Per Bone
    ├── Base Pose：Locomotion
    └── Blend Pose：UpperBodySlot
        ↓
Output Pose
```

这样角色可以：

```text
腿部继续跑步
上半身播放攻击 / 射击 / 换弹
```

------

## 7.5 面试推荐回答

> Slot 是 Montage 接入动画蓝图的插槽。Montage 需要通过 Anim Graph 中对应的 Slot 节点混入最终 Pose，否则可能调用了播放但角色没有动作。Slot 还可以配合 Layered Blend Per Bone 实现局部动画，比如下半身跑步，上半身射击。

------

# 8. Anim Notify 是什么？

## 8.1 基本概念

`Anim Notify` 是动画时间轴上的通知点。

当动画播放到某一帧时，会触发对应事件。

常见用途：

```text
攻击判定开始
攻击判定结束
播放脚步声
播放武器挥砍音效
生成特效
发射子弹
产生伤害
打开连招输入窗口
发送 Gameplay Event
```

------

## 8.2 普通 Notify

普通 Notify 是一个时间点。

例如：

```text
攻击动画第 0.35 秒
    → 触发 HitCheck
```

适合：

- 播放音效
- 生成特效
- 发射子弹
- 单次检测伤害
- 脚步声

------

## 8.3 Notify State

`Anim Notify State` 有持续时间，包含：

```text
Notify Begin
Notify Tick
Notify End
```

适合表示一个时间窗口。

例如近战攻击判定窗口：

```text
Notify Begin：开启武器碰撞
Notify Tick：持续检测命中
Notify End：关闭武器碰撞
```

------

## 8.4 攻击中如何使用 Notify？

近战攻击常见做法：

```text
播放 Attack Montage
    ↓
AnimNotifyState_AttackWindow Begin
    → 清空 HitActors
    → 开启武器碰撞 / 开始 Trace
    ↓
Notify Tick
    → 检测命中敌人
    → 如果敌人不在 HitActors 中，造成伤害并加入集合
    ↓
Notify End
    → 关闭武器碰撞 / 停止 Trace
```

这样攻击伤害和动画动作能够精确对齐。

------

## 8.5 面试推荐回答

> Anim Notify 是动画时间轴上的事件通知，可以在动画播放到指定帧时触发逻辑，比如播放脚步声、生成特效、开启攻击判定、发射子弹等。Notify State 有开始、持续和结束，适合实现攻击判定窗口，例如 Begin 开启检测，End 关闭检测。

------

# 9. Montage 和 Anim Notify 的关系

Montage 本身负责播放动作，Notify 负责在动作的关键时间点触发逻辑。

例如攻击技能：

```text
Gameplay Ability 激活
    → 播放 Attack Montage
        → Notify Begin：开启伤害检测
        → Notify：播放挥砍音效
        → Notify End：关闭伤害检测
    → Montage End：结束 Ability
```

所以可以理解为：

```text
Montage 控制动作流程
Notify 控制动画时间点上的游戏逻辑
```

------

# 10. 为什么攻击动画通常不用 Tick 判断伤害？

因为 Tick 是每帧执行，与动画关键帧没有天然绑定。

如果用 Tick 判断：

```text
攻击开始后每帧检测
```

可能会出现：

- 攻击还没挥到敌人就造成伤害
- 攻击结束了还在检测
- 多次重复命中
- 动画和判定不同步

更好的方式是：

```text
Anim Notify 控制攻击判定窗口
```

例如：

```text
第 0.2 秒：武器开始挥出 → 开启检测
第 0.5 秒：攻击结束 → 关闭检测
```

这样判定更准确。

------

# 11. 动画蓝图中可以调用 Montage Notify 吗？

可以。

如果 Montage 是通过动画蓝图对应的 Skeletal Mesh 播放的，并且 Montage 正常经过 Anim Instance，那么 Notify 可以在动画蓝图中触发对应事件。

但是需要注意：

Montage Notify 是否能触发，通常取决于：

```text
Montage 是否真的播放
Montage 是否接入了正确 Slot
Skeletal Mesh 是否使用对应 Anim BP
Notify 名字是否正确
动画是否播放到该时间点
Montage 是否被提前打断
```

------

# 12. 如果不通过 Slot 连接 Montage 和动画蓝图，还能使用 Montage Notify 吗？

这个问题你之前也问过，面试中也有可能被追问。

更严谨地说：

> Montage 的播放、可见动画输出、Notify 触发都和 AnimInstance 的 Montage 播放流程有关。通常要让 Montage 正常作用到角色动画，需要在 Anim Graph 中接入对应 Slot。没有 Slot 时，很多情况下会出现 Montage 调用了但没有真正影响最终姿势，Notify 也可能不按预期触发或难以维护。

面试时建议这样回答：

> 实际项目中应该通过 Slot 把 Montage 接入动画蓝图。Slot 是 Montage 进入最终动画 Pose 的标准方式。如果没有对应 Slot，可能出现 Montage 播放节点执行了但角色不动，Notify 也不可靠。因此攻击、技能、换弹这类 Montage 通常都要在 Anim Graph 中放对应 Slot。

------

# 13. Root Motion 是什么？

## 13.1 基本概念

`Root Motion` 是指动画本身驱动角色位移，而不是代码或 MovementComponent 驱动。

例如一个翻滚动画，角色根骨骼向前移动。

如果启用 Root Motion：

```text
角色位移来自动画根骨骼
```

如果不启用：

```text
动画看起来在翻滚
但胶囊体位置可能没有跟着移动
```

------

## 13.2 Root Motion 适合什么？

适合：

- 翻滚
- 冲刺攻击
- 处决动作
- 击退
- 爬墙
- 攀爬
- 特殊技能位移

------

## 13.3 Root Motion 的优缺点

优点：

- 动画表现准确
- 位移和动作一致
- 适合强表现动作

缺点：

- 角色控制会更复杂
- 网络同步要更谨慎
- 对动画资源要求更高
- 不适合所有移动逻辑

------

## 13.4 面试推荐回答

> Root Motion 是让动画根骨骼驱动角色位移，而不是完全由代码移动。它适合翻滚、冲刺攻击、处决这类需要动画和位移高度匹配的动作。优点是表现准确，缺点是控制和网络同步更复杂。

------

# 14. IK 是什么？

## 14.1 基本概念

`IK` 是 Inverse Kinematics，反向运动学。

普通动画通常是：

```text
父骨骼 → 子骨骼
```

比如：

```text
肩膀 → 手臂 → 手
```

IK 则是反过来：

```text
先指定手或脚的位置
再反推出中间骨骼应该怎么弯曲
```

------

## 14.2 UE 中 IK 常见用途

```text
脚贴地
手握武器
手扶墙
瞄准
攀爬
角色看向目标
双手持枪修正
```

例如脚 IK：

```text
地面不平
    → 射线检测脚下地面高度
    → 调整脚的位置
    → 让脚贴合地面
```

------

## 14.3 面试推荐回答

> IK 是反向运动学，用目标位置反推出骨骼姿势。UE 中常用于脚部贴地、双手持枪、瞄准、攀爬等。比如脚 IK 可以通过射线检测地面高度，再调整脚骨骼位置，让角色在不平地面上脚不悬空。

------

# 15. Aim Offset 是什么？

## 15.1 基本概念

`Aim Offset` 是一种根据瞄准方向混合上半身姿势的动画资源。

常用参数：

```text
Yaw   左右角度
Pitch 上下角度
```

例如：

```text
Pitch = 45°  → 向上瞄准
Pitch = -30° → 向下瞄准
Yaw = 60°    → 向右瞄准
```

------

## 15.2 适合场景

适合：

- 射击游戏角色瞄准
- 第三人称持枪
- 炮台朝向
- 角色上半身看向目标

------

## 15.3 面试推荐回答

> Aim Offset 用来根据角色的瞄准方向混合不同的瞄准姿势，通常使用 Pitch 和 Yaw 作为输入。它常用于射击游戏，让角色上半身能向不同方向瞄准，同时下半身仍然可以移动。

------

# 16. 动画系统和 Gameplay 的关系

动画不只是表现，也经常驱动游戏逻辑。

例如近战攻击：

```text
输入攻击
    → 播放 Montage
    → Notify 控制攻击判定
    → Trace / Collision 命中敌人
    → Apply Damage / Apply Gameplay Effect
    → Montage 结束后恢复状态
```

但是要注意：

> 不建议把核心游戏规则完全写死在动画资源里。动画 Notify 适合触发时间点，真正的伤害计算、权限判断、技能消耗等最好在角色、技能系统或组件中处理。

面试回答可以这样说：

> 动画可以通过 Notify 在关键帧触发玩法逻辑，比如攻击判定、发射子弹、播放特效。但核心规则不应该完全依赖动画资源，伤害计算、技能状态、冷却消耗等最好由角色逻辑或 GAS 处理，动画负责提供时机。

# 17. 实战问题：如何实现一个近战攻击动画？

这是面试非常高频的问题。

可以按这个流程回答：

```text
1. 玩家输入攻击
2. 判断是否能攻击
3. 播放攻击 Montage
4. Montage 中添加 Notify State 作为攻击判定窗口
5. Notify Begin 清空已命中目标并开启检测
6. Notify Tick 或武器碰撞检测敌人
7. 命中后判断是否已经命中过
8. 没命中过则造成伤害，并加入 HitActors
9. Notify End 关闭检测
10. Montage 结束后恢复攻击状态
```

C++ / 蓝图逻辑可以是：

```text
Input Attack
    → Play Anim Montage
    → Set bIsAttacking = true
```

Notify Begin：

```text
HitActors.Empty()
bCanDealDamage = true
```

Notify Tick / Weapon Overlap：

```text
如果 HitActor 是敌人
如果 HitActors 不包含 HitActor
    → ApplyDamage
    → HitActors.Add(HitActor)
```

Notify End：

```text
bCanDealDamage = false
```

Montage End：

```text
bIsAttacking = false
```

面试推荐回答：

> 我会用 Montage 播放攻击动画，在 Montage 中用 Anim Notify State 控制攻击判定窗口。Notify Begin 时开启武器 Trace 或碰撞，并清空本次攻击已命中目标；检测到敌人后用 TSet 记录，防止一次攻击重复命中；Notify End 时关闭检测；Montage 结束后恢复攻击状态。如果项目使用 GAS，可以在 Notify 中发送 Gameplay Event，由 Ability 处理伤害逻辑。

# 18. 实战问题：Montage 不播放，怎么排查？

面试可能会问你如何排查问题。

可以从这些方面回答：

1. 角色 Skeletal Mesh 是否使用正确 Anim Blueprint
2. Anim Graph 中是否接入了对应 Slot
3. Montage 使用的 Slot 是否和 Anim BP 中 Slot 名一致
4. 是否调用了正确的播放函数
5. Montage 资源是否为空
6. 当前是否有其他 Montage 打断了它
7. 骨骼是否匹配
8. 播放速率是否为 0
9. 是否在服务器 / 客户端播放位置不对
10. 角色是否处于死亡、禁用动画或 Mesh Hidden 状态

面试推荐回答：

> Montage 不播放我会先检查角色是否使用了正确的 Anim BP，然后检查 Anim Graph 中是否有对应 Slot，Montage 的 Slot 名是否匹配。再检查 Montage 资源是否为空、播放函数是否被调用、是否被其他 Montage 打断、骨骼是否匹配。如果是多人游戏，还要看是在服务器播放还是客户端播放，以及是否需要同步给其他客户端。

# 19. 实战问题：Anim Notify 不触发，怎么排查？

常见排查点：

1. 动画是否真的播放到 Notify 所在时间点
2. Montage 是否被提前打断
3. Notify 名字是否写对
4. Notify 是否放在正确动画资源上
5. 是否使用了正确的 Anim BP
6. Montage Slot 是否正确接入
7. 动画播放速率是否异常
8. Notify 触发逻辑是否在服务器或客户端期望端执行
9. Skeleton 是否匹配
10. Notify Filter / Trigger 设置是否有问题

面试推荐回答：

> Notify 不触发时，我会先确认动画是否真的播放到了 Notify 的时间点，Montage 有没有提前被打断，然后检查 Notify 是否放在正确动画上、名字是否对应、Anim BP 是否正确、Slot 是否接入。如果是多人项目，还要确认 Notify 是在服务器还是客户端触发，是否需要通过 RPC 或 Gameplay Event 处理。

# 20. 第五部分综合面试模板

如果面试官问：“你对 UE 动画系统了解多少？”

可以这样回答：

> UE 的动画系统主要通过 Animation Blueprint 控制 Skeletal Mesh 的动画播放。动画蓝图中 Event Graph 负责更新动画变量，比如速度、方向、是否在空中；Anim Graph 负责根据这些变量输出最终 Pose，常用 State Machine 管理站立、奔跑、跳跃等状态，Blend Space 根据速度或方向混合移动动画。

> 对于攻击、翻滚、技能、换弹这类一次性动作，通常使用 Animation Montage。Montage 可以通过 Slot 接入动画蓝图，支持 Section、Anim Notify、打断和播放结束回调。Anim Notify 可以在动画关键帧触发逻辑，比如脚步声、特效、攻击判定；Notify State 可以表示一个时间窗口，比如近战攻击检测窗口。
>
> 实现近战攻击时，我会播放攻击 Montage，在 Notify State Begin 开启武器检测并清空已命中目标，在检测期间用 TSet 防止重复命中，Notify End 关闭检测，Montage 结束后恢复状态。如果项目用 GAS，也可以通过 Notify 发送 Gameplay Event，让 Ability 处理伤害。

# 21. 简短版背诵答案

面试时可以背这个版本：

> 动画蓝图用于控制角色 Skeletal Mesh 的动画播放。Event Graph 负责更新速度、方向、是否在空中等变量，Anim Graph 根据变量通过状态机、Blend Space、Slot 等节点输出最终 Pose。
>
> State Machine 用来管理站立、奔跑、跳跃等动画状态；Blend Space 用来根据 Speed 或 Direction 在多个动画之间平滑混合。
