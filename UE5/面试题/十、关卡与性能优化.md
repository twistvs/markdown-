下面回答 **十、关卡和性能优化问题**。这一部分在 UE5 面试中很常见，因为游戏开发不仅要“功能能跑”，还要考虑 **帧率、内存、Draw Call、Tick、碰撞、资源加载、关卡组织** 等问题。

------

# 十、关卡和性能优化问题

## 1. UE5 中有哪些常见性能优化手段？

可以从几个方向回答：

```text
1. Tick 优化
2. 蓝图逻辑优化
3. Actor 数量优化
4. 碰撞优化
5. 渲染优化
6. 动画优化
7. UI 优化
8. 资源加载优化
9. 关卡流送 / World Partition
10. 使用工具分析性能
```

面试中不要只说“减少面数”，更好的回答是：

> UE 性能优化要先分析瓶颈，再针对性优化。如果瓶颈在 CPU，就看 Tick、蓝图、AI、碰撞、动画逻辑；如果瓶颈在 GPU，就看材质、光照、阴影、后处理、分辨率、透明物体、Draw Call 等；如果瓶颈在内存和加载，就看资源引用、异步加载、关卡流送和贴图大小。

------

# 2. Tick 为什么要慎用？

`Tick` 是每帧执行的逻辑。

如果一个 Actor 开启 Tick：

```cpp
void AMyActor::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
}
```

在 60 FPS 下，它每秒执行 60 次。

如果有 1000 个 Actor 都在 Tick：

```text
1000 × 60 = 每秒 60000 次 Tick
```

如果 Tick 里还有：

```text
Cast
Get All Actors of Class
Line Trace
循环遍历
创建对象
复杂蓝图逻辑
UI 更新
```

性能就会明显变差。

------

## 2.1 Tick 优化方式

常见方式：

### 关闭不必要 Tick

```cpp
PrimaryActorTick.bCanEverTick = false;
```

蓝图中也可以关闭：

```text
Start with Tick Enabled = false
```

------

### 调整 Tick 间隔

```cpp
PrimaryActorTick.TickInterval = 0.2f;
```

表示每 0.2 秒 Tick 一次，而不是每帧 Tick。

适合：

```text
低频检测
AI 状态刷新
距离检测
环境扫描
```

------

### 用 Timer 替代 Tick

例如每秒检测一次敌人：

```cpp
GetWorld()->GetTimerManager().SetTimer(
    CheckTimerHandle,
    this,
    &AMyActor::CheckEnemy,
    1.0f,
    true
);
```

------

### 用事件驱动替代 Tick

比如血条更新：

不推荐：

```text
UI 每帧读取 Health
```

推荐：

```text
Health 改变
    → 广播 OnHealthChanged
    → UI 更新
```

------

## 2.2 面试推荐回答

> Tick 每帧执行，少量使用没问题，但大量 Actor 都 Tick 或 Tick 中做复杂逻辑会影响 CPU 性能。优化时可以关闭不必要 Tick，设置 TickInterval，用 Timer 替代低频轮询，用事件驱动替代每帧查询，比如血条更新应该在血量变化时通知 UI，而不是每帧读血量。

------

# 3. 蓝图性能如何优化？

蓝图虽然方便，但复杂蓝图逻辑也可能带来性能问题。

常见优化点：

```text
避免 Tick 中复杂逻辑
避免频繁 Cast
避免频繁 Get All Actors of Class
避免大量循环
缓存引用
复杂算法放到 C++
事件驱动替代轮询
```

------

## 3.1 不要频繁 Get All Actors of Class

这个节点会遍历世界中的 Actor。

不推荐：

```text
Event Tick
    → Get All Actors of Class BP_Enemy
```

推荐：

```text
敌人生成时注册到 EnemyManager
敌人死亡时从 EnemyManager 移除
需要时直接读 EnemyManager 的数组
```

------

## 3.2 缓存引用

不推荐每次都：

```text
Get Player Character
Cast To BP_Player
Get HealthComponent
```

推荐 BeginPlay 时获取一次：

```text
BeginPlay
    → Get Player Character
    → Cast To BP_Player
    → 保存 PlayerRef
```

------

## 3.3 复杂逻辑放 C++

如果有大量计算，比如：

```text
复杂寻路
大量排序
密集数学计算
批量数据处理
复杂战斗计算
```

可以考虑放到 C++。

------

## 3.4 面试推荐回答

> 蓝图优化主要是减少 Tick 中的复杂逻辑，避免频繁 Cast、Get All Actors of Class 和大循环。常用引用可以缓存，状态变化用事件驱动，性能敏感或复杂算法可以放到 C++。蓝图适合表现层和快速迭代，底层复杂逻辑更适合 C++。

------

# 4. Actor 数量如何优化？

场景中 Actor 太多会增加：

```text
Tick 开销
组件注册开销
碰撞检测开销
渲染提交开销
内存占用
网络复制开销
```

优化方式：

## 4.1 合并静态物体

大量静态小物体可以考虑：

```text
合并 Mesh
使用 Instanced Static Mesh
使用 Hierarchical Instanced Static Mesh
使用 HLOD
```

例如场景里有很多相同的草、石头、树，可以用实例化渲染。

------

## 4.2 对象池

对于高频生成销毁的对象，比如：

```text
子弹
投射物
伤害飘字
命中特效
掉落物
```

可以使用对象池，避免频繁 SpawnActor 和 Destroy。

------

## 4.3 远处对象降级

远处或看不见的 Actor 可以：

```text
关闭 Tick
关闭碰撞
降低更新频率
隐藏或卸载
使用 LOD / HLOD
```

------

## 4.4 面试推荐回答

> Actor 数量太多会增加 Tick、碰撞、渲染和内存开销。优化时可以合并静态物体，使用 Instanced Static Mesh 或 HLOD；对子弹、特效、伤害数字等高频对象使用对象池；远处对象可以关闭 Tick、降低更新频率、关闭碰撞或使用 LOD。

------

# 5. 碰撞如何优化？

碰撞检测也是 CPU 开销来源之一。

常见优化方式：

```text
不需要碰撞的物体关闭碰撞
触发器使用 Query Only
物理物体才用 Physics
合理设置 Collision Channel
避免复杂碰撞
减少高频 Trace
Trace 使用合适长度和频率
```

------

## 5.1 不需要碰撞就关闭

很多装饰物只用于显示：

```text
小石头
草
远景模型
背景装饰
```

如果不需要交互，可以设为：

```text
No Collision
```

------

## 5.2 Query Only 和 Physics 分开

触发器、攻击检测、交互检测通常只需要：

```text
Query Only
```

不需要物理模拟。

只有真正需要刚体模拟的物体才使用：

```text
Query and Physics
```

------

## 5.3 简单碰撞优先

复杂模型使用复杂碰撞会比较贵。

可以使用：

```text
简单盒体
球体
胶囊体
简化碰撞 Hull
```

不要给大量小物体使用复杂三角面碰撞。

------

## 5.4 Trace 优化

比如 AI 视线检测，不要所有 AI 每帧都 LineTrace。

可以：

```text
降低检测频率
分批检测
距离太远不检测
使用 AI Perception
使用碰撞通道过滤
```

------

## 5.5 面试推荐回答

> 碰撞优化主要是关闭不必要碰撞，触发器使用 Query Only，避免大量复杂碰撞和高频 Trace。对不同对象设置合理的 Collision Channel，只检测真正需要的对象。AI 视线或攻击检测不要所有对象每帧 Trace，可以降低频率、分批检测或用事件驱动。

------

# 6. 渲染性能如何优化？

渲染优化主要看 GPU。

常见瓶颈包括：

```text
Draw Call 多
三角形数量高
材质复杂
透明物体多
阴影开销大
后处理重
动态光源多
过高分辨率贴图
```

------

## 6.1 Draw Call 是什么？

Draw Call 可以理解为 CPU 向 GPU 提交一次绘制命令。

如果场景中很多独立物体、材质很多，就可能产生大量 Draw Call。

优化方式：

```text
合并 Mesh
减少材质数量
使用 Instanced Static Mesh
使用 HLOD
使用 Nanite 合理处理高模
```

面试回答：

> Draw Call 是 CPU 向 GPU 提交绘制命令的次数。大量小物体和大量材质会增加 Draw Call。可以通过合并 Mesh、减少材质槽、实例化渲染和 HLOD 来优化。

------

## 6.2 材质优化

复杂材质会增加 GPU 开销。

优化方式：

```text
减少复杂节点
减少纹理采样
避免过多透明材质
减少昂贵函数
合理使用材质实例
远处物体用简化材质
```

透明材质尤其要注意，因为透明物体通常有 Overdraw 问题。

------

## 6.3 阴影优化

动态阴影很贵。

优化方式：

```text
减少动态光源数量
调整阴影距离
降低阴影质量
远处关闭阴影
小物体不投射阴影
使用烘焙或静态光照，视项目而定
```

UE5 中如果使用 Virtual Shadow Maps，也要注意阴影开销。

------

## 6.4 后处理优化

后处理包括：

```text
Bloom
Motion Blur
Depth of Field
Ambient Occlusion
Screen Space Reflection
Color Grading
```

过重会影响 GPU。

移动端尤其需要谨慎。

------

## 6.5 面试推荐回答

> 渲染优化可以从 Draw Call、材质、阴影、后处理和 LOD 入手。大量小物体可以用实例化或 HLOD；材质要减少复杂节点和透明 Overdraw；动态光源和阴影要控制数量和范围；远处物体使用 LOD，后处理根据目标平台适当降低。

------

# 7. LOD、HLOD、Nanite 分别是什么？

## 7.1 LOD

LOD 是 Level of Detail，细节层级。

同一个模型根据距离使用不同精度：

```text
近处：高模
中距离：中模
远处：低模
```

优点：

```text
减少远处模型三角形数量
提升渲染性能
```

------

## 7.2 HLOD

HLOD 是 Hierarchical LOD，层级细节。

它会把远处多个 Actor 合并成一个简化代理网格。

适合：

```text
开放世界
大场景
大量建筑
大量静态物体
```

作用：

```text
减少 Draw Call
减少远处物体复杂度
```

------

## 7.3 Nanite

Nanite 是 UE5 的虚拟化几何体系统，适合高面数静态模型渲染。

它可以根据屏幕像素级别自动选择需要显示的几何细节。

适合：

```text
高精度静态场景模型
岩石
建筑
雕塑
环境资产
```

不太适合或需要注意：

```text
大量变形骨骼网格，视版本和功能支持而定
透明材质
某些特殊 WPO 材质
移动端或低端平台
```

面试回答可以保持稳妥：

> Nanite 可以极大提升高面数静态网格的渲染效率，但不是所有东西都适合 Nanite，透明材质、特殊变形、移动端平台等需要根据项目和引擎版本具体评估。

------

## 7.4 三者对比

| 技术   | 作用                 | 适合             |
| ------ | -------------------- | ---------------- |
| LOD    | 单个模型远近切换精度 | 普通模型         |
| HLOD   | 远处多个物体合并简化 | 大场景、开放世界 |
| Nanite | 虚拟化高精度几何渲染 | 高面数静态资产   |

------

# 8. Lumen 是什么？有什么性能注意点？

`Lumen` 是 UE5 的动态全局光照和反射系统。

它可以实现：

```text
动态间接光照
动态反射
光照随场景变化实时更新
```

优点：

```text
不用传统烘焙也能有较好的动态 GI
适合动态时间、动态光源、可破坏场景
```

缺点：

```text
性能开销较大
移动端和低端设备需要谨慎
复杂场景下需要调质量
```

面试推荐回答：

> Lumen 是 UE5 的动态全局光照和反射系统，可以让场景光照实时变化，减少传统烘焙需求。但它有一定性能成本，尤其在低端平台或复杂场景中，需要调整质量、反射、阴影和后处理设置。

------

# 9. World Partition 是什么？

`World Partition` 是 UE5 的开放世界关卡管理系统。

它会把大地图划分成网格，根据玩家位置自动加载和卸载区域。

适合：

```text
开放世界
大型关卡
无缝地图
大规模场景
```

传统方式可能需要手动做 Level Streaming：

```text
Persistent Level
    ├── Streaming Level A
    ├── Streaming Level B
    └── Streaming Level C
```

World Partition 则更自动化：

```text
大地图被切成很多 Cell
玩家附近 Cell 加载
远处 Cell 卸载
```

面试回答：

> World Partition 是 UE5 用于大世界的关卡管理系统，它把地图划分成网格 Cell，并根据玩家位置自动流式加载和卸载区域，适合开放世界和大型场景。它可以减少一次性加载整个地图带来的内存压力。

------

# 10. Level Streaming 是什么？

`Level Streaming` 是流式关卡加载。

它允许在游戏运行时加载或卸载子关卡。

用途：

```text
分区域加载地图
进入副本加载房间
开放世界分块
室内外切换
减少内存占用
```

例如：

```text
玩家接近城镇
    → 加载 Town_Level
玩家离开城镇
    → 卸载 Town_Level
```

面试回答：

> Level Streaming 允许运行时加载和卸载子关卡，用来减少一次性加载内容，控制内存和性能。World Partition 可以看作 UE5 中更自动化的大世界流送方案，而传统 Level Streaming 更手动。

------

# 11. 资源加载如何优化？

资源加载问题常见表现：

```text
打开界面卡顿
切换关卡卡顿
第一次释放技能卡顿
生成怪物卡顿
内存占用过高
```

------

## 11.1 硬引用和软引用

### 硬引用

例如蓝图中直接引用某个资源：

```text
角色蓝图直接引用大型怪物蓝图
怪物蓝图引用大量动画、材质、音效
```

可能导致加载角色时，把相关资源一起加载进内存。

------

### 软引用

`TSoftObjectPtr` / `TSoftClassPtr` 保存的是资源路径，不会立刻加载。

适合：

```text
大型资源
技能特效
怪物蓝图
UI 图标
关卡资源
```

可以在需要时异步加载。

------

## 11.2 异步加载

对于较大资源，可以：

```text
提前加载
异步加载
加载完成后再使用
```

避免游戏过程中突然卡顿。

------

## 11.3 面试推荐回答

> 资源加载优化要注意硬引用导致的连带加载。对于大型资源或不一定马上使用的资源，可以用软引用和异步加载，减少初始加载和内存压力。释放技能、打开 UI、刷怪前可以提前预加载关键资源，避免首次使用卡顿。

------

# 12. 内存如何优化？

常见内存占用来源：

```text
高分辨率贴图
大量动画
大量音频
未卸载关卡
硬引用链
对象未释放
对象池过大
```

优化方式：

```text
降低贴图分辨率
使用纹理压缩
减少不必要资源引用
使用软引用
卸载不用关卡
控制对象池大小
使用资源审计工具
```

面试回答：

> 内存优化常见方向是控制贴图、动画、音频等资源大小，避免硬引用链导致资源常驻内存，使用软引用和异步加载，及时卸载不用的关卡和资源。对象池虽然能减少创建销毁，但池子过大也会占用内存，需要设置合理上限。

------

# 13. 动画性能如何优化？

动画系统也可能消耗 CPU。

优化方式：

```text
减少复杂 Anim Blueprint Tick
远处角色降低动画更新频率
使用 Update Rate Optimization
不重要 NPC 降低骨骼刷新
减少复杂 IK
LOD 关闭远处角色高成本节点
动画 Notify 不做复杂逻辑
```

------

## 13.1 远处 NPC 优化

远处 AI 不需要每帧高精度动画：

```text
降低动画更新频率
关闭 IK
使用低精度 LOD
隐藏后停止动画
```

------

## 13.2 面试推荐回答

> 动画优化可以减少 Anim Blueprint 中复杂逻辑，远处角色降低动画更新频率或关闭高成本 IK，使用动画 LOD 和 Update Rate Optimization。动画 Notify 中不要做复杂计算，复杂战斗逻辑应该交给角色或技能系统处理。

------

# 14. AI 性能如何优化？

大量 AI 会带来：

```text
行为树开销
寻路开销
感知开销
Tick 开销
碰撞开销
动画开销
```

优化方式：

```text
降低感知检测频率
AI 分层更新
远处 AI 简化逻辑
减少每帧 MoveTo / Trace
使用 LOD 思想处理 AI
避免大量 AI 同时寻路
```

例如：

```text
近处 AI：完整行为树 + 动画 + 感知
中距离 AI：低频行为更新
远处 AI：只做简单状态或休眠
```

面试回答：

> AI 优化可以降低感知和行为树更新频率，避免大量 AI 同时寻路或每帧 Trace。远处 AI 可以降低逻辑精度甚至休眠，近处 AI 才运行完整行为。大量 AI 场景要注意 NavMesh 寻路、感知和动画更新的综合开销。

------

# 15. UI 性能如何优化？

前面 UMG 部分提过，这里从性能角度总结：

```text
减少 Widget Tick
减少绑定函数
事件驱动更新
复用 Widget
伤害飘字用对象池
复杂列表用虚拟化
避免过深 UI 层级
减少透明叠加
```

面试回答：

> UI 优化主要是减少 Tick 和复杂绑定函数，使用事件驱动更新；频繁打开的界面保存引用复用；伤害数字这类高频 UI 可以对象池；大量列表使用虚拟化控件；复杂界面减少层级和透明叠加。

------

# 16. 网络性能如何优化？

如果是多人项目，还要考虑网络同步。

常见优化：

```text
只复制必要 Actor
只复制必要变量
降低 Net Update Frequency
使用 relevancy
使用 dormancy
避免频繁 RPC
状态用 Replication，瞬时事件用 RPC
不要同步纯客户端表现
```

例如：

```text
本地 UI 不需要复制
纯视觉特效可以用 Gameplay Cue 或客户端播放
远处无关 Actor 不需要频繁同步
```

面试回答：

> 网络优化主要是减少不必要复制。只复制需要服务器同步的 Actor 和变量，调整 Net Update Frequency，使用网络相关性和休眠机制。持续状态适合 Replication，瞬时事件适合 RPC。纯本地 UI 和只影响本地的表现不应该走网络同步。

# 18. 如何判断是 CPU 瓶颈还是 GPU 瓶颈？

使用：

```text
stat unit
```

看：

```text
Game
Draw
GPU
```

一般理解：

```text
Game 高：游戏线程 CPU 瓶颈
Draw 高：渲染线程 CPU 瓶颈
GPU 高：GPU 渲染瓶颈
```

例如：

```text
Game = 20ms
GPU = 8ms
```

说明游戏逻辑 CPU 更可能是瓶颈。

如果：

```text
Game = 8ms
GPU = 24ms
```

说明 GPU 渲染更可能是瓶颈。

面试回答：

> 可以用 stat unit 看 Game、Draw、GPU 时间。Game 高通常是游戏逻辑 CPU 瓶颈，比如 Tick、AI、碰撞、蓝图；Draw 高通常是渲染线程提交开销；GPU 高说明渲染负担重，比如材质、阴影、后处理、Lumen、透明物体等。

# 19. 面试高频题：场景卡顿你怎么排查？

可以按流程回答：

```text
1. 先用 stat fps / stat unit 看整体帧率和瓶颈位置
2. 如果 Game 高，看 Tick、蓝图、AI、碰撞、动画
3. 如果 Draw 高，看 Draw Call、Actor 数量、材质数量
4. 如果 GPU 高，看阴影、后处理、Lumen、材质、透明物体
5. 如果是加载卡顿，看资源引用、异步加载、硬引用链
6. 用 Unreal Insights 做更详细分析
```

面试推荐回答：

> 我不会一开始就盲目优化，而是先用 stat unit 判断瓶颈在 Game、Draw 还是 GPU。如果 Game 高，就看 Tick、蓝图、AI、碰撞、动画；如果 GPU 高，就看材质、阴影、后处理、Lumen 和透明物体；如果是切换场景或第一次释放技能卡顿，就检查资源加载和硬引用。之后再用 Unreal Insights 做更细的分析。

# 20. 面试高频题：如何优化大量子弹？

大量子弹涉及：

```text

Tick
碰撞
Trace
渲染
网络同步
```

优化方式：

```text
对象池复用子弹
用 ProjectileMovementComponent 或集中管理
关闭不必要 Tick
使用简单碰撞
合理设置生命周期
远距离隐藏或销毁
```

# 23. 面试高频题：Nanite 和 Lumen 是什么？

可以简洁回答：

> Nanite 是 UE5 的虚拟化几何体系统，用来高效渲染高面数模型，适合高精度静态环境资产。Lumen 是 UE5 的动态全局光照和反射系统，可以实现实时 GI 和反射。两者能提高画面表现，但也要根据平台和性能目标合理使用，移动端或低端平台不能无脑开启。

# 24. 第十部分综合面试模板

如果面试官问：“你了解 UE 性能优化吗？”

> 对于大地图，可以使用 World Partition 和关卡流送减少一次性加载；资源上用软引用和异步加载避免硬引用链导致的卡顿和内存压力。优化过程可以用 Unreal Insights、stat game、stat gpu、GPU Visualizer、Size Map 和 Reference Viewer 来分析。
