# 四、容器和数据结构问题

## 1. TArray、TMap、TSet 分别是什么？

UE C++ 中有自己的一套容器类型，常见的有：

```cpp
TArray
TMap
TSet
```

它们大致可以类比 STL 中的：

| UE 容器  | 类似 STL             | 作用       |
| -------- | -------------------- | ---------- |
| `TArray` | `std::vector`        | 动态数组   |
| `TMap`   | `std::unordered_map` | 键值对     |
| `TSet`   | `std::unordered_set` | 不重复集合 |

面试时可以先这样答：

> `TArray` 是动态数组，适合按顺序存储多个元素；`TMap` 是键值对容器，适合通过 Key 查找 Value；`TSet` 是集合，里面的元素不能重复，适合快速判断某个元素是否存在。

------

# 2. TArray 是什么？

## 2.1 基本概念

`TArray` 是 UE 中最常用的动态数组。

例如：

```cpp
TArray<int32> Scores;
TArray<AActor*> Enemies;
TArray<FVector> PatrolPoints;
```

它的特点是：

- 元素连续存储
- 可以动态扩容
- 支持下标访问
- 适合顺序遍历
- 适合保存一组对象

例如：

```cpp
TArray<int32> Numbers;

Numbers.Add(10);
Numbers.Add(20);
Numbers.Add(30);

int32 FirstValue = Numbers[0];
```

------

## 2.2 常见操作

### Add：添加元素

```cpp
TArray<int32> Numbers;
Numbers.Add(10);
Numbers.Add(20);
```

结果：

```text
[10, 20]
```

------

### Num：获取数量

```cpp
int32 Count = Numbers.Num();
```

------

### IsValidIndex：判断索引是否合法

```cpp
if (Numbers.IsValidIndex(0))
{
    int32 Value = Numbers[0];
}
```

比直接访问更安全。

------

### Remove：按值删除

```cpp
Numbers.Remove(20);
```

会删除数组中所有等于 `20` 的元素。

------

### RemoveAt：按索引删除

```cpp
Numbers.RemoveAt(0);
```

删除索引为 `0` 的元素。

------

### Empty：清空数组

```cpp
Numbers.Empty();
```

------

### Contains：是否包含元素

```cpp
if (Numbers.Contains(10))
{
    // 包含 10
}
```

------

### Find：查找元素索引

```cpp
int32 Index = Numbers.Find(10);
```

如果没找到，一般返回 `INDEX_NONE`。

```cpp
if (Index != INDEX_NONE)
{
    // 找到了
}
```

------

## 2.3 TArray 删除元素要注意什么？

`TArray` 是连续数组，所以删除中间元素时，后面的元素通常会前移。

例如：

```text
[10, 20, 30, 40]
RemoveAt(1)
```

结果：

```text
[10, 30, 40]
```

`30` 和 `40` 会向前移动。

这意味着：

1. 删除中间元素有移动成本
2. 遍历时删除要小心索引变化
3. 如果不关心顺序，可以用更快的删除方式

------

## 2.4 RemoveAtSwap 是什么？

如果你不关心数组顺序，可以使用：

```cpp
Numbers.RemoveAtSwap(Index);
```

它会用最后一个元素填补被删除的位置，避免大量元素前移。

例如：

```text
[10, 20, 30, 40]
RemoveAtSwap(1)
```

可能变成：

```text
[10, 40, 30]
```

优点：

- 删除更快

缺点：

- 元素顺序会变

面试中可以说：

> `RemoveAt` 会保持顺序，但可能移动后续元素；`RemoveAtSwap` 不保证顺序，但删除更快。

------

## 2.5 遍历 TArray

### 普通 for

```cpp
for (int32 i = 0; i < Enemies.Num(); ++i)
{
    AActor* Enemy = Enemies[i];
}
```

------

### 范围 for

```cpp
for (AActor* Enemy : Enemies)
{
    if (Enemy)
    {
        // 使用 Enemy
    }
}
```

------

### 删除时倒序遍历

如果遍历时要删除元素，常用倒序：

```cpp
for (int32 i = Enemies.Num() - 1; i >= 0; --i)
{
    if (!IsValid(Enemies[i]))
    {
        Enemies.RemoveAt(i);
    }
}
```

为什么倒序？

因为删除当前元素后，只会影响它后面的元素；倒序遍历时，前面的索引不受影响。

------

# 3. TMap 是什么？

## 3.1 基本概念

`TMap` 是键值对容器。

例如：

```cpp
TMap<FString, int32> PlayerScores;
```

表示：

```text
玩家名字 → 分数
```

使用示例：

```cpp
TMap<FString, int32> PlayerScores;

PlayerScores.Add(TEXT("Alice"), 100);
PlayerScores.Add(TEXT("Bob"), 80);
```

------

## 3.2 通过 Key 查找 Value

```cpp
int32* Score = PlayerScores.Find(TEXT("Alice"));

if (Score)
{
    UE_LOG(LogTemp, Warning, TEXT("Score: %d"), *Score);
}
```

注意：

`Find` 返回的是指针，因为可能找不到。

------

## 3.3 Contains

```cpp
if (PlayerScores.Contains(TEXT("Alice")))
{
    // 存在这个 Key
}
```

------

## 3.4 FindOrAdd

```cpp
int32& Score = PlayerScores.FindOrAdd(TEXT("Alice"));
Score += 10;
```

如果 Key 存在，就返回已有 Value；如果不存在，就添加一个默认 Value。

------

## 3.5 Add 覆盖问题

如果你对同一个 Key 调用 `Add`：

```cpp
PlayerScores.Add(TEXT("Alice"), 100);
PlayerScores.Add(TEXT("Alice"), 200);
```

后面的值会覆盖前面的值。

也就是说一个 Key 只能对应一个 Value。

------

## 3.6 遍历 TMap

```cpp
for (const TPair<FString, int32>& Pair : PlayerScores)
{
    UE_LOG(LogTemp, Warning, TEXT("%s: %d"), *Pair.Key, Pair.Value);
}
```

也可以写：

```cpp
for (auto& Pair : PlayerScores)
{
    FString Name = Pair.Key;
    int32 Score = Pair.Value;
}
```

------

## 3.7 TMap 适合什么场景？

适合通过某个 Key 快速找到数据。

例如：

```cpp
TMap<FName, int32> ItemCountMap;
```

物品 ID → 数量

```cpp
TMap<AActor*, float> DamageRecord;
```

敌人 Actor → 已造成伤害

```cpp
TMap<FName, UAnimMontage*> MontageMap;
```

技能名 → 蒙太奇资源

```cpp
TMap<FGameplayTag, TSubclassOf<UGameplayAbility>> AbilityMap;
```

技能标签 → 技能类

------

## 3.8 面试推荐回答

> `TMap` 是键值对容器，适合通过 Key 快速查找 Value。比如物品 ID 对应物品数量，技能标签对应技能类。`Find` 返回指针，因为 Key 可能不存在；`Contains` 可以判断 Key 是否存在；同一个 Key 只能对应一个 Value。

------

# 4. TSet 是什么？

## 4.1 基本概念

`TSet` 是集合容器。

特点是：

- 元素唯一
- 不允许重复
- 适合快速判断某个元素是否存在
- 不强调顺序

例如：

```cpp
TSet<AActor*> HitActors;
```

常见用途：

> 近战攻击中记录本次攻击已经命中过哪些敌人，防止同一次攻击重复造成伤害。

------

## 4.2 基本操作

```cpp
TSet<int32> Numbers;

Numbers.Add(1);
Numbers.Add(2);
Numbers.Add(2);
```

虽然添加了两次 `2`，但集合中只会有一个 `2`。

------

### Contains

```cpp
if (Numbers.Contains(2))
{
    // 集合中有 2
}
```

------

### Remove

```cpp
Numbers.Remove(2);
```

------

### Num

```cpp
int32 Count = Numbers.Num();
```

------

### Empty

```cpp
Numbers.Empty();
```

------

## 4.3 近战攻击中的典型使用

假设攻击判定在一个时间窗口内连续检测命中敌人，如果不用 `TSet`，可能每一帧都对同一个敌人造成一次伤害。

可以这样做：

```cpp
TSet<AActor*> HitActors;
```

命中时：

```cpp
if (!HitActors.Contains(HitActor))
{
    HitActors.Add(HitActor);

    // 对 HitActor 造成伤害
}
```

攻击结束时：

```cpp
HitActors.Empty();
```

这样一次攻击中，同一个敌人只会受一次伤害。

------

## 4.4 TSet 和 TArray 的区别

| 对比         | TArray   | TSet                 |
| ------------ | -------- | -------------------- |
| 是否有顺序   | 有       | 不强调顺序           |
| 是否允许重复 | 允许     | 不允许               |
| 下标访问     | 支持     | 不支持常规下标       |
| 常见用途     | 保存列表 | 去重、快速存在性判断 |
| 示例         | 敌人数组 | 已命中敌人集合       |

------

## 4.5 面试推荐回答

> `TSet` 是集合容器，元素不能重复，适合做去重和快速存在性判断。比如近战攻击中可以用 `TSet<AActor*> HitActors` 记录本次攻击已经命中过的敌人，避免同一次攻击多次伤害同一个目标。

------

# 5. TArray、TMap、TSet 对比总结

| 容器     | 特点                      | 适合场景                          |
| -------- | ------------------------- | --------------------------------- |
| `TArray` | 动态数组，有顺序，可重复  | 敌人列表、路径点、背包格子        |
| `TMap`   | 键值对，通过 Key 找 Value | ID 查数据、标签查技能、玩家查分数 |
| `TSet`   | 集合，元素唯一            | 去重、已命中目标、已访问节点      |

简单记忆：

```text
TArray：我要一组有顺序的数据
TMap：我要通过 Key 找 Value
TSet：我要一组不重复的数据
```

# 6. TArray 和 std::vector 有什么区别？

面试可能会追问：

> UE 里为什么不用 `std::vector`，而是用 `TArray`？

可以这样理解：

`TArray` 和 `std::vector` 都是动态数组，但 `TArray` 更适配 UE 引擎系统。

------

## 6.1 TArray 更适合 UE 反射和序列化

例如：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite)
TArray<AActor*> Targets;
```

这样 `Targets` 可以：

- 在编辑器中显示
- 在蓝图中使用
- 被序列化
- 被 GC 追踪其中的 UObject 引用

但如果写：

```cpp
std::vector<AActor*> Targets;
```

UE 的反射系统不能像识别 `TArray` 那样识别它。

------

## 6.2 TArray 和 UE 内存系统配合更好

UE 有自己的内存分配、调试、序列化、反射、GC 体系，`TArray` 能更好地融入这些系统。

------

## 6.3 面试推荐回答

> `TArray` 类似 `std::vector`，但它是 UE 自己的动态数组，能更好地配合反射、蓝图、序列化、GC 和引擎内存系统。比如 `UPROPERTY TArray<UObject*>` 中的 UObject 引用可以被 GC 追踪，而普通 `std::vector` 不能很好地接入 UE 反射系统。

------

# 7. FString、FName、FText 的区别

这也是 UE C++ 面试中非常常见的问题。

------

## 7.1 FString

`FString` 是普通字符串，适合进行字符串拼接、修改和处理。

例如：

```cpp
FString PlayerName = TEXT("Player");
PlayerName += TEXT("_01");
```

适合：

- 字符串拼接
- 文件路径
- 调试输出
- 动态生成文本

------

## 7.2 FName

`FName` 是名字标识，适合做 ID、Key、标签名。

特点：

- 不适合频繁修改
- 比字符串比较更快
- 常用于资源名、Socket 名、Bone 名、Tag 名

例如：

```cpp
FName SocketName = TEXT("Muzzle");
```

常见场景：

```cpp
MeshComp->GetSocketLocation(TEXT("Muzzle"));
```

或者：

```cpp
TMap<FName, int32> ItemCountMap;
```

------

## 7.3 FText

`FText` 用于面向玩家显示的文本，支持本地化。

例如：

```cpp
FText DisplayName = FText::FromString(TEXT("开始游戏"));
```

适合：

- UI 显示文字
- 多语言本地化
- 玩家可见文本

------

## 7.4 三者对比

| 类型      | 用途           | 是否适合显示给玩家         | 是否适合修改         |
| --------- | -------------- | -------------------------- | -------------------- |
| `FString` | 普通字符串处理 | 可以，但不推荐做本地化文本 | 适合                 |
| `FName`   | 名字、ID、Key  | 不适合                     | 不适合频繁修改       |
| `FText`   | UI显示、本地化 | 适合                       | 不适合复杂字符串处理 |

------

## 7.5 面试推荐回答

> `FString` 适合普通字符串处理，比如拼接、路径、调试文本；`FName` 适合作为名字或标识，比如 Socket 名、Bone 名、DataTable RowName、Map 的 Key，比较效率较高；`FText` 适合显示给玩家的文本，支持本地化，所以 UI 文本应该优先使用 FText。

------

# 8. UObject 指针相关容器要注意什么？

比如：

```cpp
TArray<AActor*> Enemies;
```

如果这个数组是类成员，并且你希望 GC 能识别里面的 Actor 引用，建议加：

```cpp
UPROPERTY()
TArray<AActor*> Enemies;
```

UE5 中也常见：

```cpp
UPROPERTY()
TArray<TObjectPtr<AActor>> Enemies;
```

如果不加 `UPROPERTY`，数组本身和里面的 UObject 引用不一定能被 GC 追踪。

------

## 8.1 错误示例

```cpp
class UMyManager : public UObject
{
    GENERATED_BODY()

public:
    TArray<UObject*> CachedObjects;
};
```

这个 `CachedObjects` 没有 `UPROPERTY`，GC 可能不知道这些引用。

------

## 8.2 推荐写法

```cpp
UCLASS()
class UMyManager : public UObject
{
    GENERATED_BODY()

public:
    UPROPERTY()
    TArray<TObjectPtr<UObject>> CachedObjects;
};
```

或者：

```cpp
UPROPERTY()
TArray<UObject*> CachedObjects;
```

------

## 8.3 面试推荐回答

> 如果容器里保存的是 UObject 指针，并且这个容器是类成员，通常应该用 UPROPERTY 标记，这样 GC 才能追踪容器里的引用。UE5 中也常用 `TObjectPtr` 来保存 UObject 引用。

------

# 9. TWeakObjectPtr 是什么？

## 9.1 基本概念

`TWeakObjectPtr` 是弱引用 UObject 的指针类型。

它不会阻止对象被 GC 回收。

例如：

```cpp
TWeakObjectPtr<AActor> TargetActor;
```

它适合保存“不拥有生命周期”的对象引用。

------

## 9.2 为什么需要弱引用？

比如 AI 记住一个目标敌人：

```cpp
TWeakObjectPtr<AActor> TargetActor;
```

如果目标敌人被销毁，弱引用不会强行让它继续存在。

使用前可以判断：

```cpp
if (TargetActor.IsValid())
{
    AActor* Target = TargetActor.Get();
}
```

------

## 9.3 适合场景

- 临时目标
- 缓存引用
- 不希望延长对象生命周期
- 避免悬空指针
- AI 目标
- UI 临时绑定对象

------

## 9.4 面试推荐回答

> `TWeakObjectPtr` 是 UObject 的弱引用，不会阻止对象被 GC。使用前要通过 `IsValid()` 判断对象是否还存在。它适合保存临时目标或缓存引用，比如 AI 当前目标、锁定目标等，可以避免对象销毁后留下危险的裸指针。

------

# 10. TSoftObjectPtr 和 TSoftClassPtr 是什么？

这部分实习岗不一定问，但知道会加分。

------

## 10.1 TSoftObjectPtr

`TSoftObjectPtr` 是软对象引用。

它保存的是资源路径，不一定立即加载资源。

例如：

```cpp
UPROPERTY(EditAnywhere)
TSoftObjectPtr<UTexture2D> IconTexture;
```

它适合引用资源但不想立刻加载。

常用于：

- 图标
- 音效
- 特效
- 大型资源
- 异步加载

------

## 10.2 TSoftClassPtr

`TSoftClassPtr` 是软类引用。

例如：

```cpp
UPROPERTY(EditAnywhere)
TSoftClassPtr<AActor> EnemyClass;
```

它保存类资源路径，可以在需要时加载。

------

## 10.3 和普通硬引用区别

普通引用：

```cpp
UPROPERTY(EditAnywhere)
TSubclassOf<AActor> EnemyClass;
```

如果蓝图中指定了某个类，可能形成硬引用，资源更容易被一起加载。

软引用：

```cpp
UPROPERTY(EditAnywhere)
TSoftClassPtr<AActor> EnemyClass;
```

不会立即加载目标资源，适合减少启动加载压力。

------

## 10.4 面试推荐回答

> `TSoftObjectPtr` 和 `TSoftClassPtr` 是软引用，保存的是资源路径，不会强制资源立即加载。它们适合引用大型资源或需要异步加载的资源，可以减少硬引用导致的加载压力。普通对象指针或 `TSubclassOf` 更像硬引用，使用更直接但可能增加资源依赖。

------

# 11. TSubclassOf 再补充一次

虽然上一部分提到过，但它和容器、数据配置经常一起问。

```cpp
UPROPERTY(EditAnywhere)
TSubclassOf<AActor> BulletClass;
```

表示：

> 保存一个 `AActor` 子类，而不是一个 Actor 实例。

使用：

```cpp
GetWorld()->SpawnActor<AActor>(BulletClass, Location, Rotation);
```

常见用途：

- 子弹类
- 怪物类
- UI Widget 类
- 技能类
- 掉落物类

面试推荐回答：

> `TSubclassOf` 用于保存某个基类的子类类型，比如 `TSubclassOf<AActor>` 可以在编辑器中指定一个 Actor 蓝图类，然后运行时用它 SpawnActor。它保存的是类，不是实例。

# 12. 实战例子：近战攻击中如何使用容器？

假设你要实现一个近战攻击。

需求：

- 攻击窗口内持续检测敌人
- 同一次攻击中，一个敌人只能受一次伤害
- 攻击结束后清空命中记录

可以使用：

```cpp
UPROPERTY()
TSet<TObjectPtr<AActor>> HitActors;
```

命中时：

```cpp
void AMyCharacter::OnWeaponHit(AActor* HitActor)
{
    if (!IsValid(HitActor))
    {
        return;
    }

    if (HitActors.Contains(HitActor))
    {
        return;
    }

    HitActors.Add(HitActor);

    UGameplayStatics::ApplyDamage(
        HitActor,
        AttackDamage,
        GetController(),
        this,
        nullptr
    );
}
```

攻击结束：

```cpp
void AMyCharacter::EndAttack()
{
    HitActors.Empty();
}
```

这里为什么用 `TSet`？

因为它天然去重，适合记录“已经命中过的敌人”。

# 13. 实战例子：背包系统中如何使用容器？

假设你做一个简单背包：

```cpp
TMap<FName, int32> ItemCountMap;
```

表示：

```text
物品 ID → 数量
```

添加物品：

```cpp
void UInventoryComponent::AddItem(FName ItemID, int32 Count)
{
    int32& CurrentCount = ItemCountMap.FindOrAdd(ItemID);
    CurrentCount += Count;
}
```

查询物品数量：

```cpp
int32 UInventoryComponent::GetItemCount(FName ItemID) const
{
    if (const int32* Count = ItemCountMap.Find(ItemID))
    {
        return *Count;
    }

    return 0;
}
```

这里为什么用 `TMap`？

因为可以通过物品 ID 快速查找数量。

# 14. 实战例子：巡逻点如何使用 TArray？

AI 巡逻点可以用：

```cpp
UPROPERTY(EditInstanceOnly)
TArray<AActor*> PatrolPoints;
```

AI 依次访问：

```cpp
AActor* GetNextPatrolPoint()
{
    if (PatrolPoints.Num() == 0)
    {
        return nullptr;
    }

    CurrentPatrolIndex = (CurrentPatrolIndex + 1) % PatrolPoints.Num();
    return PatrolPoints[CurrentPatrolIndex];
}
```

这里为什么用 `TArray`？

因为巡逻点有顺序，适合数组。

# 15. 面试高频追问总结

## 15.1 TArray 删除元素会发生什么？

推荐回答：

> `TArray` 是连续数组，删除中间元素时后面的元素会前移，所以有移动成本。如果遍历时删除，要注意索引变化，可以倒序遍历。如果不关心顺序，可以用 `RemoveAtSwap` 提高效率。

------

## 15.2 TMap 的 Find 为什么返回指针？

推荐回答：

> 因为 Key 可能不存在。返回指针可以用是否为 `nullptr` 判断是否找到。如果找到了，指针指向对应的 Value。

------

## 15.3 TSet 适合什么场景？

推荐回答：

> `TSet` 适合去重和快速判断是否存在。比如近战攻击记录已经命中过的敌人，避免一次攻击重复造成伤害。

------

## 15.4 为什么 UE 推荐使用自己的容器？

推荐回答：

> 因为 UE 容器能更好地配合反射、蓝图、序列化、GC、网络复制和引擎内存系统。比如 `UPROPERTY TArray<UObject*>` 可以让 GC 追踪数组中的 UObject 引用，而 STL 容器不能很好地接入 UE 反射系统。

------

# 16. 第四部分综合面试模板

如果面试官问：“你了解 UE 中常用容器吗？”

可以这样回答：

> UE 中常用容器有 `TArray`、`TMap` 和 `TSet`。`TArray` 是动态数组，适合保存有顺序的一组数据，比如敌人列表、巡逻点、背包格子；`TMap` 是键值对容器，适合通过 Key 查找 Value，比如物品 ID 对应数量、技能标签对应技能类；`TSet` 是集合，元素唯一，适合去重和快速存在性判断，比如近战攻击中记录已经命中过的敌人。
>
> `TArray` 删除元素时要注意后续元素移动，遍历删除时可以倒序，如果不关心顺序可以用 `RemoveAtSwap`。`TMap::Find` 返回指针，因为 Key 可能不存在。UE 推荐使用自己的容器，是因为它们能更好地配合反射、蓝图、序列化和 GC。

# 17. 简短版背诵答案

面试时可以背这个版本：

> `TArray` 是动态数组，类似 `std::vector`，适合保存有顺序的数据；`TMap` 是键值对容器，类似哈希表，适合通过 Key 查找 Value；`TSet` 是集合，元素唯一，适合去重和判断是否存在。
>
> `TArray` 删除中间元素会导致后续元素移动，遍历删除时可以倒序；如果不关心顺序，可以用 `RemoveAtSwap`。`TMap::Find` 返回指针，因为 Key 可能不存在。`TSet` 常用于记录已命中对象，避免重复处理。
>
> UE 推荐使用自己的容器，因为它们能配合反射、蓝图、序列化、GC 和引擎内存系统。保存 UObject 指针的容器通常要加 `UPROPERTY`，否则 GC 可能无法正确追踪引用。
