### 反射宏

只要是我们自己写的东西，不管是类，结构体，变量，枚举，函数，都需要用反射宏标记后才可以被编辑器、蓝图、序列化、垃圾回收、网络复制等系统识别

```c++
UCLASS()
USTRUCT()
UENUM()
UINTERFACE()
UFUNCTION()
UPROPERTY()
UDELEGATE()
UMETA()
UPARAM()
GENERATED_BODY()
```

- UE5的所有源文件中都使用了这些宏，所以他们自然可以被UE5识别

------

#### 新建C++类

如果我们新建一个C++类，文件会自带两个头文件

```
#include "CoreMinimal.h"
#include "BaseGameplayAbility.generated.h"
```

这些反射宏都定义在CoreMinimal.h中，所以我们一开始就可以使用所有的反射宏

------

#### 反射宏的用法

**UCLASS()只能对继承于UObject的类使用**，例如：

```c++
UCLASS()
class GAS_DEMO_API UBaseGameplayAbility : public UGameplayAbility
{
	GENERATED_BODY()
	
	UMaterialInstance* IconMaterial;
	
public:
	//将函数暴露给蓝图
	UFUNCTION(BlueprintCallable, Category = "AbilityInfo")
	//获取技能属性信息函数，根据传进的技能等级获取技能的属性信息
	FGameplayAbilityInfo GetAbilityInfo(int level);
};
```

UGameplayAbility是继承UObject的类，所以UBaseGameplayAbility自然也是

**其他的宏没有使用限制**

### 命名前缀

命名前缀仅仅**只是用于规范化代码格式**的，本身并没有什么实际意义
命名前缀是类，结构体，枚举等**类型**的前缀，而不是某个实例化对象的前缀

```c++
FGameplayAbilityInfo GetAbilityInfo(int level);
//FGameplayAbilityInfo是我们创建的结构体的名字，拥有命名前缀F，而GetAbilityInfo是该结构体的示例对象的名字，并不遵守前缀
```

| 前缀 | 含义              | 示例                                |
| ---- | ----------------- | ----------------------------------- |
| A    | Actor 类          | `ACharacter`, `APlayerController`   |
| U    | UObject 类        | `UActorComponent`, `UUserWidget`    |
| F    | Struct / 普通类型 | `FVector`, `FRotator`, `FHitResult` |
| I    | Interface         | `IInteractableInterface`            |
| E    | Enum              | `EWeaponType`                       |
| T    | Template          | `TArray`, `TMap`, `TSubclassOf`     |
| S    | Slate 控件        | `SButton`, `STextBlock`             |

​	比如我们看到UE5源文件中有一个U开头的类，我们就可以立刻知道他是继承自UObject的类；如果是A开头，那么就知道他不仅是UObject的子类，而且是其中Actor的子类

​	如果我们要自己写C++文件，那么也要注意遵守命名前缀，创建结构体时要加F，创建枚举时要加E
