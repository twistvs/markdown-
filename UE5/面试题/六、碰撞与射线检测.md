下面回答 **六、碰撞和射线检测问题**。这一部分在 UE5 面试中非常常见，因为角色移动、攻击命中、交互、子弹、AI 感知、物理检测都离不开碰撞系统。

------

# 六、碰撞和射线检测问题

## 1. UE 中的碰撞系统是什么？

UE 的碰撞系统用于判断对象之间是否发生接触、阻挡、重叠或检测命中。

常见用途包括：

```text
角色是否能穿过墙
子弹是否命中敌人
玩家是否进入触发区域
攻击范围是否打到目标
鼠标点击是否选中物体
AI 是否能看到玩家
物品是否能被拾取
```

UE 中的碰撞并不只是“撞上”，它还包括三种主要响应：

```text
Ignore：忽略
Overlap：重叠
Block：阻挡
```

------

# 2. Block、Overlap、Ignore 分别是什么？

## 2.1 Block

`Block` 表示阻挡。

例如：

```text
角色碰到墙
    → 被墙挡住
    → 不能继续穿过去
```

常见场景：

```text
角色 vs 墙体
子弹 vs 墙体
物理物体 vs 地面
```

如果两个对象之间设置为 Block，通常会产生阻挡效果，并且可以得到 Hit 事件。

------

## 2.2 Overlap

`Overlap` 表示重叠，不阻挡移动，但会触发重叠事件。

例如：

```text
玩家进入触发器范围
    → 不会被挡住
    → 触发 BeginOverlap
```

常见场景：

```text
拾取物检测玩家
技能范围检测敌人
触发区域检测进入
AI 感知范围
治疗区域
陷阱区域
```

Overlap 适合做“进入范围后触发某件事”。

------

## 2.3 Ignore

`Ignore` 表示完全忽略，不阻挡，也不触发重叠。

例如：

```text
子弹忽略发射者
队友之间不碰撞
特效对象不参与碰撞
装饰物不参与角色检测
```

------

## 2.4 面试推荐回答

> UE 的碰撞响应主要有 Ignore、Overlap、Block。Ignore 表示完全忽略；Overlap 表示可以重叠并触发重叠事件，但不会阻挡；Block 表示阻挡对方，并可能产生 Hit 事件。比如墙体通常 Block 角色，拾取物通常 Overlap 玩家，特效一般 Ignore 大多数对象。

------

# 3. Collision Enabled 是什么？

组件的碰撞是否启用，由 `Collision Enabled` 控制。

常见选项有：

```text
No Collision
Query Only
Physics Only
Query and Physics
```

------

## 3.1 No Collision

完全不参与碰撞。

```text
既不参与射线检测
也不参与 Overlap
也不参与物理模拟
```

适合：

```text
纯视觉装饰物
背景物件
不需要检测的特效
```

------

## 3.2 Query Only

只参与查询，不参与物理模拟。

Query 包括：

```text
Line Trace
Sphere Trace
Overlap 检测
Sweep 检测
```

适合：

```text
触发器
交互检测
攻击判定
拾取范围
AI 感知范围
```

例如一个触发盒通常设置为 `Query Only`。

------

## 3.3 Physics Only

只参与物理模拟，不参与查询。

这个相对少见。

------

## 3.4 Query and Physics

既参与查询，也参与物理模拟。

适合：

```text
可推动箱子
物理掉落物
刚体物体
车辆
可破坏物
```

------

## 3.5 面试推荐回答

> Collision Enabled 决定组件是否参与碰撞。No Collision 是完全不碰撞；Query Only 只参与射线、Overlap、Sweep 等查询，适合触发器和攻击检测；Physics Only 只参与物理模拟；Query and Physics 同时参与查询和物理，适合可模拟物理的物体。

------

# 4. Object Channel 和 Trace Channel 有什么区别？

这是 UE 碰撞系统里的重点。

UE 的碰撞通道大致分为两类：

```text
Object Channel：对象通道
Trace Channel：检测通道
```

------

## 4.1 Object Channel 是什么？

`Object Channel` 表示对象自身是什么类型。

例如：

```text
WorldStatic
WorldDynamic
Pawn
PhysicsBody
Vehicle
Destructible
```

也可以自定义：

```text
Enemy
Player
Projectile
Interactable
Pickup
```

比如一个玩家角色可能设置为：

```text
Object Type = Pawn
```

一个墙体可能是：

```text
Object Type = WorldStatic
```

一个子弹可能是：

```text
Object Type = Projectile
```

简单说：

> Object Channel 是对象自己的身份。

------

## 4.2 Trace Channel 是什么？

`Trace Channel` 是检测用的通道。

例如：

```text
Visibility
Camera
```

也可以自定义：

```text
WeaponTrace
InteractTrace
SkillTrace
```

当你做 Line Trace 时，通常会选择一个 Trace Channel：

```text
LineTraceByChannel：使用 Visibility 通道检测
LineTraceByChannel：使用 WeaponTrace 通道检测
```

简单说：

> Trace Channel 是检测时发出的“问题”。

比如：

```text
我用 Visibility 射线检测：
    你是否阻挡 Visibility？

我用 WeaponTrace 射线检测：
    你是否阻挡 WeaponTrace？
```

------

## 4.3 两者区别

| 对比   | Object Channel                | Trace Channel                   |
| ------ | ----------------------------- | ------------------------------- |
| 含义   | 对象自己的类型                | 检测使用的通道                  |
| 谁拥有 | 组件自身                      | Trace / Sweep 发起时指定        |
| 例子   | Pawn、WorldStatic、Projectile | Visibility、Camera、WeaponTrace |
| 作用   | 表示“我是什么”                | 表示“我要检测什么”              |

------

## 4.4 举例理解

假设你有一条交互射线：

```text
InteractTrace
```

你希望：

```text
门：Block InteractTrace
敌人：Ignore InteractTrace
墙：Block InteractTrace
装饰物：Ignore InteractTrace
```

这样玩家按 E 时，射线只会检测到需要交互或阻挡交互的对象。

------

## 4.5 面试推荐回答

> Object Channel 表示对象自己的碰撞类型，比如 Pawn、WorldStatic、Projectile；Trace Channel 是射线或 Sweep 检测时使用的通道，比如 Visibility、Camera、WeaponTrace。简单说，Object Channel 是“我是什么”，Trace Channel 是“我用什么规则去检测”。

------

# 5. Collision Preset 是什么？

`Collision Preset` 是 UE 预设好的碰撞配置。

它包含：

```text
Collision Enabled
Object Type
对各个 Channel 的 Response
```

例如常见预设：

```text
NoCollision
BlockAll
OverlapAll
Pawn
CharacterMesh
PhysicsActor
Trigger
Custom
```

------

## 5.1 Trigger 预设

Trigger 通常用于触发器。

一般特点：

```text
Collision Enabled = Query Only
Response = Overlap
```

适合：

```text
门触发区域
拾取物范围
陷阱范围
任务区域
```

------

## 5.2 Pawn 预设

角色的 CapsuleComponent 通常使用 Pawn 类型，用来和世界、角色、物理物体产生碰撞。

------

## 5.3 Custom

当预设不满足需求时，可以使用 Custom 自定义每个通道的响应。

例如：

```text
Pawn：Block
WorldStatic：Block
Projectile：Ignore
InteractTrace：Block
```

------

## 5.4 面试推荐回答

> Collision Preset 是碰撞预设，包含碰撞是否启用、对象类型以及对各个通道的响应规则。比如 Trigger 常用于触发区域，通常只做 Overlap；Pawn 用于角色；如果默认预设不满足需求，可以使用 Custom 自定义每个 Channel 的响应。

------

# 6. Set Collision Response to Channel 是做什么的？

`Set Collision Response to Channel` 用来在运行时修改某个组件对指定通道的响应。

比如：

```text
让角色临时无敌
让门打开后不再阻挡玩家
让攻击判定只在攻击窗口中开启
让子弹忽略某些目标
```

------

## 6.1 示例：门打开后不阻挡玩家

门关闭时：

```text
Pawn → Block
```

门打开后：

```text
Set Collision Response to Channel
Channel = Pawn
Response = Ignore
```

这样玩家就可以通过门。

------

## 6.2 示例：攻击判定窗口

非攻击状态：

```text
Weapon Collision → NoCollision
```

攻击 Notify Begin：

```text
Set Collision Enabled = Query Only
Set Collision Response to Pawn = Overlap
```

攻击 Notify End：

```text
Set Collision Enabled = NoCollision
```

------

## 6.3 示例：子弹忽略发射者

生成子弹后，可以设置忽略发射者：

```cpp
CollisionComp->IgnoreActorWhenMoving(OwnerActor, true);
```

或者通过通道规则让同队对象 Ignore。

------

## 6.4 面试推荐回答

> Set Collision Response to Channel 用来动态修改组件对某个碰撞通道的响应，比如从 Block 改成 Ignore，或者从 Ignore 改成 Overlap。常见用途是门打开后不再阻挡玩家、攻击窗口中临时开启武器碰撞、角色无敌时忽略伤害检测等。

------

# 7. Hit Event 和 Overlap Event 有什么区别？

## 7.1 Hit Event

Hit Event 通常发生在两个对象发生阻挡碰撞时。

常见事件：

```text
OnComponentHit
Event Hit
```

一般需要：

```text
双方碰撞设置为 Block
至少一个对象发生移动或物理碰撞
Simulation Generates Hit Events 开启，部分情况需要
```

适合：

```text
子弹撞墙
角色撞到物体
物理箱子撞击地面
投掷物命中目标
```

------

## 7.2 Overlap Event

Overlap Event 发生在两个对象重叠时。

常见事件：

```text
OnComponentBeginOverlap
OnComponentEndOverlap
```

一般需要：

```text
碰撞响应为 Overlap
Generate Overlap Events 开启
```

适合：

```text
玩家进入触发区域
拾取物检测玩家
技能范围检测敌人
治疗区域检测目标
```

------

## 7.3 对比总结

| 对比     | Hit                | Overlap                   |
| -------- | ------------------ | ------------------------- |
| 响应类型 | Block              | Overlap                   |
| 是否阻挡 | 阻挡               | 不阻挡                    |
| 常见用途 | 子弹撞墙、物理碰撞 | 触发器、拾取、范围检测    |
| 常见事件 | OnHit              | BeginOverlap / EndOverlap |

------

## 7.4 面试推荐回答

> Hit 通常对应 Block，会发生阻挡，适合子弹撞墙、物体碰撞等；Overlap 对应重叠，不会阻挡，适合触发器、拾取物、技能范围检测。Overlap 需要开启 Generate Overlap Events，Hit 在某些情况下需要开启 Simulation Generates Hit Events。

------

# 8. Line Trace 是什么？

`Line Trace` 是从起点到终点发出一条线段，用来检测这条线段上是否命中对象。

可以理解为：

```text
从 A 点向 B 点发射一条不可见射线
看它碰到了什么
```

常见用途：

```text
射击命中检测
鼠标点击选中物体
玩家交互检测
AI 视线检测
地面检测
摄像机遮挡检测
```

------

## 8.1 Line Trace 的基本参数

一次 Line Trace 通常需要：

```text
Start：起点
End：终点
Trace Channel：检测通道
Actors to Ignore：忽略对象
Hit Result：命中结果
Draw Debug Type：调试绘制
```

例如第一人称射击：

```text
Start = 摄像机位置
End = 摄像机位置 + 摄像机前方向 * 射程
```

------

## 8.2 Hit Result 包含什么？

`FHitResult` 中常见信息：

```text
Hit Actor：命中的 Actor
Hit Component：命中的组件
Impact Point：实际碰撞点
Location：命中位置
Impact Normal：碰撞表面法线
Distance：命中距离
Bone Name：命中的骨骼名
Phys Material：物理材质
```

例如：

```cpp
if (HitResult.bBlockingHit)
{
    AActor* HitActor = HitResult.GetActor();
    FVector ImpactPoint = HitResult.ImpactPoint;
}
```

------

## 8.3 面试推荐回答

> Line Trace 是从起点到终点发出一条射线，检测路径上是否命中对象。它常用于射击、交互、鼠标选中、AI视线和地面检测。检测结果保存在 Hit Result 中，里面包含命中的 Actor、Component、位置、法线、骨骼名等信息。

------

# 9. LineTraceByChannel 和 LineTraceForObjects 的区别

这是高频追问。

------

## 9.1 LineTraceByChannel

`LineTraceByChannel` 使用一个 Trace Channel 进行检测。

例如：

```text
Visibility
Camera
WeaponTrace
InteractTrace
```

逻辑是：

```text
我发出一条 Visibility 射线
检测路径上的对象是否 Block Visibility
```

适合：

```text
交互检测
射击检测
视线检测
摄像机遮挡
```

------

## 9.2 LineTraceForObjects

`LineTraceForObjects` 根据对象类型检测。

例如只检测：

```text
Pawn
WorldDynamic
PhysicsBody
```

逻辑是：

```text
我只关心这些 Object Type 的对象
```

适合：

```text
只找敌人
只找物理物体
只找可拾取物
只找 WorldDynamic 对象
```

------

## 9.3 两者对比

| 对比         | LineTraceByChannel       | LineTraceForObjects |
| ------------ | ------------------------ | ------------------- |
| 根据什么检测 | Trace Channel            | Object Channel      |
| 关注点       | 对象是否响应这条检测通道 | 对象自身是什么类型  |
| 例子         | Visibility、WeaponTrace  | Pawn、PhysicsBody   |
| 常见用途     | 射击、交互、视线         | 查找某类对象        |

------

## 9.4 面试推荐回答

> LineTraceByChannel 是按 Trace Channel 检测，比如 Visibility 或 WeaponTrace，它会看对象是否阻挡这个通道。LineTraceForObjects 是按对象类型检测，比如只检测 Pawn 或 PhysicsBody。简单说，ByChannel 是“用什么检测规则”，ForObjects 是“我只检测哪些对象类型”。

------

# 10. Sweep Trace 和 Line Trace 有什么区别？

## 10.1 Line Trace

Line Trace 是一条线，没有体积。

适合精确检测：

```text
射击
视线
点击
交互
```

------

## 10.2 Sweep Trace

Sweep 是用一个形状沿路径扫描。

常见有：

```text
Sphere Trace
Box Trace
Capsule Trace
```

它们是有体积的检测。

例如：

```text
Sphere Trace：用一个球从 Start 扫到 End
Box Trace：用一个盒子从 Start 扫到 End
Capsule Trace：用一个胶囊从 Start 扫到 End
```

------

## 10.3 适合场景

### Sphere Trace

适合：

```text
近战攻击范围
技能球形检测
宽容度更高的交互检测
爆炸范围检测
```

### Box Trace

适合：

```text
刀剑横扫
矩形区域检测
陷阱区域检测
```

### Capsule Trace

适合：

```text
角色体型检测
冲撞检测
沿角色高度扫描
```

------

## 10.4 对比总结

| 对比       | Line Trace | Sweep Trace            |
| ---------- | ---------- | ---------------------- |
| 是否有体积 | 没有       | 有                     |
| 精确度     | 精确线段   | 范围更宽               |
| 常见用途   | 射击、视线 | 近战、技能、范围检测   |
| 类型       | Line       | Sphere / Box / Capsule |

------

## 10.5 面试推荐回答

> Line Trace 是一条没有体积的射线，适合射击、交互、视线检测。Sweep Trace 是用球、盒子或胶囊等形状沿路径扫描，有体积，适合近战攻击、技能范围、冲撞检测等需要一定范围的检测。

------

# 11. Multi Trace 和 Single Trace 的区别

## 11.1 Single Trace

Single Trace 只返回一个命中结果，通常是第一个阻挡命中的对象。

例如：

```text
LineTraceSingleByChannel
```

适合：

```text
射击只命中第一个目标
交互只选中最近对象
摄像机遮挡检测
```

------

## 11.2 Multi Trace

Multi Trace 返回路径上的多个命中结果。

例如：

```text
LineTraceMultiByChannel
```

适合：

```text
穿透射击
激光命中多个敌人
范围扫描
调试检测所有碰到的对象
```

------

## 11.3 面试推荐回答

> Single Trace 通常只返回一个命中结果，适合普通射击、交互检测；Multi Trace 会返回多个命中结果，适合穿透攻击、激光命中多个目标或需要检测路径上多个对象的情况。

------

# 12. 如何忽略自己？

做射线检测时，经常需要忽略发起者自己。

例如玩家射击：

```text
射线从摄像机发出
不应该命中自己角色
```

蓝图中一般有：

```text
Actors to Ignore
Ignore Self
```

C++ 中常见：

```cpp
FCollisionQueryParams Params;
Params.AddIgnoredActor(this);
```

如果是武器发出的检测，也可以忽略 Owner：

```cpp
Params.AddIgnoredActor(GetOwner());
```

示例：

```cpp
FHitResult Hit;
FCollisionQueryParams Params;
Params.AddIgnoredActor(this);

bool bHit = GetWorld()->LineTraceSingleByChannel(
    Hit,
    Start,
    End,
    ECC_Visibility,
    Params
);
```

面试推荐回答：

> 可以在 Trace 参数中添加忽略对象。蓝图里可以用 Actors to Ignore 或 Ignore Self，C++ 中可以用 FCollisionQueryParams::AddIgnoredActor(this) 或 AddIgnoredActor(GetOwner())，避免射线命中自己或武器拥有者。

------

# 13. 射击命中检测怎么做？

普通即时命中武器，也就是 Hit Scan 武器，通常使用 Line Trace。

流程：

```text
玩家按下开火
    ↓
获取摄像机位置和朝向
    ↓
Start = CameraLocation
End = Start + ForwardVector * Range
    ↓
LineTraceByChannel
    ↓
如果命中敌人
        ApplyDamage
        生成命中特效
    如果命中墙体
        生成弹孔或火花
```

------

## C++ 示例

```cpp
void AMyCharacter::Fire()
{
    FVector Start = FollowCamera->GetComponentLocation();
    FVector End = Start + FollowCamera->GetForwardVector() * 10000.0f;

    FHitResult Hit;
    FCollisionQueryParams Params;
    Params.AddIgnoredActor(this);

    bool bHit = GetWorld()->LineTraceSingleByChannel(
        Hit,
        Start,
        End,
        ECC_Visibility,
        Params
    );

    if (bHit)
    {
        AActor* HitActor = Hit.GetActor();

        if (HitActor)
        {
            UGameplayStatics::ApplyDamage(
                HitActor,
                20.0f,
                GetController(),
                this,
                nullptr
            );
        }
    }
}
```

# 14. 近战攻击检测怎么做？

近战攻击通常不用普通 Line Trace 一次性检测，而是结合动画 Notify 使用：

```text
播放攻击 Montage
    ↓
Notify Begin：开启攻击检测
    ↓
攻击窗口内：
    使用 Sphere Trace / Box Trace / 武器碰撞
    ↓
命中敌人后：
    检查是否已经命中过
    ApplyDamage
    加入 HitActors
    ↓
Notify End：关闭攻击检测
```

------

## 14.1 武器碰撞方案

给武器加碰撞体：

```text
SwordCollision
```

攻击开始：

```text
Set Collision Enabled = Query Only
```

攻击结束：

```text
Set Collision Enabled = No Collision
```

命中时：

```text
OnComponentBeginOverlap
    → 判断敌人
    → 判断是否已命中
    → 造成伤害
```

优点：

```text
直观
和武器模型绑定
```

缺点：

```text
高速挥砍可能漏检
需要处理重复命中
```

------

## 14.2 Trace 方案

在武器上设置 Socket：

```text
BladeStart
BladeEnd
```

攻击窗口内每帧做 Trace：

```text
从上一帧武器位置到当前帧武器位置做 Sweep
```

优点：

```text
高速武器更不容易漏检
判定更可控
```

缺点：

```text
实现稍复杂
需要记录上一帧 Socket 位置
```

------

## 14.3 面试推荐回答

> 近战攻击通常会播放 Montage，并用 Anim Notify State 控制攻击判定窗口。判定方式可以是开启武器碰撞，也可以在攻击窗口内做 Sphere Trace 或 Box Trace。命中敌人后用 TSet 记录已命中对象，避免一次攻击重复造成伤害。Notify End 时关闭碰撞或停止检测。

# 15. 爆炸范围检测怎么做？

爆炸通常可以用：

```text
Sphere Overlap
```

流程：

```text
爆炸发生
    ↓
SphereOverlapActors
    ↓
获取半径内所有敌人
    ↓
根据距离计算伤害衰减
    ↓
ApplyDamage
```

例如：

```text
距离中心越近，伤害越高
距离越远，伤害越低
```

C++ 简化示例：

```cpp
TArray<AActor*> OverlappedActors;
TArray<TEnumAsByte<EObjectTypeQuery>> ObjectTypes;

UKismetSystemLibrary::SphereOverlapActors(
    this,
    ExplosionLocation,
    ExplosionRadius,
    ObjectTypes,
    AActor::StaticClass(),
    ActorsToIgnore,
    OverlappedActors
);
```

面试回答：

> 爆炸范围通常用 SphereOverlapActors 或 Sphere Trace 检测半径内目标，然后遍历目标，根据距离计算伤害衰减并 ApplyDamage。需要注意忽略自己、过滤目标类型，以及避免重复伤害。

```text
脚 IK

判断地面材质
```

```text
命中地面

调整脚部 IK
```

面试回答：

> 地面检测通常从角色或脚部位置向下做 Line Trace，命中后可以获取地面位置、法线和物理材质。常用于判断是否接地、脚 IK、放置物体或检测落点。

```text
Impact Point
```

```text
让弹孔贴在墙面

判断坡度
```

# 18. 碰撞调试方法

面试中如果问“碰撞检测不到怎么办”，可以按这个顺序排查：

```text
1. Collision Enabled 是否开启
2. Object Type 是否正确
3. 对目标 Channel 的 Response 是否正确
4. Generate Overlap Events 是否开启
5. 是否使用了正确的 Trace Channel
6. 是否被 Actors to Ignore 忽略了
7. 组件是否真的有碰撞体
8. 复杂碰撞 / 简单碰撞是否正确
9. 是否在正确端执行，服务器还是客户端
10. 使用 Draw Debug 查看射线位置
```

------

## 18.1 Draw Debug

Line Trace、Sphere Trace 通常可以开启调试绘制：

```text
Draw Debug Type = For Duration
```

这样可以看到：

```text
射线从哪里发出
射到哪里
有没有命中
命中位置在哪里
```

C++ 里也可以：

```cpp
DrawDebugLine(
    GetWorld(),
    Start,
    End,
    FColor::Red,
    false,
    2.0f
);
```

# 19. 常见 Bug：Overlap 不触发的原因

如果 Overlap 不触发，常见原因：

```text
1. Collision Enabled 不是 Query Only 或 Query and Physics
2. 双方响应没有设置为 Overlap
3. Generate Overlap Events 没有开启
4. 碰撞体太小或位置不对
5. 绑定事件的组件不是实际发生碰撞的组件
6. 对象被设置成 Ignore
7. Actor 已隐藏但碰撞仍关着
8. 网络环境下事件只在服务器触发，你在客户端看不到
```

面试回答：

> Overlap 不触发时，我会检查双方 Collision Enabled 是否开启，响应是否是 Overlap，Generate Overlap Events 是否开启，碰撞体位置和大小是否正确，事件是否绑定在正确组件上，以及是否被 Ignore 或网络端执行位置不对。

# 20. 常见 Bug：Line Trace 检测不到的原因

常见原因：

```text
1. Start / End 位置不对
2. 射线长度不够
3. 使用了错误的 Trace Channel
4. 目标对象对该通道是 Ignore
5. 目标组件没有碰撞
6. 目标组件 Collision Enabled 为 No Collision
7. 被 AddIgnoredActor 忽略了
8. 命中了前面的透明物体或其他对象
9. 没开启 Draw Debug，不知道射线实际方向
```

面试回答：

> Line Trace 检测不到时，我会先打开 Draw Debug 看射线方向和长度是否正确，然后检查目标组件的 Collision Enabled、Object Type 和对 Trace Channel 的 Response 是否正确，也要确认没有被忽略对象列表过滤掉。

# 21. 面试高频题：如何实现玩家交互检测？

比如玩家按 E 开门、拾取物品。

常见做法：

```text
玩家按 E
    ↓
从摄像机位置向前 Line Trace
    ↓
如果命中对象实现了 BPI_Interactable 接口
    ↓
调用 Interact
```

流程：

```text
Start = CameraLocation
End = Start + ForwardVector * InteractDistance
LineTraceByChannel 使用 InteractTrace
HitActor 是否实现 Interact Interface
调用 Interact
```

面试推荐回答：

> 我会从摄像机或角色眼睛位置向前发一条 Line Trace，使用专门的 InteractTrace 通道。命中对象后判断它是否实现交互接口，如果实现就调用 Interact。这样门、宝箱、NPC、拾取物都可以实现同一个接口，玩家不需要 Cast 到具体类型。

子弹有两种常见方案：

适合：

```text

激光枪
瞬发武器
```

优点：

# 23. 第六部分综合面试模板

如果面试官问：“你了解 UE 的碰撞和射线检测吗？”

可以这样回答：

> UE 的碰撞系统通过 Collision Enabled、Object Channel、Trace Channel 和 Response 共同决定对象之间如何交互。常见响应有 Ignore、Overlap、Block。Ignore 表示忽略，Overlap 表示重叠但不阻挡，Block 表示阻挡并可能产生 Hit。
>
> Object Channel 表示对象自己的类型，比如 Pawn、WorldStatic、Projectile；Trace Channel 是检测用的通道，比如 Visibility、Camera 或自定义 WeaponTrace。LineTraceByChannel 是按检测通道判断对象是否阻挡，LineTraceForObjects 是按对象类型筛选目标。
>
> Line Trace 是从起点到终点发射射线，常用于射击、交互、鼠标选择和视线检测；Sphere Trace、Box Trace、Capsule Trace 是带体积的 Sweep 检测，适合近战攻击、技能范围和冲撞检测。
>
> 实现近战攻击时，我会用 Montage 的 Notify State 控制攻击判定窗口，在窗口内开启武器碰撞或做 Sphere / Box Trace，命中后用 TSet 记录已命中目标，避免重复伤害。调试碰撞问题时，我会先检查 Collision Enabled、Channel Response、Generate Overlap Events，并打开 Draw Debug 查看射线位置和方向。

------

# 24. 简短版背诵答案

面试时可以背这个版本：

> UE 碰撞响应主要有 Ignore、Overlap、Block。Ignore 是忽略，Overlap 是重叠但不阻挡，Block 是阻挡并可能触发 Hit。Object Channel 表示对象自己的类型，比如 Pawn、WorldStatic；Trace Channel 是检测用的通道，比如 Visibility、WeaponTrace。
>
> Line Trace 是从起点到终点发射射线，常用于射击、交互、视线检测。LineTraceByChannel 是按 Trace Channel 检测，LineTraceForObjects 是按 Object Type 检测。Sphere Trace、Box Trace、Capsule Trace 是带体积的检测，适合近战和范围技能。
>
> Overlap 适合触发器、拾取物、范围检测；Hit 适合阻挡碰撞，比如子弹撞墙。碰撞不生效时要检查 Collision Enabled、响应通道、Generate Overlap Events、是否忽略了目标，并用 Draw Debug 调试。
