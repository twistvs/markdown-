# UE5 原生 UI 系统与 CommonUI 面试题（50 道）

适用范围：秋招 UE5 UI 与系统开发岗位。第 1–30 题覆盖原生 UMG/Slate，第 31–50 题覆盖 CommonUI 及其与原生 UI 的协作；每题附简短参考答案。

题目优先选择常见基础与实际交互问题，不代表严格的考察概率排名。CommonUI 的输入配置、Enhanced Input 集成和平台支持可能随 UE5 版本变化，应以项目使用的版本为准。

## 一、原生 UI 架构与对象生命周期

### 1. UMG 与 Slate 有什么关系？

**参考答案：**Slate 是底层 C++ UI 框架；UMG 在其上提供 UObject 封装、蓝图和可视化编辑能力。游戏界面通常使用 UMG，底层自定义控件和编辑器工具可使用 Slate。

### 2. `UWidget`、`UUserWidget` 与 `SWidget` 分别是什么？

**参考答案：**`UWidget` 是 UMG 控件基类，`UUserWidget` 用于组合可复用界面和实现逻辑；`SWidget` 是 Slate 控件基类。前两者由 UObject 生命周期机制管理，Slate 控件通常使用共享指针管理。

### 3. `CreateWidget`、`AddToViewport` 和 `AddToPlayerScreen` 分别负责什么？

**参考答案：**`CreateWidget` 创建用户控件实例，并可关联所属玩家；它不会自动显示界面。`AddToViewport` 添加到整体游戏视口，`AddToPlayerScreen` 添加到所属本地玩家的屏幕区域，适合分屏。

### 4. `OnInitialized`、`PreConstruct` 和 `Construct` 有什么区别？

**参考答案：**`OnInitialized` 通常在运行时每个实例初始化一次；`PreConstruct` 可在编辑器预览和运行时执行，适合预览显示。`Construct` 对应底层控件构建，可能重复执行，因此事件绑定需要防重。

### 5. `RemoveFromParent` 是否会立即销毁 Widget？

**参考答案：**不会，它只从父容器或屏幕中移除控件；底层控件释放时可能触发 Destruct，但不等于 UObject 已被回收。实例若仍有可追踪强引用可继续存在，应按需清理外部绑定和定时器。

## 二、布局与屏幕适配

### 6. 为什么 UMG 中 Slot 的类型由父容器决定？

**参考答案：**Slot 保存父容器对该子控件的布局规则，例如 Canvas Slot 的锚点、Horizontal Box Slot 的填充。它描述的是父子布局关系，所以同一控件放到不同容器中会使用不同类型的 Slot。

### 7. Canvas Panel 中锚点、偏移和对齐分别有什么作用？

**参考答案：**锚点指定相对父容器的定位或拉伸基准，对齐指定控件自身的定位点。固定锚点下偏移通常表示位置与尺寸，拉伸锚点下相应偏移表示边距。

### 8. Desired Size 与实际布局尺寸有什么区别？

**参考答案：**Desired Size 是控件根据内容和布局约束计算的期望尺寸；实际尺寸由父容器分配，可能不同。刚修改内容或刚创建控件时，布局尚未完成，读取到的尺寸可能不是最新结果。

### 9. SizeBox 与 ScaleBox 分别适合解决什么问题？

**参考答案：**SizeBox 用于指定或限制布局尺寸；ScaleBox 按规则缩放子内容以适应分配空间。需要控制宽高约束时用 SizeBox，需要整体缩放或保持比例时用 ScaleBox。

### 10. DPI 缩放与 Safe Zone 分别解决什么问题？

**参考答案：**DPI 规则根据视口尺寸等因素调节 UI 显示尺度；Safe Zone 避让设备或平台要求的非安全区域。适配还应结合锚点和容器布局，不能只依赖固定像素位置。

## 三、可见性、层级与输入基础

### 11. `Visible`、`Hidden`、`Collapsed` 和两种 HitTestInvisible 有什么区别？

**参考答案：**

- `Visible`：显示并参与命中测试。
- `Hidden`：不显示，但保留布局空间；`Collapsed`：不显示，也不保留空间。
- `HitTestInvisible`：显示，但自身及子控件不参与命中测试。
- `SelfHitTestInvisible`：显示，仅自身不参与命中测试，子控件仍可交互。

### 12. 为什么界面看得见，却点不到按钮？

**参考答案：**先用 Widget Reflector 检查实际命中的控件，再检查遮挡层、Visibility、启用状态和输入模式。透明控件也可能挡住鼠标，而 `HitTestInvisible` 父控件会使整棵子树无法命中。

### 13. ZOrder 是否能统一控制所有 UI 层级？

**参考答案：**不能，ZOrder 的含义取决于所属层级，例如视口控件与 Canvas 子控件分别在各自容器内排序。不能仅靠某个子控件的 ZOrder 越过外层容器或其他屏幕层，应先检查完整层级。

### 14. Game Only、UI Only 和 Game and UI 输入模式有什么区别？

**参考答案：**Game Only 面向游戏输入，UI Only 面向 UI，Game and UI 允许 UI 优先处理，并将未处理输入交给游戏。鼠标显示、键盘焦点和映射上下文还需要按交互需求配置。

### 15. 键盘焦点与鼠标命中测试有什么区别？

**参考答案：**键盘或手柄导航通常依赖焦点，鼠标事件通常依赖光标位置下的命中路径。控件可被鼠标点击不代表可以接收键盘输入，设置焦点还需确认控件可聚焦、可见、启用且已接入界面。

## 四、事件路由与交互设计

### 16. UI 事件返回 `Handled` 与 `Unhandled` 有什么区别？

**参考答案：**`Handled` 表示已处理，通常停止该事件继续路由；`Unhandled` 允许后续处理者接收。是否继续进入游戏输入还受输入模式和具体事件路由影响，不能只凭返回值判断全部输入行为。

### 17. `OnPreviewKeyDown` 与 `OnKeyDown` 的路由方向有什么区别？

**参考答案：**Preview 阶段沿焦点路径由祖先向目标传递，KeyDown 阶段由目标向祖先冒泡。父控件提前返回 Handled 可能阻止子控件正常处理，因此预处理应只拦截确实需要的按键。

### 18. 为什么打开菜单后 WASD 仍然控制角色？

**参考答案：**检查是否仍在 Game and UI 模式、菜单是否获得焦点、按键是否未处理，以及游戏输入映射是否仍启用。按设计切换输入模式或映射上下文；暂停游戏是独立决策，不应当作唯一输入隔离方式。

### 19. 手柄导航为什么不能只依赖鼠标悬停效果？

**参考答案：**手柄导航以焦点为核心，悬停是鼠标交互状态，二者并不等价。应提供清晰的焦点样式、初始焦点和导航规则，并处理禁用、隐藏及动态增删控件后的焦点迁移。

### 20. UMG 拖拽通常如何组织？

**参考答案：**按下时请求拖拽检测，在 `OnDragDetected` 创建 `UDragDropOperation`，携带数据和拖拽表现；目标在 `OnDrop` 验证并处理数据。未成功放置时通过取消流程恢复状态，业务数据不要只靠拖拽图像保存。

## 五、数据、列表与动画

### 21. `BindWidget` 与 `BindWidgetOptional` 有什么区别？

**参考答案：**它们将 C++ 控件属性绑定到 Widget Blueprint 中名称和类型匹配的控件。`BindWidget` 要求对应控件存在，`BindWidgetOptional` 允许缺失，使用可选控件前必须检查有效性。

### 22. 为什么 UI 状态更新通常优先用事件通知，而不是 Tick 或传统属性绑定？

**参考答案：**Tick 和传统 UMG 函数绑定可能反复执行取值逻辑，成本会随界面复杂度增长。数据变化时定向更新可减少无效工作；基于 FieldNotify 的 MVVM 绑定与传统轮询式绑定应区别看待。

### 23. UI 应直接修改游戏对象，还是通过接口或 ViewModel 操作？

**参考答案：**简单局部功能可直接调用，跨系统操作通常应通过业务接口或 ViewModel 提交请求。UI 负责展示与交互，业务系统负责校验和状态修改，可减少对具体 Actor 类型的依赖。

### 24. ListView 与 ScrollBox 中手动创建所有条目有什么区别？

**参考答案：**ListView 将数据项与条目 Widget 分离，按需生成和复用条目，适合大量同类数据。条目重新绑定数据时必须刷新显示并清理旧绑定，不能把条目 Widget 当成数据项的永久身份。

### 25. UI 动画播放完成后的逻辑应该如何处理？

**参考答案：**使用动画完成回调推进关闭、切换等流程，避免依赖写死时长的 Delay。还要定义重复播放、停止和中途关闭时的处理策略，防止过期回调或重复执行。

## 六、原生 UI 性能与特殊场景

### 26. Invalidation 的作用是什么？

**参考答案：**它缓存可复用的布局和绘制结果，在控件未发生相关变化时避免重复计算。频繁改变结构、布局或将控件设为 Volatile 会降低收益，应结合实际失效原因评估；全局失效模式的行为需按版本确认。

### 27. Retainer Box 与 Invalidation 有什么区别？

**参考答案：**Retainer Box 将子树渲染到纹理，可控制刷新频率并应用效果材质；Invalidation 主要复用布局与绘制数据。Retainer Box 会增加渲染目标和合成成本，降低刷新率还可能产生视觉滞后，不应无差别使用。

### 28. 为什么 UI 不应在任意后台线程直接更新？

**参考答案：**常规 UMG 和大多数 UObject 操作要求在游戏线程执行，不具备任意并发访问保证。后台线程只处理独立数据，再将结果派发到游戏线程，并检查控件生命周期和请求有效性。

### 29. Widget Component 与 Widget Interaction Component 分别负责什么？

**参考答案：**Widget Component 将 UMG 界面呈现在世界空间或屏幕空间；Widget Interaction Component 通过指针模拟等方式与控件交互。世界空间界面的检测还受组件碰撞、Trace 设置和交互距离影响。

### 30. 如何定位一个复杂 UMG 界面的卡顿？

**参考答案：**先区分游戏线程、渲染线程和 GPU 瓶颈，再用 Insights 查看耗时，用 Widget Reflector 检查层级与命中路径。重点检查高频绑定、Tick、列表全量重建、布局失效、同步加载和透明层过度绘制，以测量结果决定优化。

## 七、CommonUI 架构基础

### 31. CommonUI 相比原生 UMG 增加了什么能力？

**参考答案：**它在 UMG/Slate 基础上提供可激活界面、输入路由、跨输入设备表现和统一控件样式等能力。它适合组织复杂菜单交互，但不替代底层布局系统，也不自动实现项目业务逻辑。

### 32. `UCommonUserWidget` 与 `UCommonActivatableWidget` 有什么区别？

**参考答案：**`UCommonUserWidget` 提供 CommonUI 用户控件基础能力；`UCommonActivatableWidget` 进一步提供激活、停用及相关输入和焦点管理。完整页面或弹窗常用后者，普通可复用子控件不必都有激活生命周期。

### 33. CommonUI 的激活、停用与 UMG 的 Construct、Destruct 有什么区别？

**参考答案：**激活和停用表示界面参与交互的状态变化，可以在同一实例上多次发生；Construct 和 Destruct 对应底层控件构建与释放。当前页面相关的订阅通常在激活时建立、停用时解除，一次性初始化放在合适的初始化阶段。

### 34. 停用 ActivatableWidget 是否等于隐藏或销毁它？

**参考答案：**不等于，停用主要改变激活状态及输入参与情况；可见性取决于控件的激活可见性设置或容器管理。实例是否被移除、缓存或回收也由容器和外部引用决定。

### 35. 接入 CommonUI 时，为什么需要关注 GameViewportClient？

**参考答案：**CommonUI 的输入路由通常通过 `UCommonGameViewportClient` 或其派生类接入视口。启用插件后还需确认项目的视口类和相关输入设置正确，否则控件显示正常也可能无法按预期路由动作。

## 八、界面容器与返回流程

### 36. `UCommonActivatableWidgetStack` 适合什么场景？

**参考答案：**它适合按后进先出方式组织菜单和弹窗，顶层页面成为当前活动界面；按栈流程移除或停用顶层页面后可恢复下层。底层实例、转场与复用由容器管理，不应把入栈简单理解为全部实例持续激活。

### 37. ActivatableWidgetStack 与 ActivatableWidgetQueue 有什么区别？

**参考答案：**Stack 按后进先出组织，适合页面深入和返回；Queue 按先进入先展示的顺序组织，适合排队通知或连续提示。应根据交互顺序选择，而不是只看显示层级。

### 38. 如何用 CommonUI 组织 HUD、菜单和模态弹窗？

**参考答案：**按职责划分 UI 层，通常让交互页面和弹窗由相应容器管理，再明确层间的输入与焦点优先级。具体层名、标签和布局是项目架构，不能把示例项目的分层约定当作 CommonUI 强制规则。

### 39. CommonUI 的返回操作通常如何处理？

**参考答案：**让活动页面注册或启用返回处理，优先响应当前可处理返回的界面。页面可以先关闭局部状态或弹出确认，也可以停用自身并交由容器恢复下层；只有需要阻止后续处理时才消费返回。

### 40. 页面有未保存修改时，如何设计返回确认？

**参考答案：**拦截当前页面的返回并打开确认弹窗，保留原页面状态。确认后执行保存或丢弃再关闭原页面，取消则恢复其焦点；同时防止连续返回造成重复弹窗或误关下层。

## 九、CommonUI 输入与焦点

### 41. CommonUI Action Router 的职责是什么？

**参考答案：**它根据可激活控件形成的路由结构、输入配置和动作绑定，将 UI 输入送到合适的处理者。它协调界面交互，但不会代替游戏业务校验，也不能假设每次按键都只由简单的“栈顶”规则处理。

### 42. CommonUI 的输入配置与手动设置 PlayerController 输入模式如何协作？

**参考答案：**可激活页面可通过期望输入配置声明游戏或菜单输入需求，由路由系统应用。若页面同时手动设置输入模式，可能与激活、返回后的自动恢复相冲突，应明确统一的配置来源及恢复策略。

### 43. CommonUI 与 Enhanced Input 分别负责什么？

**参考答案：**CommonUI 负责 UI 层级、动作路由与设备相关表现；Enhanced Input 负责 Action、映射、触发器和输入值处理。二者可按版本支持集成，但游戏映射上下文与 UI 路由仍需分别检查，不能认为启用一个就自动隔离全部游戏输入。

### 44. `GetDesiredFocusTarget` 的用途是什么？

**参考答案：**它为可激活页面提供期望焦点目标，C++ 通常重写对应的 Native 实现。目标应可聚焦、可见且启用；异步生成列表时，还需在条目就绪后正确设置或恢复焦点。

### 45. 如何排查 CommonUI 中“按钮点击正常，但手柄确认无效”？

**参考答案：**检查活动页面、当前焦点、按钮可聚焦和启用状态，再检查确认动作绑定、设备映射及 Action Router 接入。鼠标命中不依赖同一套焦点条件，因此点击正常不能证明手柄路由正确。

## 十、CommonUI 控件、设备与实战

### 46. `UCommonButtonBase` 相比普通 UMG Button 有什么优势？

**参考答案：**它提供统一的按钮状态、样式、选择行为及输入动作相关能力，适合跨设备菜单。选择状态、键盘焦点和鼠标悬停仍是不同概念，应分别设计视觉反馈。

### 47. CommonUI 的样式类如何帮助维护 UI？

**参考答案：**`UCommonButtonStyle`、`UCommonTextStyle` 等将常用外观集中配置，减少控件逐个维护颜色、字体和状态样式的成本。业务逻辑仍应与样式分离，局部特例也要避免破坏整体一致性。

### 48. `UCommonInputSubsystem` 与 `UCommonActionWidget` 分别负责什么？

**参考答案：**CommonInputSubsystem 按本地玩家跟踪输入设备类型等状态；CommonActionWidget 展示动作对应的按键或图标。正确的平台、手柄类型和动作数据配置能让提示随设备切换，而无需硬编码键盘图标。

### 49. `UCommonBoundActionBar` 为什么比固定的底部操作提示更易维护？

**参考答案：**它根据路由系统中符合显示条件的动作绑定生成操作提示，可随活动界面和输入设备变化更新。提示能否出现还取决于动作绑定、显示设置和图标配置，不是注册任何动作都会自动显示。

### 50. CommonUI 页面停用后仍收到数据回调，应如何处理？

**参考答案：**区分实例存活与页面激活：停用不会自动解除所有业务委托。仅服务于当前展示的订阅在停用时解绑，需要跨停用保留的订阅则检查激活状态或只更新数据；异步结果还需验证弱引用和请求是否过期。
