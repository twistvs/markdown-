#### 反射到底是啥

只有宏声明才能让某一部分代码参与反射，**反射的作用只是生成一大堆可以供别人调用的信息**（比如这个类叫啥，父类是啥）

```
你编写的头文件
      ↓
UBT 安排构建，并在需要时调用 UHT
      ↓
UHT 解析 UCLASS、UPROPERTY、UFUNCTION 等声明
      ↓
生成 .generated.h 和 .gen.cpp 等代码
      ↓
C++ 编译器编译你的代码及生成代码
      ↓
链接成模块
      ↓
模块初始化及相关注册机制建立运行时反射信息
```

反射系统不仅保存描述，**还提供操作能力**，例如：

- 查询对象所属类型。
- 判断继承关系。
- 查找或遍历属性。
- 查找函数。
- 按属性描述访问值。
- 分发反射函数调用。

例如：

​	==很明显，我们在写代码的时候，并没有在Object的类里面写GetClass等等函数，但是这些函数又确实可以调用，这些就是反射系统生成的信息==

```c++
Object->GetClass();             // 查询实际类型
Object->IsA<UMyObject>();       // 判断是否属于该类型或其派生类型
Object->FindFunction(Name);     // 查找反射函数
```

UE 的 `Cast<T>()` 也利用对象类型体系完成受检查的类型转换。

#### 别的系统会使用反射生成的信息

**GC、蓝图、序列化属于什么关系？**

它们是**使用反射信息的系统**，各自还包含独立的实现，==不能把它们全部等同于反射系统。==

| 系统     | 如何利用反射                                 |
| -------- | -------------------------------------------- |
| GC       | 根据属性和引用扫描描述，追踪 UObject 引用    |
| 序列化   | 根据属性类型和标志，保存、恢复数据           |
| 编辑器   | 根据属性描述和元数据，生成属性面板           |
| 蓝图     | 利用类型、属性和函数信息进行检查、访问和调用 |
| 网络复制 | 利用反射声明及复制布局等机制处理属性和 RPC   |

例如，反射提供“这是一个对象引用属性”的信息；GC 在此基础上判断引用关系和可达性。**反射本身并不负责完成整个垃圾回收算法。**

整体关系是：

```
声明与代码生成
      ↓
类型描述、属性描述、函数描述、标志及元数据
      ↓
查询、访问、调用接口
      ↓
GC、编辑器、蓝图、序列化、网络复制等系统使用
```

#### 垃圾回收只是使用反射信息的系统之一

***==UObject是对象是否自动受GC控制的唯一标准==***

如果一个对象他不是UObject，那么只有手动将他加入到GC中，他才会受GC的控制

***==反射提供了垃圾回收需要的引用信息，如果没有这些信息，GC无法找到UObject==***

UCLASS()让这个类产生了反射信息，UPROPERTY让这个成员产生了反射信息，所以GC可以通过这条引用链发现IconMaterial

```c++
UCLASS()
class UMyObject : public UObject{

 GENERATED_BODY()

private:

 UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "AbilityInfo")
 UMaterialInstance* IconMaterial;

public:

}
```
