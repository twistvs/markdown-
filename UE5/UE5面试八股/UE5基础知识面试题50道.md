# UE5 基础知识面试题（50 道）

适用范围：秋招 UE5 开发岗位的基础知识复习，结合 UI 交互、CommonUI、MVVM 与 Mass 项目背景。按知识主题分组，不代表严格的考察概率排名。

每题附简短参考答案，供快速回忆和口头表达；插件功能和平台支持以项目使用的 UE5 版本为准。

## 一、引擎结构与 C++ 基础

### 1. UE 的模块与插件有什么区别？`Build.cs` 和 `Target.cs` 各负责什么？

**参考答案：**模块是代码编译与依赖组织单元，插件是可包含模块、资源和配置的功能包。`Build.cs` 描述模块依赖与编译规则；`Target.cs` 描述构建目标及其设置，使用其他模块的接口时需要声明相应依赖。

### 2. `UObject`、`AActor` 和 `UActorComponent` 有什么区别？

**参考答案：**`UObject` 是支持反射与垃圾回收的对象基类；`AActor` 是可放入 World 的对象；`UActorComponent` 是依附 Actor 的可复用功能单元。数据对象通常用 UObject，场景实体用 Actor，复用功能用组件。

### 3. UE 反射系统有什么作用？反射宏与 UHT 如何参与其中？

**参考答案：**反射提供运行时类型和成员信息，支撑编辑器、序列化、蓝图和 GC 等机制。`UCLASS/USTRUCT/UENUM` 标记类型，`UPROPERTY/UFUNCTION` 标记属性与函数；UHT 解析这些声明并生成辅助代码，再由 C++ 编译器编译。

### 4. `FString`、`FName` 和 `FText` 有什么区别？

**参考答案：**`FString` 用于可操作的字符串；`FName` 用于名称标识和高效比较；`FText` 支持本地化，适合面向用户的 UI 文本。

### 5. `TArray`、`TMap` 和 `TSet` 各适合什么场景？增删元素时要注意什么？

**参考答案：**`TArray` 存储有序序列，`TMap` 存储键值映射，`TSet` 存储不重复元素。增删可能使迭代器、索引或元素引用失效，尤其 TArray 扩容和元素移动后不能继续使用旧地址；遍历中删除应采用容器支持的安全方式。

## 二、对象创建、生命周期与内存管理

### 6. `NewObject`、`SpawnActor` 和 `CreateDefaultSubobject` 有什么区别？

**参考答案：**`NewObject` 创建运行时 UObject，`World->SpawnActor` 创建并接入世界的 Actor，`CreateDefaultSubobject` 在构造函数中创建默认子对象。普通 `new` 不会完成 UObject 所需的引擎注册和初始化流程。

### 7. Actor 生命周期中的构造、`OnConstruction`、`BeginPlay`、`Tick` 和 `EndPlay` 分别适合做什么？

**参考答案：**构造函数设置默认值和默认子对象；`OnConstruction` 根据实例属性构建或更新实例，编辑器中可重复执行。`BeginPlay` 初始化游戏逻辑，启用的 Tick 执行逐帧逻辑，`EndPlay` 清理退出时的运行资源；加载与生成路径的前置步骤有所不同。

### 8. 什么是 CDO？为什么构造函数不适合依赖运行时世界状态？

**参考答案：**CDO 是每个 UObject 类的默认对象，保存该类的默认属性。构造函数也会用于创建 CDO，此时不保证有有效的游戏世界或其他运行时对象，因此世界相关初始化通常放到合适的运行时生命周期回调中。

### 9. UE GC 如何判断对象可达？为什么普通裸指针不能阻止回收？

**参考答案：**GC 从根集合出发，沿可追踪的强引用查找可达对象。可达 UObject 中的 `UPROPERTY` 强对象引用可被追踪，普通未登记裸指针不能；强引用也不能阻止 Actor 被显式 `Destroy`。

### 10. `TObjectPtr`、`TWeakObjectPtr`、`TSoftObjectPtr` 和 `TSharedPtr` 有什么区别？

**参考答案：**

- `TObjectPtr`：UObject 引用包装，作为 `UPROPERTY` 等可追踪强引用使用时参与 GC 保活。
- `TWeakObjectPtr`：不保活 UObject，使用前调用 `IsValid()` 或检查 `Get()`。
- `TSoftObjectPtr`：通过路径引用对象，不自动加载或保活资源。
- `TSharedPtr`：通过引用计数管理普通 C++ 对象，不用于管理 UObject 生命周期。

## 三、Actor、组件与空间变换

### 11. RootComponent 有什么作用？三类常见组件有什么区别？

**参考答案：**RootComponent 是 Actor 的根场景组件，决定 Actor 的空间变换。`UActorComponent` 提供功能但没有自身场景变换；`USceneComponent` 增加变换和附着能力；`UPrimitiveComponent` 在此基础上提供几何表示及渲染、碰撞等能力。

### 12. 世界变换与相对变换有什么区别？附着时如何选择保持方式？

**参考答案：**世界变换相对于世界，相对变换相对于父组件，子组件的世界变换由父变换与相对变换组合得到。`KeepRelativeTransform` 保留相对值；`KeepWorldTransform` 保留当前世界变换，并重新计算相对值。

### 13. `FVector`、`FRotator`、`FQuat` 和 `FTransform` 分别表示什么？

**参考答案：**`FVector` 表示三维向量，`FRotator` 以角度表示 Pitch、Yaw、Roll，`FQuat` 用四元数表示旋转，`FTransform` 包含平移、旋转和缩放。Rotator 便于编辑，四元数适合旋转组合和球面插值，避免直接线性插值欧拉角带来的跨角度问题。

### 14. Actor Tick 与 Component Tick 如何组织？什么时候可以不用 Tick？

**参考答案：**Actor 与组件有独立的 Tick 设置；Tick Group 控制执行阶段，Tick Prerequisite 控制先后依赖。只需响应状态变化时使用事件，低频周期任务使用 Timer，避免无意义的逐帧轮询。

### 15. `Destroy`、隐藏 Actor 和禁用碰撞有什么区别？

**参考答案：**`Destroy` 使 Actor 退出正常生命周期，内存由后续 GC 处理，不能再按正常存活对象使用。隐藏主要影响显示，禁用碰撞主要影响碰撞交互，二者都不等于销毁或关闭 Tick；退出时应按需解绑外部事件并清理 Timer。

## 四、Gameplay Framework

### 16. GameMode 与 GameState 的职责和网络分布有什么区别？

**参考答案：**GameMode 管理规则、登录和生成等逻辑，在多人游戏中只存在于服务器。GameState 保存需要共享的游戏状态并复制到客户端，因此客户端 UI 通常读取 GameState，而不是 GameMode。

### 17. PlayerController、Pawn 和 Character 有什么区别？`Possess` 表示什么？

**参考答案：**PlayerController 表示玩家控制者，Pawn 表示可被控制的实体，Character 是带胶囊体、骨骼网格和角色移动组件的 Pawn 子类。`Possess/UnPossess` 建立或解除控制关系，切换 Pawn 通常不需要更换 PlayerController。

### 18. PlayerState 与 PlayerController 分别适合保存什么信息？

**参考答案：**PlayerState 适合玩家名称、分数等需向其他客户端共享的信息；PlayerController 适合控制逻辑及仅所属玩家需要的信息。远端玩家的 PlayerController 通常不在其他客户端存在，因此查看他人状态通常读取 PlayerState。

### 19. GameInstance 的生命周期与用途是什么？

**参考答案：**GameInstance 通常随游戏实例存在，跨普通地图切换保留，适合会话和跨地图数据；它本身不自动网络复制。World 和关卡 Actor 可能随切图销毁，长期保存它们的引用需要及时清理或验证有效性。

### 20. GameInstance、World 和 LocalPlayer Subsystem 有什么区别？

**参考答案：**Subsystem 是随所属对象自动管理生命周期的模块化服务。GameInstanceSubsystem 适合跨地图服务，WorldSubsystem 适合每个世界的管理功能，LocalPlayerSubsystem 适合每个本地玩家的输入、UI 等服务。

## 五、蓝图、事件与输入

### 21. C++ 与蓝图通常如何分工？

**参考答案：**C++ 常负责核心系统、公共接口和性能敏感逻辑；蓝图常负责内容配置、表现和快速迭代。通过稳定接口协作，并依据实际性能分析决定是否将蓝图逻辑迁到 C++。

### 22. 四种常见的蓝图函数声明有什么区别？

**参考答案：**

- `BlueprintCallable`：允许蓝图调用。
- `BlueprintPure`：无执行引脚，按无副作用的查询设计，不保证结果缓存。
- `BlueprintImplementableEvent`：由蓝图提供实现。
- `BlueprintNativeEvent`：C++ 可通过 `_Implementation` 提供默认实现，蓝图可重写。

### 23. 单播、多播和动态委托有什么区别？绑定时如何处理生命周期？

**参考答案：**单播绑定一个回调，多播绑定多个；动态委托利用反射，支持序列化及相应的蓝图交互，但有额外开销。优先使用合适的 UObject 或弱引用绑定，按需保存句柄解绑，避免普通 Lambda 捕获已失效对象。

### 24. 接口、直接引用和事件分发器分别适合什么通信？

**参考答案：**直接引用适合明确且紧密的对象关系；接口适合对不同实现发出统一请求；事件分发器适合一对多通知。UI 可通过接口或 ViewModel 获取数据，通过事件响应变化，减少对具体 Actor 类型的依赖。

### 25. Enhanced Input 的 Action、Mapping Context、Trigger 和 Modifier 分别负责什么？

**参考答案：**Action 表示操作语义，Mapping Context 定义按键到 Action 的映射及上下文；Trigger 决定触发条件，Modifier 变换输入值。切换菜单时可增删上下文或调整优先级，并配合焦点和输入模式管理。

## 六、UI 与交互基础

### 26. UMG 与 Slate 是什么关系？什么时候使用它们？

**参考答案：**Slate 是底层 UI 框架，UMG 提供基于 UObject、蓝图和可视化编辑器的 UI 封装，`UUserWidget` 用于组织可复用用户界面。常规游戏 UI 优先用 UMG，复杂底层控件或编辑器工具可使用 Slate。

### 27. `OnInitialized`、`PreConstruct`、`Construct` 和 `Destruct` 有什么区别？

**参考答案：**`OnInitialized` 通常在运行时每个 Widget 实例初始化一次；`PreConstruct` 可在编辑器预览和运行时执行。`Construct/Destruct` 对应底层界面构建和释放，可能重复发生，且 Destruct 不等于 UObject 被 GC，因此绑定需防重并适时解绑。

### 28. 锚点、对齐、Slot 和 DPI 缩放如何影响布局？

**参考答案：**Canvas 锚点确定相对父容器的定位基准，对齐确定自身定位点；Slot 保存父容器特定的布局规则，DPI 缩放调节整体显示尺度。使用合理锚点、容器布局和 DPI 规则适配不同屏幕，减少对固定坐标的依赖。

### 29. 输入模式、焦点和命中测试如何影响 UI 交互？

**参考答案：**Game Only 面向游戏输入，UI Only 面向 UI，Game and UI 允许 UI 优先处理并把未处理输入交给游戏。键盘操作依赖焦点，鼠标操作依赖命中测试；菜单中角色仍响应时，应检查输入模式、事件是否已处理及游戏输入映射。

### 30. CommonUI 与 MVVM 在 UI 架构中分别负责什么？

**参考答案：**CommonUI 组织可激活界面、界面栈及输入和返回行为；MVVM 将 View 的显示与 ViewModel 的展示数据、操作接口分开，业务数据由底层系统维护。采用字段变化通知驱动绑定可减少每帧轮询，也便于维护。

## 七、资源、关卡与数据组织

### 31. 硬引用与软引用如何影响资源加载？

**参考答案：**硬引用通常使被引用资源随引用方加载，形成传递依赖；软引用保存路径，需要显式加载，不自动保活。UI 蓝图若硬引用重型类或资源，可能沿依赖链带入大量资源，应检查引用关系并合理使用软引用。

### 32. 同步加载与异步加载有什么区别？请求方关闭后如何处理异步结果？

**参考答案：**同步加载阻塞调用线程，大资源在游戏线程加载可能造成卡顿；异步加载允许等待期间继续执行其他工作。回调中应检查请求方弱引用和当前请求状态，界面关闭时可取消请求或忽略结果，避免更新失效或过期界面。

### 33. DataAsset 与 DataTable 各适合什么配置？

**参考答案：**DataAsset 适合对象式、类型化且结构灵活的配置，DataTable 适合统一行结构的批量表格数据。共享配置通常作为只读模板，运行时状态单独存储，避免多个实例互相污染。

### 34. 关卡切换、关卡流送和 World Partition 有什么区别？

**参考答案：**关卡切换进入另一地图；关卡流送在当前世界中按需加载或卸载子关卡；World Partition 将世界划分为可按需加载的单元。卸载可能使 Actor 退出或销毁，外部引用应验证有效性，持久数据应放在合适的长期对象中。

### 35. Gameplay Tags 相比字符串和枚举有什么特点？如何匹配层级？

**参考答案：**Gameplay Tags 提供统一注册的层级标签和容器查询，适合可组合的状态与分类。精确匹配只认同一标签；层级匹配中，持有 `State.Combat.Attacking` 可匹配父标签 `State.Combat`，反向不成立。

## 八、碰撞、物理与动画

### 36. Block、Overlap、Ignore 及碰撞通道分别表示什么？

**参考答案：**Block 阻挡，Overlap 允许重叠并在满足事件条件时通知，Ignore 忽略交互。Object Channel 分类对象，Trace Channel 分类查询，Collision Profile 封装配置；对象交互综合双方响应，通常 Ignore 优先、Overlap 次之，双方 Block 才阻挡，并受碰撞启用模式限制。

### 37. Overlap、Hit 事件和主动 Trace 查询有什么区别？

**参考答案：**Overlap 通知重叠关系变化，Hit 通知满足条件的阻挡碰撞，Trace 主动查询空间中的碰撞对象。精确指向交互用射线，带检测宽度用形状扫描，区域进入退出用重叠事件，并正确配置响应和事件开关。

### 38. Static Mesh 与 Skeletal Mesh 有什么区别？

**参考答案：**Static Mesh 不通过骨骼蒙皮变形，但仍可整体移动；Skeletal Mesh 通过骨骼和蒙皮权重驱动顶点变形。动画序列提供随时间变化的骨骼姿态，适合需要关节动作的角色。

### 39. 动画蓝图、状态机、Blend Space 和 Montage 分别解决什么问题？

**参考答案：**动画蓝图计算最终动画姿态；状态机管理状态切换，Blend Space 根据速度等参数混合动画，Montage 组织可触发的动作片段。常用状态机和 Blend Space 驱动待机、移动，通过 Slot 和 Montage 播放攻击等动作。

### 40. CharacterMovementComponent 与直接修改位置有什么区别？

**参考答案：**CharacterMovementComponent 处理行走、跳跃、地面检测、碰撞移动及网络预测等；`AddMovementInput` 提供输入，再由移动逻辑消费。直接改位置绕过正常移动流程，可能影响碰撞和联网表现；模拟物理的组件通常应由力、冲量等物理方式驱动。

## 九、网络与数据架构基础

### 41. 服务器权威、本地控制和网络角色有什么区别？

**参考答案：**服务器权威表示服务器负责共享游戏状态的最终判定；本地控制表示当前机器控制该 Pawn 或 Controller。网络角色区分 Authority、AutonomousProxy 和 SimulatedProxy 等职责，客户端本地控制的联网 Pawn 通常是 AutonomousProxy；`HasAuthority()` 判断 Actor 角色，不能简单替代服务器进程判断。

### 42. 属性复制与 RPC 有什么区别？`ReplicatedUsing` 有什么作用？

**参考答案：**属性复制用于同步服务器状态，不保证中间每次变化都送达；RPC 用于远程调用函数。`Replicated` 标记属性参与复制，`ReplicatedUsing` 指定接收更新时的 RepNotify 回调；客户端本地改值不会自动反向同步，且仍需配置 Actor 复制和属性登记。

### 43. Server、Client 和 NetMulticast RPC 如何使用？Reliable 是否适合每帧发送？

**参考答案：**Server RPC 向服务器发送请求，客户端调用通常要求 Actor 属于该连接；服务器调用 Client RPC 发给所属客户端。服务器调用 NetMulticast 在服务器及相关客户端执行，客户端调用仅本地执行；Reliable 适合关键低频调用，高频使用可能造成可靠队列积压。

### 44. 多人游戏中，玩家点击 UI 按钮后应如何更新共享状态？

**参考答案：**本地 UI 通过所属 Controller 等对象发起 Server RPC，服务器校验并修改权威数据，再通过属性复制和 OnRep 等通知客户端。客户端更新 ViewModel 或 UI 展示，使表现反映服务器确认后的状态。

### 45. Mass 中 Entity、Fragment 和 Processor 分别是什么？与 Actor 架构有什么区别？

**参考答案：**Entity 是实体标识，Fragment 保存数据，Processor 按查询批量处理实体；Mass 按数据组合组织存储与处理，适合大量实体。为每个实体创建完整 Actor 或 UI 会增加对象和更新成本，应按表现需求、可见性及交互需求选择性创建。

## 十、渲染、性能与调试

### 46. Nanite 与 Lumen 分别解决什么问题？

**参考答案：**Nanite 提供虚拟化几何与自动细节管理，支持高几何复杂度内容；Lumen 提供动态全局光照和反射。二者仍受材质、场景、平台和版本支持影响，需要评估实际 CPU、GPU 与显存预算。

### 47. 游戏线程、渲染线程和 GPU 如何分工？如何初步判断性能瓶颈？

**参考答案：**游戏线程更新游戏逻辑，渲染线程组织渲染工作，GPU 执行绘制与计算，部分提交工作由 RHI 线程承担。`stat unit` 比较 Game、Draw、GPU 等耗时，`stat gpu` 查看 GPU 各阶段成本；结合帧率限制和分析工具确认瓶颈。

### 48. 后台线程如何安全地把计算结果交给 UObject 或 UI？

**参考答案：**大多数 UObject、Actor 和 UMG 操作要求在游戏线程执行，只有明确支持线程安全的接口可例外。后台线程处理独立数据，完成后通过 `AsyncTask(ENamedThreads::GameThread, ...)` 等方式回到游戏线程，并检查弱引用及结果是否仍有效。

### 49. 如何定位 UI 卡顿？Insights、stat 和 Widget Reflector 各能提供什么？

**参考答案：**先稳定复现并区分逻辑、渲染与加载瓶颈：Insights 查看线程、耗时调用及相应加载轨迹，stat 查看实时耗时，Widget Reflector 检查控件层级、布局与命中测试。结合 Slate/UMG 分析数据，确认 Tick、布局失效、绘制或同步加载的成本，再针对性优化。

### 50. PIE、Standalone 和打包运行有什么区别？打包后异常如何排查？

**参考答案：**PIE 在编辑器测试环境运行；Standalone 独立运行游戏，具体进程方式由启动设置决定；打包运行使用构建和 Cook 后的内容，更接近发布环境。Development 便于调试分析，Shipping 面向发布并默认收紧部分调试功能；异常时先看日志或崩溃栈，再检查 Cook 资源、路径和对编辑器模块的依赖。
