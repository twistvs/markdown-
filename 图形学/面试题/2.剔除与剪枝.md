在**光栅化渲染管线**中，为了避免把不可见或贡献很小的东西送到后续阶段，会发生很多“剔除 / 剪枝”操作。它们分布在 **CPU 场景管理、GPU 几何处理、光栅化、片元测试**等阶段。

可以按管线顺序理解：

```text
场景/对象级剔除
↓
顶点处理
↓
裁剪与背面剔除
↓
光栅化
↓
片元级测试
↓
混合与写入帧缓冲
```

------

# 1. 对象级剔除：不把不可见物体送进 GPU

这类剔除通常发生在 **CPU 端或 GPU Driven 渲染前处理阶段**。

## 1.1 视锥体剔除 Frustum Culling

摄像机只能看到视锥体内的物体。

如果一个物体的包围盒完全在视锥体外，就不需要绘制。

```text
物体在摄像机视野外
→ 不提交 Draw Call
→ 不执行顶点着色器
→ 不进入光栅化
```

通常使用：

```text
AABB
OBB
Bounding Sphere
Bounding Box
```

判断物体是否和视锥体相交。

例如：

```text
摄像机看向前方
身后的建筑、角色、树木
→ 直接剔除
```

这是最基础、收益很高的剔除。

------

## 1.2 遮挡剔除 Occlusion Culling

有些物体虽然在视锥体内，但被其他物体完全挡住。

例如：

```text
建筑后面的汽车
山体后面的敌人
墙后面的家具
```

这些物体对最终画面没有贡献，可以剔除。

常见方法包括：

```text
硬件 Occlusion Query
Hi-Z Buffer
Software Rasterizer
Portal / Room System
预计算可见性 PVS
```

在开放世界或室内场景中，遮挡剔除非常重要。

------

## 1.3 距离剔除 Distance Culling

物体距离摄像机太远时，可能小到不可见，或者不值得渲染。

例如：

```text
超过 500 米的小石头
超过 1000 米的小草
超过 2000 米的小道具
```

可以直接不绘制。

```text
距离超过阈值
→ Cull
```

常见于：

```text
植被
粒子
小道具
装饰物
远处 NPC
```

LOD 的最后一级通常就是 **Cull**。

------

## 1.4 屏幕尺寸剔除 Small Object Culling

有些物体虽然不远，但在屏幕上投影面积很小。

例如一个螺丝钉在屏幕上只占 1 个像素，继续渲染意义不大。

可以根据屏幕占比判断：

```text
屏幕面积 < 阈值
→ 剔除
```

这比单纯按距离更合理，因为物体大小、FOV、分辨率都会影响可见程度。

------

## 1.5 Portal / Cell 剔除

常用于室内、地下城、建筑内部场景。

场景被划分成房间 Cell，房间之间通过门、窗、走廊 Portal 连接。

```text
摄像机所在房间
→ 只递归查看可通过 Portal 看到的房间
→ 其他房间不渲染
```

例如：

```text
玩家在房间 A
门关着或视线看不到房间 C
→ 房间 C 的物体不提交渲染
```

这种方式对室内场景非常有效。

------

## 1.6 PVS 剔除

**PVS** 是 Potentially Visible Set，潜在可见集。

它通常是预计算的：

```text
站在某个区域时
理论上可能看到哪些区域或物体
```

运行时只渲染 PVS 集合中的物体。

优点是运行时开销低，缺点是预计算成本高、对动态场景不够灵活。

------

## 1.7 LOD / HLOD 剪枝

严格来说，LOD 不一定是“剔除”，但它是一种细节剪枝。

远处物体会使用低精度版本：

```text
LOD0：高模
LOD1：中模
LOD2：低模
LOD3：极低模
Cull：不显示
```

HLOD 会把远处一组物体合并成代理模型：

```text
远处一片建筑
→ 不再渲染每个窗户、门框、栏杆
→ 使用一个合并后的低模代理
```

这属于几何复杂度和 Draw Call 数量的剪枝。

------

# 2. 顶点和图元级处理中的剔除

物体被提交到 GPU 后，还会在几何阶段继续剔除。

------

## 2.1 背面剔除 Back-face Culling

三角形有正反面。

如果一个三角形背对摄像机，通常不会被看见，可以剔除。

判断方式通常基于顶点绕序：

```text
逆时针 winding → 正面
顺时针 winding → 背面
```

如果启用背面剔除：

```text
背向摄像机的三角形
→ 不进入光栅化
```

例如一个封闭立方体：

```text
看向立方体正面时
背面的三角形不可见
→ 可以剔除
```

背面剔除可以显著减少光栅化和片元处理量。

不过以下情况可能不能简单背面剔除：

```text
双面材质
树叶
布料
纸片
头发卡片
透明面片
某些特效
```

------

## 2.2 视锥裁剪 Clipping

图元可能部分位于视锥体外。

例如一个三角形一半在屏幕内，一半在屏幕外。

这时不能整个丢弃，而要裁剪成视锥体内的部分。

```text
完全在视锥体外 → 丢弃
部分在视锥体内 → 裁剪
完全在视锥体内 → 保留
```

裁剪空间通常是齐次裁剪空间：

```text
-w <= x <= w
-w <= y <= w
0 <= z <= w    DirectX / Vulkan 常见
或
-w <= z <= w   OpenGL 传统 NDC
```

裁剪后，可能生成新的顶点和新的三角形。

------

## 2.3 近平面 / 远平面裁剪

视锥体中的 Near Plane 和 Far Plane 也会裁剪图元。

```text
太靠近摄像机
→ 被 Near Plane 裁剪

超过远平面
→ 被 Far Plane 裁剪
```

Near Plane 很重要，因为摄像机前方非常近的图元可能导致投影异常。

Far Plane 则用于限制可见距离。

------

## 2.4 用户裁剪平面 User Clip Plane

一些渲染效果会自定义裁剪平面。

例如：

```text
水面反射
传送门
切割视图
剖面显示
镜面反射
局部渲染
```

可以在 Shader 中输出裁剪距离，或者使用图形 API 的 clip distance 功能。

例如：

```text
只保留水面上方的物体
水面下方部分裁掉
```

------

## 2.5 Clip / Discard 类操作

在 Shader 中也可以主动丢弃片元或图元相关结果。

比如 HLSL 中：

```hlsl
clip(alpha - 0.5);
```

当条件不满足时，片元被丢弃。

常见于：

```text
树叶 Alpha Test
铁丝网
草
栅栏
破洞布料
贴花边缘
```

这种操作发生在像素着色阶段，但会影响后续深度写入和混合。

注意：大量使用 discard / clip 可能降低 Early-Z 优化效果。

------

# 3. 屏幕空间和光栅化阶段的剔除

进入光栅化后，GPU 会把三角形转成片元，但仍然有一些剪枝。

------

## 3.1 屏幕外裁剪 Viewport / Scissor

视口外的片元不会被生成或不会被保留。

### Viewport

Viewport 定义最终渲染区域：

```text
只在指定屏幕矩形内绘制
```

### Scissor Test

Scissor 是更直接的矩形裁剪。

例如 UI 渲染中：

```text
只允许按钮内容画在某个面板矩形内部
超出矩形部分全部丢弃
```

Scissor Test 常用于：

```text
UI 裁剪
小地图
分屏渲染
局部更新
后处理区域限制
```

------

## 3.2 零面积三角形剔除

如果三角形投影到屏幕后面积为 0，无法覆盖任何像素。

例如：

```text
三个点共线
三角形太小
退化三角形
```

这种图元通常会被丢弃。

------

## 3.3 小三角形 / 微三角形问题

严格来说 GPU 不一定自动剔除所有小三角形，但当三角形小于一个像素时，光栅化效率会变差。

现代系统可能通过：

```text
LOD
Nanite
Cluster Culling
Mesh Shader
GPU Driven Culling
```

提前剪枝微小三角形。

比如 UE5 Nanite 会以 Cluster 为单位进行可见性判断和细节选择，避免大量不可见或过小三角形进入传统光栅化。

------

# 4. 片元级剔除：生成片元后继续测试

光栅化产生片元后，不代表它一定会写入颜色缓冲。它还要经过一系列测试。

------

## 4.1 Early-Z / 深度测试

深度测试用于判断当前片元是否被之前绘制的片元挡住。

```text
如果当前片元比深度缓冲中的值更远
→ 被遮挡
→ 丢弃
```

例如：

```text
墙后面的桌子片元
→ 深度测试失败
→ 不写入颜色缓冲
```

### Early-Z

GPU 可以在像素着色器之前提前做深度测试。

```text
深度测试失败
→ 不执行像素着色器
→ 节省大量像素计算
```

这就是 Early-Z。

它对复杂材质非常重要，因为可以避免对不可见片元执行昂贵的 Pixel Shader。

但某些操作可能破坏 Early-Z，例如：

```text
Pixel Shader 修改深度
discard / clip
Alpha Test
透明混合
某些 UAV 写入
```

------

## 4.2 Hi-Z / 层级深度剔除

Hi-Z 是 Hierarchical Z Buffer。

它把深度缓冲做成层级结构，用较粗粒度判断一块区域是否已经被遮挡。

```text
一整个 tile / block 都被更近物体遮挡
→ 后面的片元或图元可以快速拒绝
```

Hi-Z 可以用于：

```text
GPU 遮挡剔除
Early-Z 加速
Cluster Culling
屏幕空间可见性判断
```

它比逐像素深度测试更高效。

------

## 4.3 Stencil Test 模板测试

模板缓冲可以控制哪些区域允许绘制。

例如：

```text
Stencil 值不匹配
→ 片元丢弃
```

常见用途：

```text
镜子
传送门
描边
UI 遮罩
角色轮廓
阴影体
延迟渲染中的区域限制
```

例如传送门渲染：

```text
只有传送门形状区域的 stencil = 1
后续画面只允许画在 stencil = 1 的区域
```

------

## 4.4 Alpha Test / 透明裁剪

一些材质不是完全不透明，而是通过 Alpha 控制是否保留片元。

例如树叶贴图：

```text
alpha >= 0.5 → 保留
alpha < 0.5  → 丢弃
```

常见于：

```text
草
树叶
铁丝网
栅栏
布料破洞
纸片植被
```

Alpha Test 会产生清晰边缘，但也可能导致锯齿，需要 MSAA、Alpha-to-Coverage 或 TAA 辅助。

------

## 4.5 透明物体中的深度排序

透明物体通常不能像不透明物体一样简单 Early-Z 剔除，因为它们需要和背景混合。

例如玻璃：

```text
后面的物体仍然能透过玻璃看到
不能直接因为玻璃在前面就丢弃后方颜色
```

所以透明物体通常：

```text
不写入深度，或特殊写入深度
按距离排序绘制
使用混合
```

透明渲染中的剔除更复杂，也更容易产生性能问题。

------

## 4.6 MSAA Sample Mask / Coverage 剔除

在 MSAA 中，一个像素有多个 sample。

三角形可能只覆盖部分 sample。

```text
被覆盖的 sample → 参与计算
未覆盖的 sample → 不写入
```

Alpha-to-Coverage 也会根据 alpha 值控制 sample coverage。

这种属于更细粒度的采样级剪枝。

------

# 5. 光照与延迟渲染中的剔除

除了传统几何管线，现代渲染还会对光照计算做剪枝。

------

## 5.1 Light Culling 光源剔除

在 Forward+、Clustered Forward、Deferred Shading 中，不会让每个像素计算所有光源。

通常会把屏幕或视锥划分成：

```text
Tile
Cluster
Froxel
```

然后判断每个区域受哪些光影响。

```text
某个 Tile 不在光源影响范围内
→ 不计算这个光
```

这可以大幅减少多光源场景的光照计算成本。

------

## 5.2 Shadow Culling 阴影剔除

并不是所有物体都需要进入阴影贴图。

可以剔除：

```text
不在光源视锥内的物体
太远的小物体
不投射阴影的物体
被遮挡的投影物
低优先级物体
```

例如太阳光 CSM 中，每个 Cascade 只渲染对应范围内的投影物。

------

## 5.3 Decal / Reflection / Probe 剔除

贴花、反射探针、局部光照探针也会做影响范围剔除。

例如：

```text
贴花盒子没有覆盖到物体
→ 不应用贴花

反射探针影响范围外
→ 不参与反射

局部雾体积外
→ 不计算体积效果
```

------

# 6. GPU Driven / Mesh Shader 中的高级剪枝

现代渲染管线中，很多剔除可以放到 GPU 上做。

------

## 6.1 Instance Culling

大量实例化物体，例如草、石头、树，可以在 GPU 上逐实例剔除：

```text
每个 instance 判断：
是否在视锥内
是否太远
是否被遮挡
是否太小
```

不可见 instance 不进入绘制列表。

------

## 6.2 Cluster Culling

把模型拆成很多小 cluster，每个 cluster 有自己的包围体。

可以对 cluster 做：

```text
视锥剔除
背面 cone 剔除
遮挡剔除
屏幕尺寸剔除
LOD 选择
```

UE5 Nanite、Mesh Shader 管线、现代 GPU Driven Renderer 都大量使用这种思想。

------

## 6.3 Meshlet Culling

Mesh Shader 管线中，一个模型会被拆成很多 meshlet。

每个 meshlet 可以独立判断是否可见：

```text
meshlet 在视锥外 → 丢弃
meshlet 背对摄像机 → 丢弃
meshlet 被遮挡 → 丢弃
meshlet 太小 → 丢弃
```

这样可以在进入光栅化前更细粒度地减少三角形数量。

------

# 7. 按管线顺序总结

可以把剔除过程整理成这样：

| 阶段       | 剔除 / 剪枝类型           | 作用                   |
| ---------- | ------------------------- | ---------------------- |
| 场景提交前 | 视锥体剔除                | 不提交视野外物体       |
| 场景提交前 | 遮挡剔除                  | 不提交被完全挡住的物体 |
| 场景提交前 | 距离剔除                  | 不渲染过远物体         |
| 场景提交前 | 屏幕尺寸剔除              | 不渲染过小物体         |
| 场景管理   | Portal / PVS              | 剔除不可见区域         |
| LOD 系统   | LOD / HLOD                | 降低远处模型复杂度     |
| 几何阶段   | 背面剔除                  | 丢弃背向三角形         |
| 几何阶段   | 视锥裁剪                  | 裁掉视锥外图元部分     |
| 几何阶段   | 用户裁剪平面              | 自定义裁剪区域         |
| 光栅化阶段 | Viewport / Scissor        | 限制屏幕绘制区域       |
| 光栅化阶段 | 零面积图元剔除            | 丢弃无效三角形         |
| 片元阶段   | Early-Z                   | 提前丢弃被遮挡片元     |
| 片元阶段   | 深度测试                  | 保留最近可见片元       |
| 片元阶段   | Stencil Test              | 按模板区域丢弃片元     |
| 片元阶段   | Alpha Test / Clip         | 根据透明度丢弃片元     |
| 光照阶段   | Light Culling             | 减少无关光源计算       |
| 阴影阶段   | Shadow Culling            | 减少阴影贴图绘制对象   |
| GPU Driven | Cluster / Meshlet Culling | 更细粒度剔除几何       |

------

# 8. 最核心的几种剔除

如果只记最重要的，可以记这几个：

```text
Frustum Culling       视锥体剔除
Occlusion Culling     遮挡剔除
Back-face Culling     背面剔除
Clipping              裁剪
Early-Z / Z-Test      深度剔除
Stencil Test          模板测试
Alpha Test / Clip     透明裁剪
LOD / HLOD            细节剪枝
Light Culling         光源剪枝
```

------

# 9. 一个完整例子

假设场景里有一座城市、很多树、很多车辆和角色。

渲染一帧时可能发生：

```text
1. 摄像机背后的建筑
   → 视锥体剔除

2. 山后面的建筑群
   → 遮挡剔除

3. 很远的小草
   → 距离剔除

4. 远处城市街区
   → HLOD 合并代理

5. 建筑背面的三角形
   → 背面剔除

6. 一部分穿出屏幕的三角形
   → 视锥裁剪

7. 墙后面的片元
   → Early-Z / 深度测试丢弃

8. 树叶贴图透明区域
   → Alpha Test 丢弃

9. UI 面板外的内容
   → Scissor Test 丢弃

10. 不影响当前屏幕 tile 的点光源
    → Light Culling
```

最终只有真正可能影响画面的数据，才会尽量进入后续昂贵计算阶段。

------

## 总结

在光栅化管线中，剔除和剪枝的目标是：

> **越早发现不可见，越早丢弃；越晚才发现不可见，代价越高。**

所以优化原则通常是：

```text
对象级剔除优先
↓
图元级剔除
↓
片元级剔除
↓
光照级剪枝
```

越靠前的剔除，收益通常越大。

例如：

```text
CPU 端剔除一个物体
→ 省掉 Draw Call、顶点处理、光栅化、像素着色

Early-Z 剔除一个片元
→ 主要省掉 Pixel Shader

深度测试失败
→ 只能省掉后续混合和写入
```

因此现代实时渲染系统会尽量把可见性判断前移，通过 **视锥剔除、遮挡剔除、LOD、HLOD、Cluster Culling、Early-Z** 等手段，把渲染负载控制在合理范围内。
