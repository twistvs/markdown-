

# 完整光栅化渲染管线

```text
CPU / 引擎准备数据
  ↓
输入装配 Input Assembler
  ↓
顶点着色器 Vertex Shader
  ↓
曲面细分 Tessellation，可选
  ↓
几何着色器 Geometry Shader，可选
  ↓
图元装配 Primitive Assembly
  ↓
裁剪 Clipping
  ↓
背面剔除 Back-face Culling
  ↓
透视除法 Perspective Divide
  ↓
视口变换 Viewport Transform
  ↓
光栅化 Rasterization
  ↓
属性插值 Interpolation
  ↓
Early-Z / Early-Stencil
  ↓
像素着色器 Pixel Shader
  ↓
深度 / 模板测试 Depth / Stencil Test
  ↓
混合 Blending
  ↓
写入 Render Target / Framebuffer
  ↓
MSAA Resolve，可选
  ↓
后处理 Post Processing
  ↓
Present 显示
```

------

# 1. CPU / 引擎准备阶段

在进入 GPU 管线之前，引擎会先决定哪些物体需要绘制。

常见工作包括：

```text
场景遍历
  ↓
视锥体剔除 Frustum Culling
  ↓
遮挡剔除 Occlusion Culling
  ↓
LOD / HLOD 选择
  ↓
材质和渲染状态排序
  ↓
生成 Draw Call / Render Pass
```

这一步通常不属于 GPU 固定光栅管线，但它决定了哪些物体会被提交给 GPU。

------

# 2. 输入装配 Input Assembler

GPU 从顶点缓冲和索引缓冲中读取数据。

顶点缓冲中通常包含：

```text
Position
Normal
Tangent
UV
Vertex Color
Skin Weight
```

索引缓冲决定顶点如何组成图元，例如三角形列表：

```text
0, 1, 2  → Triangle 0
3, 4, 5  → Triangle 1
```

------

# 3. 顶点着色器 Vertex Shader

顶点着色器对每个顶点执行一次。

它最核心的任务是把模型空间坐标变换到裁剪空间：
$$
P_{clip}=P \cdot V \cdot M \cdot P_{model}
$$
也就是：

```text
Model Space
  ↓ Model Matrix
World Space
  ↓ View Matrix
View Space
  ↓ Projection Matrix
Clip Space
```

$$
P_{clip}=(x_c,y_c,z_c,w_c)
$$

顶点着色器还会输出后续需要插值的属性，例如：

```text
UV
Normal
World Position
Vertex Color
Tangent
```

------

# 4. 曲面细分 Tessellation，可选

在 DirectX 风格管线中，曲面细分阶段大致包括：

```text
Hull Shader
  ↓
Tessellator
  ↓
Domain Shader
```

作用是把较粗的网格细分成更多三角形。

常用于：

```text
地形细分
位移贴图
曲面细节增强
```

这一阶段不是所有渲染流程都会使用。

------

# 5. 几何着色器 Geometry Shader，可选

几何着色器接收一个完整图元，然后可以生成新的图元。

例如：

```text
输入：1 个三角形
输出：多个三角形 / 线段 / 点
```

它可以用于：

```text
生成草
调试法线可视化
粒子 billboard
阴影体
```

但在现代实时渲染中，Geometry Shader 使用较少，因为性能通常不理想。

------

# 6. 图元装配 Primitive Assembly

这一阶段把顶点真正组装成图元。

例如三角形列表：

```text
Index 0, 1, 2 → Triangle 0
Index 3, 4, 5 → Triangle 1
```

此时 GPU 已经知道每个三角形由哪三个顶点构成。

------

# 7. 裁剪 Clipping

顶点着色器输出的是裁剪空间坐标：

$$
P_{clip}=(x_c,y_c,z_c,w_c)
$$

GPU 会在透视除法之前进行裁剪。

在 DirectX / Vulkan / UE 常见约定下，裁剪条件可以理解为：

$$
-w_c \le x_c \le w_c
$$

$$
-w_c \le y_c \le w_c
$$

$$
0 \le z_c \le w_c
$$

在 OpenGL 约定下，z 方向通常是：

$$
-w_c \le z_c \le w_c
$$

三角形有三种情况：

```text
完全在视锥体内 → 保留
完全在视锥体外 → 丢弃
跨越裁剪边界 → 被切割成新的图元
```

注意，裁剪发生在 **透视除法之前**，因为此时使用的是齐次裁剪空间。

------

# 8. 背面剔除 Back-face Culling

背面剔除根据三角形投影到屏幕后的顶点绕序判断正面和背面。

常用的是屏幕空间有符号面积：

$$ A = (x_1-x_0)(y_2-y_0)(y_1-y_0)(x_2-x_0)
$$

如果：

$$
A>0
$$

表示一种绕序，例如逆时针。

如果：

$$
A<0
$$

表示另一种绕序，例如顺时针。

然后根据渲染状态决定是否剔除：

```text
Cull None   → 不剔除
Cull Back   → 剔除背面
Cull Front  → 剔除正面
```

------

# 9. 透视除法 Perspective Divide

裁剪之后，对裁剪空间坐标执行透视除法：

$$
x_{ndc}=\frac{x_c}{w_c}
$$

$$
y_{ndc}=\frac{y_c}{w_c}
$$

$$
z_{ndc}=\frac{z_c}{w_c}
$$

得到 NDC 坐标：

```text
Clip Space
  ↓ 除以 w
NDC Space
```

DirectX / Vulkan / UE 常见 NDC 范围：

$$
x_{ndc}\in[-1,1]
$$

$$
y_{ndc}\in[-1,1]
$$

$$
z_{ndc}\in[0,1]
$$

OpenGL 中 z 通常是：

$$
z_{ndc}\in[-1,1]
$$

透视投影中，“近大远小”的效果主要来自这一步。

------

# 10. 视口变换 Viewport Transform

NDC 还不是屏幕像素坐标，需要映射到屏幕空间。

假设视口宽高为 $W,H$，DirectX 风格可以理解为：

$$
x_{screen}=\frac{x_{ndc}+1}{2}W
$$

$$
y_{screen}=\frac{1-y_{ndc}}{2}H
$$

$$
z_{screen}=z_{ndc}
$$

这一步之后，三角形顶点变成屏幕坐标：

```text
(x_screen, y_screen, z_depth)
```

------

# 11. 光栅化 Rasterization

光栅化的核心任务是：

```text
判断三角形覆盖了哪些像素或 sample
```

简化流程：

```cpp
for each triangle:
    bbox = triangle screen-space bounding box

    for each pixel in bbox:
        if pixel/sample inside triangle:
            generate fragment
```

通常会先计算三角形的屏幕空间包围盒，然后只在包围盒内测试像素。

判断点是否在三角形内部，可以使用边函数。

例如三角形一条边 $P_0P_1$，对点 $p$ 的边函数可以写成：

$$ E_{01}(p)= (p_x-x_0)(y_1-y_0)(p_y-y_0)(x_1-x_0)
$$

对三条边都测试：

$$
E_{01}(p) \ge 0
$$

$$
E_{12}(p) \ge 0
$$

$$
E_{20}(p) \ge 0
$$

如果点在三条边的同侧，就认为该 sample 被三角形覆盖。

------

# 12. 属性插值 Interpolation

光栅化生成 fragment 后，需要把顶点属性插值到 fragment 上。

假设一个属性是 $a$，三角形三个顶点上的属性为：
$$
a_0,\ a_1,\ a_2
$$
像素位置对应的屏幕空间重心坐标为：
$$
\lambda_0,\lambda_1,\lambda_2
$$
如果不考虑透视，线性插值是：

$$
a =
\lambda_0 a_0
+
\lambda_1 a_1
+
\lambda_2 a_2
$$

但在透视投影下，UV、世界坐标、法线等属性通常需要透视矫正插值：

$$ a_{pixel}\frac{
\lambda_0 \frac{a_0}{w_0}
+
\lambda_1 \frac{a_1}{w_1}
+
\lambda_2 \frac{a_2}{w_2}
}{
\lambda_0 \frac{1}{w_0}
+
\lambda_1 \frac{1}{w_1}
+
\lambda_2 \frac{1}{w_2}
}
$$

这样可以避免纹理在透视投影下产生错误扭曲。

------

# 13. 深度值生成

每个 fragment 都会有一个深度值，用于深度测试。

深度缓冲通常存储投影后的深度，例如：

$$
depth = z_{ndc}
$$

在 DirectX / Vulkan / UE 常见约定中：

$$
depth \in [0,1]
$$

透视投影下，深度值和真实视空间距离通常不是线性关系，而是类似：

$$
depth = A + \frac{B}{z_{view}}
$$

所以深度精度通常集中在近裁剪面附近。

------

# 14. Early-Z / Early-Stencil

在可能的情况下，GPU 会在像素着色器之前做深度和模板测试。

```text
光栅化
  ↓
Early-Z / Early-Stencil
  ↓
像素着色器
```

如果一个 fragment 已经被前面的物体挡住，就可以直接丢弃，不运行像素着色器。

这可以节省大量性能。

不过以下情况可能影响 Early-Z：

```text
像素着色器中使用 discard / clip
像素着色器写入自定义深度
透明混合
某些 UAV 写入
Alpha Test / Masked 材质
```

------

# 15. 像素着色器 Pixel Shader

像素着色器，也叫 Fragment Shader，用于计算当前 fragment 的输出。

它通常会做：

```text
采样纹理
计算法线
计算材质参数
计算光照
输出颜色或 GBuffer 数据
```

例如在 Forward Rendering 中，像素着色器可能直接输出最终颜色：

显示为：

$$
C_{out}=Lighting(Material, Light, View)
$$

在 Deferred Rendering 中，像素着色器通常先输出 GBuffer：

```text
BaseColor
Normal
Roughness
Metallic
Depth
```

然后后续再统一做光照。

------

# 16. 深度测试 Depth Test

深度测试用于判断当前 fragment 是否被已有像素遮挡。

常见深度比较方式有：

| 深度函数     | 含义                       |
| ------------ | -------------------------- |
| Less         | 新深度小于旧深度则通过     |
| LessEqual    | 新深度小于等于旧深度则通过 |
| Greater      | 新深度大于旧深度则通过     |
| GreaterEqual | 新深度大于等于旧深度则通过 |
| Always       | 总是通过                   |
| Never        | 总是不通过                 |

传统深度中一般是：

```text
near = 0
far = 1
使用 Less / LessEqual
```

反向 Z 中一般是：

```text
near = 1
far = 0
使用 Greater / GreaterEqual
```

现代引擎常使用反向 Z 来提高远处深度精度。

------

# 17. 模板测试 Stencil Test

模板缓冲可以理解为每个像素上的整数标记。

它可以用于：

```text
限制某些区域绘制
实现描边
实现镜子 / 传送门
实现遮罩
控制后处理范围
```

模板测试通常和深度测试一起属于逐片元测试阶段。

------

# 18. 混合 Blending

如果 fragment 通过深度和模板测试，它输出的颜色会写入 Render Target。

对于不透明物体，通常直接覆盖：

```text
RenderTarget = ShaderOutput
```

对于透明物体，通常会进行混合。

最常见的 Alpha 混合公式是：

$$ C_{out}C_{src}\alpha
+
C_{dst}(1-\alpha)
$$

其中：

```text
C_src → 当前像素着色器输出颜色
C_dst → Render Target 中已有颜色
alpha → 当前 fragment 的透明度
```

透明混合通常依赖绘制顺序，因此透明物体经常需要排序。

------

# 19. 写入 Render Target / Framebuffer

最终结果会写入渲染目标。

常见 Render Target 包括：

```text
Back Buffer
Scene Color
GBuffer
Shadow Map
Velocity Buffer
Custom Depth
Post Process Input
```

现代引擎通常不会直接把物体绘制到最终屏幕，而是先写入中间缓冲，再经过后处理。

------

# 20. MSAA Resolve，可选

如果开启 MSAA，一个像素中会有多个 sample。

例如 4x MSAA：

```text
Color[0], Color[1], Color[2], Color[3]
Depth[0], Depth[1], Depth[2], Depth[3]
```

最终显示前，需要把多个 sample 合成为一个普通像素。

最简单的 Resolve 是平均：

$$ C_{final}\frac{1}{N}
\sum_{i=0}^{N-1} C_i
$$

对于 4x MSAA：

显示为：

$$ C_{final}\frac{C_0+C_1+C_2+C_3}{4}
$$

------

# 21. 后处理 Post Processing

后处理通常也是通过绘制全屏三角形或全屏四边形完成的。

常见后处理包括：

```text
Tone Mapping
Bloom
Depth of Field
Motion Blur
SSR
SSAO
TAA / TSR
Color Grading
Exposure
Sharpen
UI Composite
```

最后得到最终显示图像。

------

# 22. Present 显示

最后把 Back Buffer 提交给显示系统：

```text
Swap Chain Present
  ↓
显示器显示
```

------

# 总结版流程

```text
CPU 场景管理 / 可见性判断
  ↓
提交 Draw Call
  ↓
Input Assembler 输入装配
  ↓
Vertex Shader 顶点着色器
  ↓
Tessellation 曲面细分，可选
  ↓
Geometry Shader 几何着色器，可选
  ↓
Primitive Assembly 图元装配
  ↓
Clipping 裁剪
  ↓
Back-face Culling 背面剔除
  ↓
Perspective Divide 透视除法
  ↓
Viewport Transform 视口变换
  ↓
Rasterization 光栅化
  ↓
Attribute Interpolation 属性插值
  ↓
Early-Z / Early-Stencil
  ↓
Pixel Shader 像素着色器
  ↓
Depth / Stencil Test 深度模板测试
  ↓
Blending 混合
  ↓
Render Target / Framebuffer 写入
  ↓
MSAA Resolve，可选
  ↓
Post Processing 后处理
  ↓

```

最核心的一句话：

**光栅管线就是把三维模型的顶点经过变换、裁剪、投影、光栅化和像素着色，最终转换成屏幕上的颜色像素。**
