**Early-Z（提前深度测试）是一种减少无效着色计算的优化：在执行片元着色器之前，先判断片元是否被遮挡，被遮挡就直接跳过着色。**

这里的 Z 指深度。

**1. 为什么需要 Early-Z？**

片元着色器可能需要执行纹理采样、材质计算、光照计算，开销比较大。

如果先着色，再做深度测试：

> 执行昂贵的片元着色 → 发现被遮挡 → 丢弃结果

前面的着色计算就浪费了。

Early-Z 把判断提前：

> 先检查深度 → 如果被遮挡，直接拒绝 → 通过后才执行片元着色

**2. 举个例子**

假设相机前有一面墙，墙后有一个角色，而且**墙已经绘制并写入了深度缓冲**。

接下来绘制角色时：

| 处理方式         | 被墙遮挡的角色片元               |
| ---------------- | -------------------------------- |
| 着色后再测试深度 | 先计算材质和光照，再因遮挡而丢弃 |
| Early-Z          | 先发现被墙遮挡，跳过片元着色     |

**Early-Z 主要节省片元着色阶段的工作，不代表整个角色都不用处理。** 顶点处理、图元装配等工作通常仍然需要执行。

**3. 为什么不总能提前？**

因为片元着色器的行为可能影响深度测试或写入结果。

例如：

- **修改片元深度**：最终深度要运行着色器后才能确定，普通 Early-Z 可能受限。
- **使用 `discard` 丢弃片元**：需要先执行着色器才能知道是否丢弃，因此不能随意提前写入深度。不过，提前拒绝明确被遮挡的片元仍可能进行。
- **写入缓冲区等副作用**：跳过着色器可能改变程序结果，需要结合 API 规则和实现处理。

所以要区分：**提前测试深度和提前写入深度，是两件事。** 是否能够执行、能执行到什么程度，取决于着色器行为、渲染状态和硬件。

**4. 怎样让它更有效？**

**不透明物体尽量从近到远绘制。** 近处物体先写入深度，后面的物体就更容易被提前拒绝。如果先画远处物体，它们执行着色时，深度缓冲中可能还没有近处遮挡物的信息。

另一种方式是 **Depth Prepass（深度预通过，也常叫 Z-Prepass）**：

1. 先用较简单的通道绘制深度。
2. 再进行正式的材质和光照绘制，利用已有深度跳过被遮挡的片元。

它与 Early-Z 的关系是：**Prepass 提前准备深度，Early-Z 利用深度提前拒绝片元。** Prepass 会增加绘制和几何处理开销，因此收益取决于场景。

面试时可以这样回答：

> Early-Z 是把深度测试提前到片元着色之前，利用已有深度缓冲拒绝被遮挡的片元，减少无效的纹理采样和光照计算。不透明物体从近到远绘制，或者先做深度预通过，都能帮助它发挥作用。修改片元深度、discard 和着色器副作用等行为，会影响提前测试或提前写入的可行性。

------

**判断 Early-Z 是否可行，核心标准是：提前进行深度判断、跳过片元着色器，会不会改变原本的渲染结果或程序行为。**

具体要把**提前拒绝片元**和**提前写入深度**分开判断。

**1. 能否根据当前深度，提前拒绝片元？**

需要考虑两点：

- **着色器会不会修改深度，导致测试结果改变？**
- **跳过着色器，会不会遗漏必须执行的副作用，例如写入存储缓冲区？**

如果着色器不修改深度，也没有必须执行的副作用，那么已经被遮挡的片元通常可以直接拒绝。

如果着色器可以任意修改深度，就不能简单依据光栅化深度提前拒绝。例如，它可能把片元从墙后“移”到墙前。若声明了特定的深度变化约束，仍可能保留部分提前测试能力。

**2. 通过测试后，能否提前写入深度？**

还要判断：**这个片元之后是否可能被丢弃，或者改变最终覆盖范围？**

例如着色器使用 `discard`：

```
if (纹理透明度 < 阈值) {
    discard;
}
```

在执行着色器之前，不知道片元最终是否保留，因此不能随意提前写入深度，否则被丢弃的片元也会遮挡后面的物体。

但对于**已经确定被前方物体遮挡**的片元，如果没有其他副作用，仍可能提前拒绝。

常见情况可以这样记：

| 情况                               | 提前拒绝被遮挡片元           | 提前写入深度           |
| ---------------------------------- | ---------------------------- | ---------------------- |
| 普通不透明材质，不改深度、无副作用 | 通常可以                     | 开启深度写入时通常可以 |
| 使用 `discard`，不改深度、无副作用 | 仍可能可以                   | 通常需要等待是否丢弃   |
| 任意修改输出深度                   | 通常受限                     | 通常需要等待最终深度   |
| 向存储缓冲区等资源写数据           | 取决于执行语义，不能随意跳过 | 需结合其他条件判断     |
| 关闭深度写入，但开启深度测试       | 仍可能可以                   | 不写入                 |

**透明混合本身，也不意味着 Early-Z 一定失效。** 例如透明物体虽然通常关闭深度写入，但仍可以通过深度测试，拒绝被不透明墙体遮挡的片元。

**3. 实际由谁判断？**

通常由**驱动和 GPU 根据着色器行为、深度/模板状态及其他渲染状态决定**，开发者不需要在 CPU 上逐个片元判断。具体能优化到什么程度，还与图形 API 和硬件有关。

面试时可以概括为：

> 判断 Early-Z 能否使用，要看提前测试是否与原本的执行结果等价。着色器不修改深度、没有必须执行的副作用时，通常可以提前拒绝被遮挡的片元；如果使用 discard，还要把提前测试与提前写入分开，避免给最终被丢弃的片元写入深度。
