**光栅化管线，就是把场景中的三维模型转换成屏幕上二维像素的处理流程。**

接着前面的前向渲染和延迟渲染来看：**两者都需要通过光栅化确定物体覆盖屏幕的哪些位置，主要区别在于后续怎样组织材质和光照计算。**

可以先记住这条主线：

> 提交模型 → 顶点变换 → 图元装配与裁剪 → 光栅化 → 片元着色 → 深度测试与混合 → 输出图像

下面以“把一个三角形画到屏幕上”为例。

**1. CPU 准备数据并提交绘制命令**

CPU 准备或绑定绘制需要的资源，例如：

- 顶点数据：位置、法线、UV 等。
- 索引数据：哪些顶点组成一个三角形。
- 材质与纹理。
- 变换矩阵、灯光参数。
- 渲染状态：是否开启深度测试、背面剔除、混合等。

然后提交 Draw Call，GPU 开始处理。

例如，矩形可以用四个顶点、两个三角形表示：

```c++
顶点：v0, v1, v2, v3
索引：0, 1, 2,  0, 2, 3
```

索引允许多个三角形复用同一个顶点的数据。

**2. 顶点着色：把顶点转换到裁剪空间**

顶点着色器（Vertex Shader）主要处理每个顶点的位置和相关属性。

最常见的位置变换是：

​									\[ p_{\text{clip}} = P \cdot V \cdot M \cdot p_{\text{local}} \]

这里采用列向量约定，从右往左执行：

| 变换           | 含义                    |
| -------------- | ----------------------- |
| 模型变换 \(M\) | 模型局部空间 → 世界空间 |
| 观察变换 \(V\) | 世界空间 → 相机观察空间 |
| 投影变换 \(P\) | 观察空间 → 裁剪空间     |

比如角色手上的一个顶点，先根据角色的旋转、位置放到世界中，再转换到相机视角，最后进行投影变换。

需要注意：**投影矩阵输出的还不是屏幕坐标，而是包含 \(x,y,z,w\) 的齐次裁剪坐标。**

顶点着色器还会把 UV、法线、世界坐标等数据传递给后续阶段。

**3. 图元装配、裁剪、透视除法与视口变换**

这一部分把顶点组织成可以在屏幕上绘制的三角形。

**① 图元装配**

按照索引和图元类型，把顶点组成三角形等基本图元。

**② 裁剪**

根据视锥体边界裁剪图元：

- 完全在视锥体外的三角形被丢弃。
- 部分在外的三角形会被切割，并可能生成新的顶点和三角形。

**因此，并不是“顶点在屏幕外，就直接删除这个顶点”。** 一个三角形即使顶点在屏幕外，也可能覆盖屏幕中的区域。

**③ 透视除法**

将裁剪坐标的前三个分量除以 \(w\)，得到标准化设备坐标 NDC：

\[ x_{\text{ndc}}=\frac{x_{\text{clip}}}{w}, \quad y_{\text{ndc}}=\frac{y_{\text{clip}}}{w}, \quad z_{\text{ndc}}=\frac{z_{\text{clip}}}{w} \]

对于通常的透视投影，这一步与投影矩阵共同形成近大远小的效果。

**④ 视口变换**

把 NDC 映射到实际渲染区域，例如一张 1920×1080 的图像。

这个过程中还会按设置进行**背面剔除**：根据三角形投影后的顶点绕序，判断它是否为背面，从而跳过不需要绘制的面。

这里要区分：

- **裁剪**：处理视锥体之外的部分。
- **背面剔除**：跳过朝向不符合设置的三角形。
- **深度测试**：解决不同表面之间的前后遮挡。

> [!NOTE]
>
> 背面剔除：一条狗，正面留着，屁股剔除
>
> 深度测试：一只猫被一条狗挡住了，所以渲染这条狗

**4. 光栅化：确定三角形覆盖哪些采样位置**

> [!NOTE]
>
> “**片元**”到底是个啥东西？
>
> ​	对于一个三角形，他会覆盖很多个像素，他在每个像素生成的属于自己的属性，就是一个片元。由于一个像素可能不止被一个三角形覆盖，所以其实一个像素的位置，可能有多个片元，而这些片元在后面会只剩下深度最低的那个，或者进行混合（毕竟可能存在透明的情况）。

这是“光栅化管线”名称的来源。

此时三角形已经投影到了屏幕上，光栅化阶段需要回答：

> 这个三角形覆盖了屏幕上的哪些采样位置？

GPU 根据覆盖规则生成片元，并为它们提供插值后的属性，例如：

- UV。
- 法线。
- 世界位置。
- 顶点颜色。
- 深度。

例如，一个三角形只有三个顶点的 UV，但其内部每个片元采样纹理时都需要 UV，因此需要根据三个顶点的数据进行插值。

**在透视投影下，UV 等属性通常需要进行透视校正插值，不能直接按屏幕空间距离做普通线性插值，否则纹理会出现扭曲。**

还要注意：**片元不等于最终像素。** 同一个像素位置可能有多个三角形生成的片元，它们还需要经过深度测试、混合等处理；MSAA 下还涉及多个覆盖采样点。

> [!NOTE]
>
> 光栅化做的事情，一句话形容就是：把所有的三角形拆成片元（包含了大量插值操作）

**5. 片元着色：计算表面输出**

片元着色器（Fragment Shader，也常称 Pixel Shader）利用插值得到的数据进行计算，例如：

```
基础颜色 = 采样颜色纹理(UV);
法线 = 计算表面法线();
输出颜色 = 根据材质和灯光计算颜色();
```

它可以完成纹理采样、法线贴图、材质计算和光照计算等工作。

> [!NOTE]
>
> 如果使用前向渲染，这里就把光照算出来了

这里就能对应到前面的两种渲染方式：

| 渲染方式 | 典型几何绘制阶段的片元输出             |
| -------- | -------------------------------------- |
| 前向渲染 | 结合灯光计算得到的表面颜色             |
| 延迟渲染 | 基础颜色、法线、粗糙度等 G-buffer 数据 |

**所以，光栅化负责确定覆盖和插值，着色器负责计算表面表现。**

**6. 逐片元操作：决定结果能否写入、如何写入**

片元着色器产生输出后，还需要经过相关测试与合并操作。

> [!NOTE]
>
> 前面给所有片元都着色了，这里反而把很多已经着色了的片元扔了，这不是显得很傻逼吗？
>
> ​	没错，就是这么傻逼，但是没办法，Early-Z并不是可以无脑使用的

**深度测试（Depth Test）**

比较当前片元深度与深度缓冲中已有的深度，判断它是否被前面的表面遮挡。

例如，角色站在墙后，墙已经写入深度，角色被墙挡住的片元就无法通过深度测试。

**深度测试和深度写入是两件事：前者决定是否通过，后者决定是否更新深度缓冲。**

**模板测试（Stencil Test）**

根据模板缓冲中的值，限制哪些区域允许绘制。常用于遮罩、轮廓等效果。

**颜色混合（Blending）**

把当前输出颜色与颜色缓冲中已有的颜色组合。

常见的透明混合为：

\[ C_{\text{out}} = \alpha C_{\text{src}} + (1-\alpha)C_{\text{dst}} \]

其中，\(C_{\text{src}}\) 是当前片元颜色，\(C_{\text{dst}}\) 是缓冲中已有的颜色。

普通透明混合通常依赖绘制顺序，因此透明物体经常需要按从远到近的顺序绘制。

另外，**深度测试不一定等到片元着色之后才执行。** 条件允许时，GPU 会提前进行深度测试，即 Early-Z，跳过被遮挡片元的昂贵着色计算。

**面试时可以这样回答：**

> 光栅化管线负责把三维模型转换成二维图像。首先 CPU 提交顶点、索引、材质等数据和绘制命令；GPU 通过顶点着色器完成坐标变换，再进行图元装配、裁剪、透视除法和视口变换。随后光栅化确定三角形覆盖哪些采样位置，并插值出 UV、法线等属性；片元着色器据此计算颜色或 G-buffer 数据，最后经过深度测试、模板测试和颜色混合等操作，将结果写入渲染目标。
