你说的“后向渲染”，通常是指**延迟渲染（Deferred Rendering）**。它与**前向渲染（Forward Rendering）**的核心区别是：**在什么时候计算光照。**

## 1. 前向渲染：绘制物体时直接计算光照

前向渲染在绘制一个物体时，就结合它的材质以及影响它的灯光，计算出最终颜色。

大致流程：

> 提交物体 → 顶点处理 → 光栅化 → 片元着色器计算材质和光照 → 写入颜色缓冲

例如，场景中有一个角色受到三盏灯影响，绘制角色时就需要计算这三盏灯的贡献：

```
最终颜色 = 自发光;

for (影响当前片元的每盏灯) {
    最终颜色 += 计算光照(材质, 法线, 视线, 灯光);
}
```

**特点：材质计算和光照计算在绘制物体的过程中完成。**

它的主要优点是：

- **透明物体处理比较自然**，可以按顺序绘制并进行颜色混合。
- **适合使用 MSAA**，能够较自然地处理几何边缘的锯齿。
- 通常不需要保存大量中间材质数据，**显存占用和带宽开销较低**。

主要问题是：**灯光较多时，每个片元需要处理的光照计算可能很多。** 如果出现过度绘制，某些最后被遮挡的片元也可能已经执行了昂贵的着色计算。不过，深度预通过和 Early-Z 可以减少这类浪费。

## 2. 延迟渲染：先记录表面信息，再统一计算光照

延迟渲染把主要工作拆成两个阶段。

**第一阶段：几何阶段，生成 G-buffer。**

先绘制场景，把屏幕上可见表面的信息保存到多张缓冲纹理中，例如：

| 数据                | 用途                       |
| ------------------- | -------------------------- |
| 基础颜色 Base Color | 描述材质本身的颜色         |
| 法线 Normal         | 判断表面与光照的方向关系   |
| 粗糙度、金属度等    | 决定材质如何响应光照       |
| 深度 Depth          | 用于重建位置、判断空间关系 |

这些缓冲区统称为 **G-buffer，几何缓冲区**。具体保存哪些数据，取决于引擎实现。

**第二阶段：光照阶段。**

读取 G-buffer，再根据灯光计算最终颜色：

```
表面信息 = 读取GBuffer(屏幕坐标);
位置 = 根据深度重建位置();

最终颜色 = 计算光照(表面信息, 位置, 灯光);
```

**“延迟”指的是把光照计算推迟到表面信息生成之后。**

例如，一面墙后面藏着多个物体，几何阶段会通过深度测试确定可见表面，随后主要对最终可见的表面进行光照计算。

对于局部灯光，还可以通过灯光体积、屏幕分块等方式，把计算限制在灯光影响的区域内，因此更适合大量动态灯光。

## 3. 两者的主要区别

| 对比项       | 前向渲染                   | 延迟渲染                 |
| ------------ | -------------------------- | ------------------------ |
| 光照计算时机 | 绘制物体时计算             | 先生成 G-buffer，再计算  |
| 大量动态灯光 | 传统方案下开销容易增大     | 通常更有优势             |
| 显存和带宽   | 通常较低                   | G-buffer 带来额外开销    |
| 透明物体     | 处理自然                   | 通常需要额外的前向通道   |
| MSAA         | 较容易支持                 | 实现与带宽成本较高       |
| 材质灵活性   | 每个物体可使用不同着色逻辑 | 受 G-buffer 表达能力约束 |

**延迟渲染处理透明物体比较困难，是因为一个普通 G-buffer 像素通常只记录一层表面信息，而透明混合需要考虑前后多层表面的贡献。** 所以实际引擎经常采用“不透明物体走延迟，透明物体走前向”的混合方式。

另外，**延迟渲染并不是灯光再多都不影响性能**。灯光覆盖的像素越多、重叠越严重，光照计算仍然越贵；阴影也有独立的生成和采样成本。

## 4. Forward+ 是什么？

前向渲染也可以优化多灯光问题。

**Forward+ 会先把屏幕分块，为每块筛选出可能影响它的灯光；绘制物体时，只计算所属分块中的灯光。** Clustered Forward 则进一步按深度划分空间。

因此，现代前向渲染也能处理较多灯光，不能简单理解成“灯光多就只能用延迟渲染”。

面试时可以这样回答：

> 前向渲染是在绘制物体时直接计算材质和光照；延迟渲染先把可见表面的颜色、法线、粗糙度、深度等信息写入 G-buffer，再进行光照计算。前向渲染对透明和 MSAA 支持比较自然，通常显存带宽开销较低；延迟渲染更适合大量动态灯光，但需要额外的 G-buffer 开销，而且透明物体通常仍需要用前向通道处理。
