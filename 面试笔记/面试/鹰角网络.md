### 第一题、如果有两个线程同时访问一个vector，可能会导致什么问题

如果有两个线程同时访问同一个 `std::vector`，是否出问题取决于它们是**只读**还是**至少有一个线程在写**。

------

**1. 两个线程都只读：通常没问题**

例如：

```cpp
std::vector<int> v = {1, 2, 3};

void read() {
    int x = v[0];
}
```

如果两个线程都只是读取：

```cpp
v[0];
v.size();
v.empty();
```

一般是安全的。

前提是：**没有其他线程同时修改这个 vector**。

------

**2. 一个读，一个写：可能出问题**

例如一个线程在读：

```cpp
int x = v[0];
```

另一个线程在写：

```cpp
v.push_back(100);
```

这就可能产生**数据竞争**，属于未定义行为。

未定义行为的意思是：程序可能正常运行，也可能崩溃，也可能读到错误数据。

------

**3. 两个线程都写：更危险**

例如两个线程同时执行：

```cpp
v.push_back(1);
```

可能导致：

```text
1. vector 内部数据损坏
2. size 记录错误
3. capacity 记录错误
4. 内存越界访问
5. 程序崩溃
6. 数据丢失
```

`std::vector` 本身不会自动加锁，所以不能保证多线程写入安全。

------

**4.最危险的是扩容**

`vector` 的 `push_back` 在容量不够时会扩容。

扩容大致会做这些事：

```text
1. 申请一块更大的新内存
2. 把旧元素移动/拷贝到新内存
3. 释放旧内存
4. 更新 vector 内部指针
```

如果此时另一个线程还在访问旧内存，例如：

```cpp
int x = v[0];
```

那么它可能访问到已经释放的内存。

这可能导致：

```text
读到脏数据
程序崩溃
堆内存损坏
```

------

**5. 迭代器、指针、引用可能失效**

比如：

```cpp
int* p = &v[0];
```

然后另一个线程执行：

```cpp
v.push_back(100);
```

如果 `push_back` 触发扩容，原来的 `p` 就失效了。

此时再使用：

```cpp
*p
```

就是危险的。

同理，下面这些也可能失效：

```cpp
auto it = v.begin();
int& ref = v[0];
```

------

**6. 即使没有扩容，也可能不安全**

有人可能会想：

> 我提前 `reserve` 足够容量，是不是就可以多个线程同时 `push_back`？

也不行。

因为 `push_back` 还会修改 `vector` 的 `size`。

两个线程同时修改 `size`，仍然会产生数据竞争。

例如：

```cpp
v.reserve(1000);
```

然后两个线程同时：

```cpp
v.push_back(1);
```

可能出现：

```text
两个线程写到了同一个位置
size 最终结果错误
某些元素被覆盖
```

------

**7. 正确做法：加锁**

最简单的方式是使用 `std::mutex`：

```cpp
#include <vector>
#include <mutex>

std::vector<int> v;
std::mutex mtx;

void add(int x) {
    std::lock_guard<std::mutex> lock(mtx);
    v.push_back(x);
}

int getFirst() {
    std::lock_guard<std::mutex> lock(mtx);
    return v[0];
}
```

只要访问 `v`，就先加锁。

------

**8. 读多写少：可以用读写锁**

如果大多数操作是读取，少量操作是写入，可以用 `std::shared_mutex`：

```cpp
#include <vector>
#include <shared_mutex>

std::vector<int> v;
std::shared_mutex mtx;

int readAt(size_t index) {
    std::shared_lock<std::shared_mutex> lock(mtx);
    return v[index];
}

void add(int x) {
    std::unique_lock<std::shared_mutex> lock(mtx);
    v.push_back(x);
}
```

含义是：

```text
多个读线程可以同时读
写线程必须独占访问
写的时候不能读
读的时候不能写
```

------

**9. 总结**

两个线程同时访问 `vector`：

```text
都只读：
    通常安全

一个读一个写：
    不安全，可能数据竞争

两个都写：
    不安全，可能内存损坏或崩溃

push_back 触发扩容：
    可能导致指针、引用、迭代器失效

提前 reserve：
    只能减少扩容，不代表多线程写入安全
```

一句话：

> `std::vector` 本身不是线程安全容器。多个线程访问同一个 `vector` 时，只要至少有一个线程会修改它，就需要同步机制，例如 `mutex`。

### 第三题、内存管理

==new和malloc有什么区别？==

答案：

1. malloc是C函数，new是C++操作符
2. 如果是new Person()，会调用类的构造函数，再为其分配内存；而malloc只能分配内存
3. malloc会从堆上动态分配内存；new会根据operator new的具体实现来决定在哪里分配内存（默认是用malloc，所以也是在堆上）
4. malloc内存分配失败会返回NULL；new内存分配失败会报错
5. malloc内存分配成功返回无类型指针void*；new返回对应类型的指针，因此new符合类型安全
6. malloc手动指定内存的字节数；new根据对象类型自动计算内存大小
7. malloc不能被重载；new调用的operator new可以被重载

==delete和free有什么区别？==

答案：

1. free是C函数，delete是C++操作符
2. delete调用析构函数；free只释放内存

### 第四题、UE5的智能指针

你这里应该是想问 **UE5 中的智能指针**。UE 里有两套常见“智能指针”体系，需要区分：

```text
1. UObject 体系的指针
   TObjectPtr、TWeakObjectPtr、TSoftObjectPtr、TSubclassOf 等

2. 普通 C++ 对象的智能指针
   TSharedPtr、TSharedRef、TWeakPtr、TUniquePtr
```

它们不能随便混用。

------

**一、最重要的区别**

UE5 中有两类对象：

```text
UObject 对象：
AActor、UActorComponent、UUserWidget、UTexture、UAnimMontage、UGameplayAbility 等

非 UObject 普通 C++ 对象：
普通 struct、普通 class、Slate 对象、工具类对象等
```

对应指针选择：

```text
UObject / Actor / Component：
用 TObjectPtr、TWeakObjectPtr、TSoftObjectPtr

普通 C++ 对象：
用 TSharedPtr、TSharedRef、TWeakPtr、TUniquePtr
```

不要用 `TSharedPtr` 管理 `UObject`。

------

**二、UObject 体系中的指针**

**1. TObjectPtr**

`TObjectPtr` 是 UE5 推荐用来保存 UObject 引用的指针类型。

例如：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite)
TObjectPtr<UStaticMeshComponent> MeshComponent;

UPROPERTY(EditAnywhere, BlueprintReadWrite)
TObjectPtr<UAnimMontage> AttackMontage;

UPROPERTY(EditAnywhere, BlueprintReadWrite)
TObjectPtr<AActor> TargetActor;
```

它通常配合 `UPROPERTY` 使用。

UE4 常见写法是：

```cpp
UPROPERTY()
UAnimMontage* AttackMontage;
```

UE5 更推荐：

```cpp
UPROPERTY()
TObjectPtr<UAnimMontage> AttackMontage;
```

它的作用是让 UE 的反射、垃圾回收、编辑器引用追踪更安全。

------

**2. 原始 UObject 指针 `UObject*`**

现在仍然可以用：

```cpp
AActor* TargetActor;
UAnimMontage* AttackMontage;
```

但如果你希望 UE 垃圾回收系统知道这个引用，应该加 `UPROPERTY`：

```cpp
UPROPERTY()
AActor* TargetActor;
```

否则这个指针不会被 GC 追踪，可能出现：

```text
对象已经被销毁
但你的指针还保存着旧地址
导致野指针
```

UE5 中更推荐把成员变量写成：

```cpp
UPROPERTY()
TObjectPtr<AActor> TargetActor;
```

------

**3. TWeakObjectPtr**

`TWeakObjectPtr` 是 UObject 的弱引用。

它不会阻止对象被销毁。

适合保存“我想引用它，但我不拥有它”的对象。

例如：

```cpp
TWeakObjectPtr<AActor> LockTarget;
```

使用时要检查是否有效：

```cpp
if (LockTarget.IsValid())
{
    AActor* Target = LockTarget.Get();
}
```

适合：

```text
锁定目标
当前交互对象
临时缓存某个 Actor
AI 当前目标
UI 临时关联的角色
```

例如锁定敌人：

```cpp
TWeakObjectPtr<AActor> CurrentLockTarget;
```

敌人死亡或被销毁后，`IsValid()` 会变成 false，比较安全。

------

**4. TSoftObjectPtr**

`TSoftObjectPtr` 是软对象引用。

它不会直接把资源加载进内存，而是保存资源路径。

例如：

```cpp
UPROPERTY(EditAnywhere)
TSoftObjectPtr<UTexture2D> IconTexture;

UPROPERTY(EditAnywhere)
TSoftObjectPtr<UAnimMontage> AttackMontage;
```

适合引用大资源：

```text
贴图
音效
动画蒙太奇
蓝图资源
DataAsset
关卡资源
```

它的优点是：

```text
不立即加载资源
可以按需异步加载
减少启动时内存占用
降低硬引用耦合
```

使用时需要加载：

```cpp
UTexture2D* LoadedTexture = IconTexture.LoadSynchronous();
```

或者使用异步加载。

------

**5. TSoftClassPtr**

`TSoftClassPtr` 是软类引用。

适合保存某个蓝图类，但不立刻加载它。

例如：

```cpp
UPROPERTY(EditAnywhere)
TSoftClassPtr<AActor> EnemyClass;
```

适合：

```text
怪物生成表
技能生成投射物类
关卡配置
资源管理器
```

------

**6. TSubclassOf**

`TSubclassOf` 用来限制“类类型必须是某个父类的子类”。

例如你想在编辑器里指定一个投射物类：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite)
TSubclassOf<AActor> ProjectileClass;
```

或者更具体：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite)
TSubclassOf<AGameplayAbilityTargetActor> TargetActorClass;
```

它保存的不是对象实例，而是“类”。

常用于：

```text
SpawnActor 要生成哪个类
技能授予哪个 GameplayAbility 类
AI 要生成哪种敌人
UI 要创建哪个 Widget 类
```

例如：

```cpp
GetWorld()->SpawnActor<AActor>(ProjectileClass, SpawnLocation, SpawnRotation);
```

------

**三、普通 C++ 智能指针**

下面这些主要用于 **非 UObject 类型**。

------

**1. TSharedPtr**

`TSharedPtr` 是共享所有权智能指针，类似标准库的：

```cpp
std::shared_ptr
```

多个 `TSharedPtr` 可以共同持有同一个对象。

当最后一个 `TSharedPtr` 释放时，对象自动销毁。

例如：

```cpp
TSharedPtr<FMyData> DataPtr = MakeShared<FMyData>();
```

适合普通 C++ 对象：

```cpp
class FMyData
{
public:
    int32 Value;
};
```

使用：

```cpp
if (DataPtr.IsValid())
{
    DataPtr->Value = 10;
}
```

注意：不要这样管理 UObject：

```cpp
TSharedPtr<AActor> ActorPtr; // 不推荐，错误思路
```

`AActor`、`UObject` 由 UE 的 GC 管，不应该由 `TSharedPtr` 管生命周期。

------

**2. TSharedRef**

`TSharedRef` 和 `TSharedPtr` 很像，但它不能为空。

```cpp
TSharedRef<FMyData> DataRef = MakeShared<FMyData>();
```

区别：

```text
TSharedPtr：可以为空
TSharedRef：不能为空
```

Slate UI 中经常用 `TSharedRef`：

```cpp
TSharedRef<SWidget>
```

例如：

```cpp
TSharedRef<SButton> Button = SNew(SButton);
```

------

**3. TWeakPtr**

`TWeakPtr` 是 `TSharedPtr` 的弱引用。

它不会增加引用计数。

适合避免循环引用。

例如：

```cpp
TSharedPtr<FPlayerData> PlayerData;
TWeakPtr<FPlayerData> WeakPlayerData;
```

使用时需要转成共享指针：

```cpp
TSharedPtr<FPlayerData> PinnedData = WeakPlayerData.Pin();

if (PinnedData.IsValid())
{
    PinnedData->Value = 100;
}
```

和 `TWeakObjectPtr` 区别是：

```text
TWeakPtr：
用于 TSharedPtr 管理的普通 C++ 对象

TWeakObjectPtr：
用于 UObject / Actor
```

------

**4. TUniquePtr**

`TUniquePtr` 是独占所有权智能指针，类似：

```cpp
std::unique_ptr
```

同一时间只有一个 `TUniquePtr` 拥有对象。

例如：

```cpp
TUniquePtr<FMyData> Data = MakeUnique<FMyData>();
```

不能复制，只能移动：

```cpp
TUniquePtr<FMyData> OtherData = MoveTemp(Data);
```

适合：

```text
某个对象只属于当前类
不需要共享
生命周期明确
```

------

**四、常用选择规则**

**如果是 Actor / UObject**

优先考虑：

```cpp
UPROPERTY()
TObjectPtr<AActor> SomeActor;
```

如果只是临时弱引用：

```cpp
TWeakObjectPtr<AActor> SomeActor;
```

如果是资源软引用：

```cpp
TSoftObjectPtr<UTexture2D> Icon;
```

如果是类引用：

```cpp
TSubclassOf<AActor> ActorClass;
```

------

**如果是普通 C++ 对象**

共享所有权：

```cpp
TSharedPtr<FMyData> Data;
```

不能为空共享引用：

```cpp
TSharedRef<FMyData> DataRef;
```

弱引用：

```cpp
TWeakPtr<FMyData> WeakData;
```

独占所有权：

```cpp
TUniquePtr<FMyData> UniqueData;
```

------

**五、一个常见错误：用 TSharedPtr 管 UObject**

不要这样：

```cpp
TSharedPtr<UObject> Obj;
TSharedPtr<AActor> Actor;
TUniquePtr<UUserWidget> Widget;
```

原因是：

```text
UObject 生命周期由 UE 垃圾回收管理
TSharedPtr / TUniquePtr 是普通 C++ 生命周期管理
两套系统混用容易出问题
```

正确做法：

```cpp
UPROPERTY()
TObjectPtr<UUserWidget> Widget;

TWeakObjectPtr<AActor> TargetActor;

TSoftObjectPtr<UTexture2D> TextureAsset;
```

------

**六、UPROPERTY 和智能指针的关系**

对于 UObject 引用，`UPROPERTY` 非常重要。

例如：

```cpp
TObjectPtr<UAnimMontage> AttackMontage;
```

如果不加 `UPROPERTY`，UE 的反射系统和 GC 不一定能追踪它。

推荐：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Combat")
TObjectPtr<UAnimMontage> AttackMontage;
```

这样它可以：

```text
在编辑器中编辑
被蓝图访问
被序列化保存
被垃圾回收系统追踪
```

------

**七、在 UE5 中成员变量推荐写法**

**组件**

```cpp
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category="Components")
TObjectPtr<USpringArmComponent> CameraBoom;

UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category="Components")
TObjectPtr<UCameraComponent> FollowCamera;
```

------

**动画蒙太奇**

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Animation")
TObjectPtr<UAnimMontage> AttackMontage;
```

------

**当前目标**

```cpp
TWeakObjectPtr<AActor> CurrentTarget;
```

------

**生成类**

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Spawn")
TSubclassOf<AActor> ProjectileClass;
```

------

**软资源**

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="UI")
TSoftObjectPtr<UTexture2D> SkillIcon;
```

------

**八、简单总结**

UE5 里可以这样记：

```text
TObjectPtr：
强引用 UObject，UE5 推荐成员变量写法

TWeakObjectPtr：
弱引用 UObject，对象销毁后可检测失效

TSoftObjectPtr：
软引用资源，不立即加载

TSubclassOf：
保存某个类，并限制它必须继承自指定父类

TSharedPtr：
共享普通 C++ 对象，不用于 UObject

TSharedRef：
不能为空的 TSharedPtr

TWeakPtr：
TSharedPtr 的弱引用

TUniquePtr：
独占普通 C++ 对象
```

最重要的一句话：

> **UObject / Actor 用 UE 的 UObject 指针体系；普通 C++ 对象才用 TSharedPtr、TWeakPtr、TUniquePtr。**

### 第五题、Slate

Slate 是 UE 的 **底层 UI 框架**。UMG 其实就是建立在 Slate 之上的一层更适合设计师和蓝图使用的 UI 系统。

可以简单理解为：

```text
Slate：UE 的底层 C++ UI 框架
UMG：基于 Slate 封装出来的可视化 UI 系统
```

------

**1. Slate 是什么？**

Slate 是 UE 中用 C++ 写 UI 的框架，主要用于：

```text
UE 编辑器界面
工具窗口
细节面板
菜单栏
Content Browser
右键菜单
自定义编辑器工具
部分运行时 UI
```

比如 UE 编辑器里的这些界面，很多都是 Slate 写的：

```text
菜单栏
工具栏
Details 面板
Content Browser
Blueprint Editor
Animation Editor
Material Editor
```

所以 Slate 不只是游戏 UI，它也是 UE 编辑器本身的 UI 基础。

------

**2. Slate 和 UMG 的关系**

UMG 是更高层、更可视化的 UI 系统。

你在 UMG 里拖出来的：

```text
Button
TextBlock
Image
ProgressBar
ScrollBox
VerticalBox
HorizontalBox
```

底层大多都会对应 Slate 控件。

例如：

```text
UMG 的 UButton      底层对应 Slate 的 SButton
UMG 的 UTextBlock   底层对应 Slate 的 STextBlock
UMG 的 UImage       底层对应 Slate 的 SImage
```

可以这样理解：

```text
Slate：C++ 层面的 UI 控件
UMG：给蓝图和设计器使用的 UI 封装
```

------

**3. Slate 常见类名前缀**

Slate 控件一般以 `S` 开头。

例如：

```cpp
SWidget
SButton
STextBlock
SImage
SBorder
SBox
SHorizontalBox
SVerticalBox
SOverlay
SScrollBox
SComboBox
SCheckBox
SEditableText
SEditableTextBox
```

其中最基础的是：

```cpp
SWidget
```

很多 Slate 控件都继承自 `SWidget`。

------

**4. Slate 的基本写法**

Slate 不是用蓝图拖控件，而是用 C++ 代码声明 UI 树。

例如创建一个简单按钮：

```cpp
SNew(SButton)
.Text(FText::FromString(TEXT("Click Me")))
.OnClicked(this, &SMyWidget::OnButtonClicked)
```

一个简单布局可能长这样：

```cpp
SNew(SVerticalBox)

+ SVerticalBox::Slot()
.AutoHeight()
[
    SNew(STextBlock)
    .Text(FText::FromString(TEXT("Hello Slate")))
]

+ SVerticalBox::Slot()
.AutoHeight()
[
    SNew(SButton)
    .Text(FText::FromString(TEXT("Button")))
]
```

这里的结构类似 UMG 中：

```text
VerticalBox
├─ TextBlock
└─ Button
```

只是 Slate 是用 C++ 写出来的。

------

**5. Slate 的声明式语法**

Slate 最明显的特点是这种写法：

```cpp
SNew(SButton)
[
    SNew(STextBlock)
    .Text(FText::FromString(TEXT("确认")))
]
```

这是一种“声明式 UI”风格。

意思是：

```text
创建一个按钮
按钮里面放一个文本
文本内容是“确认”
```

更完整一点：

```cpp
TSharedRef<SWidget> MyWidget =
    SNew(SBorder)
    .Padding(10)
    [
        SNew(SVerticalBox)

        + SVerticalBox::Slot()
        .AutoHeight()
        [
            SNew(STextBlock)
            .Text(FText::FromString(TEXT("角色属性")))
        ]

        + SVerticalBox::Slot()
        .AutoHeight()
        [
            SNew(SButton)
            .Text(FText::FromString(TEXT("升级")))
        ]
    ];
```

------

**6. Slate 为什么大量使用智能指针？**

Slate 控件不是 `UObject`，所以不走 UE 的垃圾回收系统。

Slate 控件通常用：

```cpp
TSharedPtr
TSharedRef
TWeakPtr
```

管理生命周期。

例如：

```cpp
TSharedPtr<STextBlock> MyTextBlock;
```

创建控件时常见：

```cpp
SAssignNew(MyTextBlock, STextBlock)
.Text(FText::FromString(TEXT("HP: 100")))
```

这里：

```cpp
SNew
```

用于创建控件；

```cpp
SAssignNew
```

用于创建控件并保存引用。

------

**7. SNew 和 SAssignNew 的区别**

**SNew**

只创建控件：

```cpp
SNew(STextBlock)
.Text(FText::FromString(TEXT("Hello")))
```

适合不需要后续访问的控件。

------

**SAssignNew**

创建控件，并把它保存到一个 `TSharedPtr` 里：

```cpp
TSharedPtr<STextBlock> HealthText;

SAssignNew(HealthText, STextBlock)
.Text(FText::FromString(TEXT("HP: 100")))
```

之后你可以更新它：

```cpp
HealthText->SetText(FText::FromString(TEXT("HP: 80")));
```

**8. Slate 的布局控件**

Slate 布局和 UMG 很像。

常见布局控件：

```text
SVerticalBox      垂直排列
SHorizontalBox    水平排列
SOverlay          多层叠加
```

例如垂直布局：

```cpp
SNew(SVerticalBox)
```

```cpp
    SNew(SProgressBar)
```

**9. Slate 中的事件绑定**

Slate 按钮点击通常这样写：

```cpp
SNew(SButton)
.Text(FText::FromString(TEXT("点击")))
.OnClicked(this, &SMyWidget::OnClicked)
```

函数返回值一般是：

```cpp
FReply
```

例如：

```cpp
FReply SMyWidget::OnClicked()
{
    UE_LOG(LogTemp, Warning, TEXT("Button Clicked"));
    return FReply::Handled();
}
```

`FReply::Handled()` 表示事件已经被处理。

也有：

```cpp
FReply::Unhandled()
```

表示事件未处理，可以继续传递。

**10. Slate 和 UObject 不一样**

Slate 控件通常不是 UObject。

例如：

```cpp
SButton
STextBlock
SWidget
```

它们不是：

```cpp
UObject
```

所以：

```cpp
UPROPERTY()
TObjectPtr<SButton>
```

这种写法是错误的。

Slate 通常用：

```cpp
TSharedPtr<SButton>
TSharedRef<SButton>
```

而 UMG 控件是 UObject 类型，例如：

```cpp
UButton
UTextBlock
UUserWidget
```

这些才可以用：

```cpp
UPROPERTY()
TObjectPtr<UButton>
```

Slate 更适合：

```text
复杂工具面板
```

比如你写一个 UE 编辑器插件，添加一个新面板：

```text
批量重命名工具

关卡分析工具
自定义数据编辑器
技能编辑器
对话编辑器

```

这些通常用 Slate 写。

**12. UMG 适合做什么？**

UMG 更适合游戏中的用户界面：

```text
血条
技能栏
背包
暂停菜单
主菜单
任务面板
对话 UI
小地图
```

所以实际项目中常见分工是：

```text
游戏 UI：优先 UMG
编辑器工具 UI：优先 Slate
```

**13. Slate 和 UMG 对比**

| 对比         | Slate                        | UMG                   |
| ------------ | ---------------------------- | --------------------- |
| 主要使用方式 | C++ 代码                     | 可视化设计器 + 蓝图   |
| 底层/高层    | 底层 UI 框架                 | 基于 Slate 的高层封装 |
| 常见用途     | 编辑器工具、插件、自定义面板 | 游戏 UI               |
| 类名前缀     | `S`                          | `U`                   |
| 生命周期     | `TSharedPtr/TSharedRef`      | `UObject` + GC        |
| 上手难度     | 较高                         | 较低                  |
| 灵活性       | 很高                         | 高，但受封装限制      |
| 适合设计师   | 不太适合                     | 适合                  |

**14.一个自定义 Slate 控件的基本结构**

通常会写一个继承自 `SCompoundWidget` 的类。

头文件：

```cpp
#pragma once

#include "CoreMinimal.h"
#include "Widgets/SCompoundWidget.h"

class SMySlateWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SMySlateWidget)
    {}
    SLATE_END_ARGS()

    void Construct(const FArguments& InArgs);

private:
    FReply OnButtonClicked();

    TSharedPtr<STextBlock> InfoText;
};
```

cpp 文件：

```cpp
#include "SMySlateWidget.h"
#include "Widgets/Text/STextBlock.h"
#include "Widgets/Input/SButton.h"
#include "Widgets/Layout/SVerticalBox.h"

void SMySlateWidget::Construct(const FArguments& InArgs)
{
    ChildSlot
    [
        SNew(SVerticalBox)

        + SVerticalBox::Slot()
        .AutoHeight()
        [
            SAssignNew(InfoText, STextBlock)
            .Text(FText::FromString(TEXT("Hello Slate")))
        ]

        + SVerticalBox::Slot()
        .AutoHeight()
        [
            SNew(SButton)
            .Text(FText::FromString(TEXT("Click")))
            .OnClicked(this, &SMySlateWidget::OnButtonClicked)
        ]
    ];
}

FReply SMySlateWidget::OnButtonClicked()
{
    if (InfoText.IsValid())
    {
        InfoText->SetText(FText::FromString(TEXT("Clicked!")));
    }

    return FReply::Handled();
}
```

------

**15. `SLATE_BEGIN_ARGS` 是什么？**

这是 Slate 的参数声明宏。

比如：

```cpp
SLATE_BEGIN_ARGS(SMySlateWidget)
    : _Title(FText::FromString(TEXT("Default Title")))
{}
    SLATE_ARGUMENT(FText, Title)
SLATE_END_ARGS()
```

表示这个控件构造时可以传入参数：

```cpp
SNew(SMySlateWidget)
.Title(FText::FromString(TEXT("我的窗口")))
```

在 `Construct` 中读取：

```cpp
FText Title = InArgs._Title;
```

这和 UMG 中暴露变量有点像，只不过 Slate 是 C++ 宏形式。

**16. Slate 中的属性绑定**

Slate 支持把 UI 属性绑定到函数。

例如文本：

```cpp
SNew(STextBlock)
.Text(this, &SMyWidget::GetHealthText)
```

函数：

```cpp
FText SMyWidget::GetHealthText() const
{
    return FText::FromString(TEXT("HP: 100"));
}
```

类似 UMG 中的绑定，但同样要注意：绑定函数可能会频繁调用，不要写太重的逻辑。

**20. 总结**

Slate 是 UE 的底层 C++ UI 框架。

可以这样记：

```text
Slate：
C++ 写 UI，主要用于编辑器和高级工具

UMG：
基于 Slate 的可视化 UI，主要用于游戏界面
```

最常见类：

```cpp
SWidget
SButton
STextBlock
SImage
SVerticalBox
SHorizontalBox
SOverlay
SBorder
SCompoundWidget
```

最重要特点：

```text
声明式语法
大量使用 TSharedPtr / TSharedRef
不是 UObject，不走 GC
适合编辑器插件和工具开发
```

一句话：

> **Slate 是 UE5 UI 系统的底层框架；UMG 是给游戏 UI 使用的高层封装，而 UE 编辑器本身大量界面都是用 Slate 写的。**
