简单 · C++ 基础 / 游戏开发场景

面试官：

假设你正在开发一个游戏的敌人管理系统。

游戏中有多个敌人，每个敌人都有一个唯一的 ID，我们使用 `std::vector` 存储这些敌人。

```c++
struct Enemy
{
    int id;
    int hp;
};

std::vector<Enemy> enemies;
```

为了方便后续操作，我们还使用一个 `std::unordered_map`，保存敌人 ID 对应的指针。

```c++
std::unordered_map<int, Enemy*> enemyMap;

for (auto& enemy : enemies)
{
    enemyMap[enemy.id] = &enemy;
}
```

一开始程序运行正常，可以通过 ID 快速找到敌人：

```c++
Enemy* enemy = enemyMap[1001];
enemy->hp -= 10;
```

但是随着游戏运行，不断有新的敌人加入：

```c++
enemies.push_back(newEnemy);
```

测试人员发现，有时候通过 `enemyMap` 获取敌人指针并修改血量，程序会发生崩溃，或者修改到了错误的数据。

**面试官的问题**

1. 你认为可能是什么原因导致的？
2. 如果让你修改这套代码，应该怎么解决？

你可以从 `vector` 的存储特点、指针的有效性入手分析。

==回答==

有三个破局的方向：

**1.既然vector会扩容导致内存搬家，那我不让他搬不就可以了**

```c++
enemies.reverse(10000);    //给vector预留很大的空间
```

但是这样就上限卡死了，万一后面会超过呢

**2.既然vector会扩容导致内存搬家，那我找个不会搬家的不就行了**

把vector换成deque，deque在扩容时不会影响元素的内存位置，但是在中间插入删除时，还是可能会导致元素指针失效

**3.既然vector会扩容导致内存搬家，那我找一个就算搬家也不会丢失索引的方法不就行了**

把数组里面的元素换成unique_ptr，把enemy实例new到堆上面去，这样每次搬家的时候搬的是unique_ptr，unordered_map对于enemy*的索引依旧正常生效

```c++
std::vector<std::unique_ptr<Enemy>> enemies;

std::unordered_map<int, Enemy*> enemyMap;
```
