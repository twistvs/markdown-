常见设计模式分为三类：**创建型关注对象怎么创建，结构型关注对象怎么组合，行为型关注对象怎么协作。**

| 类型   | 模式             | 核心特点                                                     |
| ------ | ---------------- | ------------------------------------------------------------ |
| 创建型 | **单例模式**     | 保证一个类只有一个实例，并提供统一访问入口；注意线程安全和全局耦合。 |
| 创建型 | **工厂方法模式** | 将对象创建交给具体工厂，调用方依赖抽象，方便扩展产品类型。   |
| 创建型 | **抽象工厂模式** | 创建一整套相互配合的产品，例如同一风格的按钮、窗口、菜单。   |
| 创建型 | **建造者模式**   | 分步骤构建复杂对象，将构建过程与最终表示分离。               |
| 结构型 | **适配器模式**   | 转换接口，让原本接口不兼容的对象能够合作。                   |
| 结构型 | **装饰器模式**   | 通过包装对象，动态叠加功能，比继承更灵活。                   |
| 结构型 | **代理模式**     | 通过代理控制对象访问，可实现权限检查、延迟加载等。           |
| 结构型 | **外观模式**     | 为复杂子系统提供简单、统一的入口。                           |
| 结构型 | **组合模式**     | 将对象组织成树，让单个对象与对象集合能够被统一处理。         |
| 结构型 | **享元模式**     | 共享大量对象中的相同数据，减少内存占用。                     |
| 行为型 | **观察者模式**   | 一对多通知，某个对象变化时通知订阅者，例如血量变化通知HUD。  |
| 行为型 | **策略模式**     | 封装可替换的算法，由调用方选择，例如切换不同寻路策略。       |
| 行为型 | **状态模式**     | 将不同状态的行为封装到不同对象中，例如角色待机、移动、攻击。 |
| 行为型 | **命令模式**     | 将请求封装成对象，方便排队、记录、撤销和重放。               |
| 行为型 | **模板方法模式** | 父类定义算法流程，子类重写其中的具体步骤。                   |
| 行为型 | **责任链模式**   | 多个处理者组成链，请求沿链传递，由合适的处理者处理。         |

容易混淆的两组：

- **策略与状态**：策略侧重“选择哪种算法”；状态侧重“当前状态决定行为，以及状态如何切换”。
- **装饰器与代理**：装饰器侧重“增加功能”；代理侧重“控制访问”。
