# AI的总结

`malloc` 和 `new` 申请到的都是进程虚拟地址空间中的内存，而不是直接申请物理内存。

但是，当程序实际访问这块虚拟内存时，操作系统通常需要为其分配物理内存，并通过页表建立虚拟地址与物理地址的映射关系。

## 一、malloc 和 new 的内存分配流程

以 Linux 操作系统为例：

![download](../图片/download.svg)

典型的按需分配流程。具体实现可能复用已经映射的物理页面，不一定每次都触发缺页异常。

### 1. malloc 申请内存

例如：

```
int* p = (int*)malloc(4096);
```

执行时：

1. `malloc` 首先检查内存分配器管理的空闲内存块。
2. 如果没有合适的内存块，可能通过 `brk` 或 `mmap` 向操作系统申请更多虚拟地址空间。
3. `malloc` 返回一个虚拟地址。
4. 在按需分页的情况下，操作系统可能暂时没有为这块区域分配物理页框。

注意，`malloc` 申请的内存不一定立即初始化，也不保证返回的地址恰好位于页边界。

### 2. new 申请内存

例如：

```
int* p = new int(10);
```

`new` 的执行流程通常是：

1. 调用 `operator new` 获取内存。
2. 底层分配器申请或复用虚拟内存。
3. 在分配到的内存中构造对象。
4. 返回对象指针。

与 `malloc` 不同，`new int(10)` 会初始化对象，写入数值 `10`。因此，这个过程可能会触发物理页面的实际分配。

## 二、什么时候真正分配物理内存？

假设执行以下代码：

```
char* p = (char*)malloc(4096);
```

此时，`p` 指向一块可用的虚拟地址区域，但不一定已经有对应的物理页框。

接下来：

```
p[0] = 'A';
```

如果该虚拟页面尚未映射到物理内存，那么：

1. CPU 尝试访问 `p[0]`。
2. MMU 发现页表中不存在有效的物理页映射。
3. 触发缺页异常（Page Fault）。
4. 操作系统分配物理页框。
5. 更新页表，建立虚拟页到物理页框的映射。
6. CPU 重新执行写入指令。

此时，才真正使用了对应的物理内存。

不过，如果 `malloc` 返回的内存来自已经分配并映射好的内存块，那么访问时就不需要重新分配物理页框。

## 三、申请 1GB 内存，就会占用 1GB 物理内存吗？

不一定。

例如：

```
char* p = (char*)malloc(1024ULL * 1024 * 1024);
```

申请 1GB 内存后：

- 虚拟地址空间中会有一块约 1GB 的可用区域。
- 物理内存不一定立即增加 1GB。
- 只有真正访问的页面才可能需要分配物理页框。

假设系统使用 4KB 页面：

```
p[0] = 1;
p[4096] = 2;
p[8192] = 3;
```

在典型的按需分页情况下，这三次写入会触及三个不同的虚拟页面，可能因此分配三个物理页框。

即：

\[ 3 \times 4KB = 12KB \]

虽然申请了 1GB，但由于只访问了三个页面，新增的实际物理内存占用可能只有约 12KB（不考虑分配器和页表等额外开销）。

## 四、malloc 和 new 的区别

| 对比项             | malloc          | new                       |
| ------------------ | --------------- | ------------------------- |
| 申请的地址         | 虚拟地址        | 虚拟地址                  |
| 是否直接分配物理页 | 不保证          | 不保证                    |
| 分配失败           | 通常返回 `NULL` | 通常抛出 `std::bad_alloc` |
| 是否初始化对象     | 不负责          | 会执行初始化              |
| 是否调用构造函数   | 否              | 是                        |
| 释放方式           | `free`          | `delete`                  |

## 五、面试中如何回答？

> `malloc` 和 `new` 申请的都是进程虚拟地址空间中的内存。
>
> 在 Linux 中，底层内存分配器可能通过 `brk` 或 `mmap` 获取虚拟内存区域，但操作系统通常采用按需分页机制，不一定立即为虚拟页面分配物理内存。
>
> 当程序真正访问尚未映射的虚拟页面时，可能触发缺页异常，由操作系统分配物理页框并建立页表映射。
>
> 因此，申请的虚拟内存大小不一定等于实际占用的物理内存大小。

还有一个重要知识点：`malloc` 返回非空指针，不代表后续使用这块内存一定成功。 在启用内存过量承诺（Overcommit）的 Linux 系统中，即使虚拟内存申请成功，后续访问时也可能因为物理内存及 Swap 不足而触发 OOM。
